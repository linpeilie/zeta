## 1. 三个阻塞问题结论

### Q1 · `<encoded-cwd>` 真实编码规则

**结论（已冻结）**：

```
encoded = absPath.replaceAll(RegExp(r'[\\/:]'), '-')
```

| 输入（绝对路径） | 目录名（`~/.claude/projects/<encoded>/`） |
|---|---|
| `D:\Development\Workspace\zeta` | `D--Development-Workspace-zeta` |
| `C:\Users\linpl` | `C--Users-linpl` |
| `D:\Development\Workspace\JDD\jdd-ares` | `D--Development-Workspace-JDD-jdd-ares` |

- 盘符冒号 `:`、`\`、`/` 一律替换为 `-`（因此 `D:\` → `D--`）。
- 与设计文档 §4.8 描述一致；**不需要**额外 lower-case 或 URL-encode。
- 历史文件名：`<session-id>.jsonl`（UUID）。
- **注意**：磁盘上的 history jsonl **不是** live stream-json 形状（含 `mode` / `attachment` / `ai-title` 等持久化帧）；T25/T26 读 history 时必须另建 parser 路径，不能复用 live mapper 原样吞文件。

### Q2 · 不带 `--include-partial-messages` 时 assistant 帧是否整条下发

**结论：是整条 content-block 级下发，不是字符级增量。**

实测（无 partial）：

| 观察 | 说明 |
|---|---|
| 同一 `message.id` 拆成多帧 | 常见：thinking 一帧 → text 一帧；或 thinking → tool_use |
| 每帧 `message.content` | 通常 **1 个** block（非整条 content 数组一次性吐完） |
| 无 `stream_event` / partial delta 帧 | 未出现字符级 `text_delta` |
| thinking 字段 | `{"type":"thinking","thinking":"...","signature":"..."}`（不是 `text`） |
| text 字段 | `{"type":"text","text":"..."}` |

**对 mapper 的含义（M1）**：

- 默认路径发 `AgentMessageUpdatedEvent`（整 block 文本）即可；
- 同一 `message.id` 的连续 text 必须经 identity 归到同一 entryId；thinking / tool_use 打断后新 segment（T15）；
- M1 **不**启用 `--include-partial-messages`；若日后开启，partial 路径必须产出**同一 entryId**（B2 / T15 单测固定）。

### Q3 · `--print` + stream-json stdin 能否跨多回合常驻

**结论：能。进程在收到 `result` 后不退出，可继续写下一帧 user。**

| 项 | 实测 |
|---|---|
| turn1 → result | `process_exited=false` |
| turn2 user 帧 | 正常受理，再出 result |
| 关闭 stdin | 进程随后退出（exit 0） |
| 二次 `system.init` | **每个 turn 开头都会再发一次 `system.init`**（同 session_id） |

**对 Provider 的含义**：

- 生命周期模型 = 常驻 peer + 串行 turn，而非「一 turn 一进程」；
- mapper 对重复 `system.init`（同 session_id）必须幂等，不得反复 `AgentSessionStartedEvent` 制造假会话边界；
- 关闭 stdin / peer.close 才是进程 teardown。
