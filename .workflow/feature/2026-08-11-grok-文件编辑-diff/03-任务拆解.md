## 执行规则

1. 严格按编号顺序执行，不跨步并行修改生产代码。
2. 每完成一步，按顺序运行：
   - `dart format .`
   - `flutter analyze`
   - 该步“相关测试”列中的测试
3. 三项都通过后，立即把该步状态改为“完成”，并在 `04-实现记录.md` 写结果。
4. 行为变化完成后，收尾步骤还要运行完整 `flutter test`。
5. 任一验证失败，该步保持“进行中”或“阻塞”，不得继续下一步。
6. 遇到以下情况立即停线并写入 `04-实现记录.md`，不得自行拍板：
   - 方案和实际代码/协议数据对不上；
   - 必须修改本文未列出的共享适配层职责或任何 Provider port；
   - 单步改动量明显超过“预计范围”。

## 版本例外

用户已明确授权跳过 Codex CLI、Grok CLI 的精确版本限制。本任务：

- 用当前可用环境采集真实数据，版本只作为 fixture/provenance 标签；
- 不用 `--expected-version` 把实现绑定到某个本机版本；
- 仓库 pin 的 Codex schema 仍作为静态兼容基线；
- 真实运行证据与 schema fixture 必须分开命名，不得互相冒充；
- Claude Code 同样按当前实测版本记录，不新增精确版本硬门。

## 当前事实基线

| Provider | 真实基线 | 方案含义 |
|---|---|---|
| Grok `1.0.0` | Edit update 给出 `path/oldText/newText`，终态再次给出同一 diff | 可做 tool-scoped `textReplacement` |
| Claude Code `2.1.227` | Edit tool_use 给出 `file_path/old_string/new_string/replace_all`；Write 给出 `file_path/content`；tool_result 无结构化 diff | 必须由 Claude-local tracker 把 tool_use 证据带到终态 |
| Codex `0.144.1` | 成功编辑只产生 commandExecution；零 fileChange/patchUpdated/turn diff | command-only 不生成文件变更卡 |
| Codex schema | `fileChange.changes[]` 与 turn aggregated unified diff | 作为结构化兼容路径，不代表当前运行时必然产生 |
