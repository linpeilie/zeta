# 左侧栏与 Agent 统计整合 · 需求分析

- 日期：2026-08-11
- 阶段：需求分析（未进入设计与实现）
- 需求类型：工作台布局与状态行为调整
- 决策状态：D1–D10 已确认

## 1. 实际要解决的问题

### 问题陈述

当前 Agent 首页同时存在最左侧 Activity Rail、Projects/Threads 侧栏，以及可单独开关的 Agent 统计面板。项目导航与高频用量信息被拆成多层入口，既占用横向空间，也让用户为了确认某个 Provider 的套餐余量和今日 Token 反复打开面板、切换 Tab。

本需求实际要解决的是：在不改变 Projects、Agent Canvas、Files 三类核心职责的前提下，压缩工作台外围 chrome，把项目导航和 Agent 用量汇总成一个可整体收起的左侧信息区；统计区在折叠时仍能提供一眼可读的关键信息，并能记住用户关注的 Provider、在当前会话完成后跟随其 Provider。

### 当前绕行方式

- 用户通过最左侧 Activity Rail 分别开关 Projects 与 Agent 统计，再手动调整上下区域。
- Agent 统计展开后可以切换 Provider Tab，但当前选择只存在内存中，重启后需要重新选择。
- 回合完成后现有链路只触发统计刷新，不会把统计选择切到该回合所属 Provider。
- 如果只想快速查看余量或今日 Token，用户仍需保持较大的统计面板，或进入完整使用统计页。

### 已确认的现状边界

- `IdeHome` 是 Workbench 的唯一组合边界；当前左侧 Navigation 已通过上下分区组合 Projects 与 Agent 统计。
- 最左 Activity Rail 当前负责 Projects 与统计区域的独立显隐；标题栏另有完整使用统计页和设置页入口。
- 统计数据已经使用中立 Provider/Quota 模型；本需求无需新增 Provider 或改变套餐、Token 的采集口径。
- “统计区折叠”和“整个左侧栏折叠”是两种不同状态，不能混为一个开关。

## 2. 可观察的验收标准

1. **打开 Agent 首页时，会看到合并后的左侧信息区。** 原最左 Activity Rail 不再占位，Projects/Threads 与 Agent 统计共用一个卡片外壳，现有独立 Agent 统计卡片消失；统计固定在卡片底部且首次默认折叠，中央 Agent Canvas 与右侧 Files 的职责和内容不变。
2. **把 Agent 统计向下折叠时，会看到所选 Provider 的紧凑摘要。** 摘要最多三行：第一行显示 Provider 图标，有套餐时显示套餐名称、无套餐时显示 Provider 名称，并在最右侧显示展开图标；第二行仅在有套餐时显示周期最短额度窗口的剩余用量进度；最后一行显示今日 Token 总量。加载中显示呼吸 Skeleton，读取失败显示错误提示，Token 暂无统计显示 `-`。
3. **调整左侧栏状态后重启应用，会看到应用级状态被恢复。** 所选 Provider、整个左侧栏显隐、统计展开/折叠、栏宽和统计展开高度均恢复为退出前状态；所选 Provider 不再可用时，按已启用 Provider 目录顺序回退到第一个。
4. **让任意前台或后台会话的 Turn 进入终态时，会看到统计选择自动切换到该 Turn 所属 Provider。** 成功、失败、取消和中断均触发，自动切换覆盖此前手动选择，只改变统计展示，不改变新会话的默认 Provider，并把结果持久化。
5. **点击窗口最左侧的新入口时，会看到整个左侧栏隐藏或恢复。** macOS 中入口位于三色灯右侧，其他桌面平台位于标题栏最左侧；它取代 Activity Rail 原 Projects 显隐入口，侧栏隐藏后仍可操作。窄窗口恢复左侧栏时以浮层展示；恢复不会丢失当前项目、Thread 或已持久化的左栏状态。

## 3. 明确不做的部分

- 不重做中央 Agent 时间线、Composer、权限/提问/Plan 卡片或右侧 Files/Tools。
- 不改变完整使用统计页和设置页的业务内容及现有标题栏入口。
- 不改变 Token 聚合、套餐额度计算、历史扫描、自动刷新口径，也不新增 Provider 专属统计分支。
- 不新增 Provider、Provider 协议、套餐购买/续费、登录或账号体系。
- 不让紧凑摘要展示 Prompt、回复、工具输出、原始错误、会话路径或 Provider raw payload。
- 不在需求分析阶段确定像素、颜色、动画、具体 Widget 或持久化文件归属。
- 默认不修改 `AgentEvent`、共享适配层、TimelineStore 或 Provider adapter；如果后续方案证明无法避免，必须停下重新判定范围并走对应专项流程。
- 不纳入移动端适配；该项本就属于产品“暂不包含”。

## 4. 已拍板的需求决策

| 编号 | 决策结果 | 对后续设计的约束 |
|---|---|---|
| D1 | 隐藏对象是当前 Activity Rail，不是 Projects/Threads 侧栏。 | 保留 Projects、Agent Canvas、Files 的核心职责。 |
| D2 | Activity Rail 移除；Projects 改由新的左侧栏入口控制显隐。Projects 与 Agent 统计合并为一个卡片，移除现有独立 Agent 统计卡片。 | 新入口控制整个合并左侧栏，不再保留原 Projects/统计两个局部显隐入口；完整使用统计页和设置页入口保持不变。 |
| D3 | Agent 统计首次默认折叠。所选 Provider、整个左侧栏显隐、统计展开/折叠、栏宽和统计展开高度全部按应用级持久化。 | 必须定义完整、宽容的应用级 UI 状态恢复；不能只保存 Provider id。 |
| D4 | Agent 统计固定在底部并向上展开，展开时挤压 Projects；上下分界可拖动，统计区设最低高度；展开内容沿用当前完整统计内容。 | Projects 与统计需要独立可用空间，拖动结果纳入应用级持久化。 |
| D5 | 使用可区分 Provider 的图标；有套餐时第一行显示套餐名称且不显示 Provider 名称，无套餐时显示 Provider 名称。 | 折叠态不得使用无法区分 Provider 的通用图标。 |
| D6 | 多额度窗口展示周期最短者；加载中显示呼吸 Skeleton，读取失败显示错误提示，Token 暂无统计显示 `-`。 | 额度窗口选择与各异常状态都必须有可测试的中立投影。 |
| D7 | 任意前台或后台会话的每个 Turn 进入任一终态都会触发；成功、失败、取消、中断均包含在内。 | 完成通知必须携带准确的 Provider 归属，不能再只有无上下文的刷新信号。 |
| D8 | Turn 完成后的自动切换覆盖手动统计选择；统计选择只影响统计展示，不改变会话默认 Provider。 | 统计选择状态与会话路由状态必须保持隔离。 |
| D9 | 已持久化 Provider 不可用时回退到第一个。 | “第一个”按当前已启用 Provider 目录的稳定顺序解释。 |
| D10 | 窄窗口使用浮层展示左侧栏。 | 复用 Workbench 的 compact overlay 语义，不能挤没 Agent Canvas。 |

D1–D10 的产品歧义已关闭，可以进入方案设计。方案阶段仍需明确最低高度、拖动范围、等周期额度窗口的稳定排序，以及多个后台 Turn 几乎同时结束时的事件顺序，但这些属于实现契约细化，不改变上述产品决策。

## 5. 门禁预判与复杂度

### 预计直接命中的门禁

| 门禁 | 命中原因 | 需求阶段约束 |
|---|---|---|
| G4 | Provider Tab、套餐行和额度信息都必须按已启用目录与中立可选能力渲染。 | 不按 Provider kind、id 或显示名硬编码；无套餐能力就不伪造套餐行。 |
| G6 | Workbench 结构、Projects、Usage Statistics、会话完成联动横跨壳层与多个 feature。 | 组合仍由 `IdeHome` 完成；Projects 与统计的业务状态留在各自 feature，不把协议字段带入 UI。 |
| G8 | Provider 选择、侧栏显隐、统计展开状态、栏宽和展开高度都会新增或扩展 Zeta 自有持久化状态。 | 只保存规范化 Provider id 与非敏感 UI 状态；版本化/宽容读取，缺字段、旧数据、损坏和失效 id 均不能阻断启动；具体 store 由 app 注入。 |
| G9 | 涉及标题栏图标、侧栏显隐、折叠摘要、响应式布局和跨平台窗口 chrome。 | 使用现有 UI 原语与 Graphite token，补 tooltip/语义标签，并验证窄宽窗口无溢出。 |

### 需要守住但不应被本需求触发的边界

- G1/G2：不应修改共享事件管线、TimelineStore、合并 identity 或 Provider 边界。
- G3：若会话完成联动需要扩展回调，仍应在 application/shell 层传递明确的中立完成上下文；不得把持久化或 UI 切换副作用塞进 reducer。
- G5：统计选择和侧栏折叠不得改变任何审批或 Plan 语义。
- G7：沿用现有只读统计来源，不扩大对 CLI 私有数据的访问范围。

### 额外验收门禁

- 修改 Workbench 组合与可见性后，使用真实 `IdeHome` 做集成级 Widget 回归，验证常驻骨架、AgentPane、当前 Thread、草稿、滚动位置、Pane 宽度与可见性不被意外重置。
- 持久化变化覆盖新数据往返、缺字段、旧版本、损坏输入、未知/失效 Provider id。
- 使用统计继续遵守中立模型、白名单索引和 Provider 原始数据不进入 presentation 的约束。

### 档位结论：L

命中 L 档的独立理由有两项：

1. 明确新增或扩展持久化状态，属于持久化格式改动。
2. 工作台壳层、Projects、Usage Statistics、会话完成信号和持久化之间形成跨 feature 的结构调整。

因此必须走完整功能开发五阶段。D1–D10 已拍板，下一步可以进入 `02-方案设计.md`，当前仍不应直接写代码。

## 6. 与产品需求文档的冲突检查

对照 `docs/product/product_requirements.md`：

- 与“暂不包含”的内置编辑器、文件内容/diff/保存、远程仓库/云同步/账号体系、完整插件系统、移动端、Cursor Cloud Agent/Automations 等均无冲突。
- 套餐信息仅展示现有只读额度快照，不扩展为购买、续费或账号体系，因此不触碰“远程仓库、云同步或账号体系”的边界。
- D1 已确认隐藏 Activity Rail，Projects/Threads、Agent Canvas、Files 三类核心职责仍然存在，符合产品目标中的三栏工作台；左侧栏只是增加固定的 Agent 统计摘要并支持整体折叠。
- 该变化属于用户可感知的工作台行为；进入实现后应同步检查产品文档、架构总览、开发者 UI 指南与 `CHANGELOG.md`，本阶段不修改这些长期文档。

结论：**需求不与产品文档的“明确不做”冲突，也不改变 Projects、Agent、Files 的核心职责。**
