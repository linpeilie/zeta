# Claude Code 模型与套餐元数据 · 任务拆解

- 日期：2026-08-12
- 范围：Claude Code 有效模型列表、套餐名称、可选额度详情，以及相关登录/连接诊断
- 原则：先加后删；每一步从上一步的绿色提交开始，可独立提交、回滚

## 执行约束

1. 严格按序号执行，不跨步并行修改生产代码。
2. 每一步提交前都必须运行 `dart format .`、`flutter analyze`、该步定向测试、完整
   `flutter test` 和 `git diff --check`；分别看到格式化退出码 0、`No issues found!`、
   `All tests passed!`、无 whitespace error 后，才可把状态改为“完成”。
3. fixture、日志和 smoke 输出只保留模型白名单字段、套餐展示名、CLI 版本、OS/架构和
   成败；不得包含 token、email、organization、PID、原始 payload、用户目录或 stderr 原文。
4. 模型目录保持 app 级 `AgentModelCatalogRepository` 为唯一 TTL 真源；Provider 新增的
   metadata 协调器只能做并发 single-flight，不得用自己的长期缓存挡住显式刷新。
5. 本任务不新增 domain 模型、bundle port、`AgentEvent` 或持久化业务字段。若实施中发现
   必须修改共享事件适配层、模型目录端口签名或工作区作用域契约，立即停线并重新论证 G1。
6. Claude Code 的逆向源码只用于确认机制和构造兼容 fixture；不得据此硬编码当前模型名、
   Keychain 内容或未经真机验证的版本下限。
