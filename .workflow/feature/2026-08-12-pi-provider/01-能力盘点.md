# Pi Provider 能力盘点

> **已过时（2026-08-13）**：旧 `AgentProvider` 大接口与 `AgentProviderBundle.adapt` 已删除。
> 新 Provider 必须通过 `AgentProviderBundleFactory.createBundle` 发布原生 Bundle；
> 静态能力由 data 组合层的 `AgentProviderStaticCapabilities` 注入，不得再往 Shared Domain
> 增加 `AgentProviderCapabilities.<vendor>` / `defaultsFor(kind)`。
> 现行契约见 [`docs/guides/developer_guide.md`](../../../docs/guides/developer_guide.md) §7
> 与 [`docs/architecture/overview.md`](../../../docs/architecture/overview.md)。
> 本目录仍可作为 Pi 协议能力盘点参考，但接入步骤以现行 native Bundle 为准。

## 结论

Pi 可以通过 **Pi RPC** 接入 Zeta。首版可覆盖核心对话、本地历史、当前头分支、turn steering、模型/推理档位、Skill、session 动态配置与用量事件。归档、指定 turn 分支、对话模式、Provider 权限请求、Plan 审批、service tier 和账号 quota 不应声明支持。

Pi RPC 是基于 stdin/stdout 的自定义 JSONL 协议：请求使用 `type` 和可选 `id`，没有 JSON-RPC 2.0 的 `jsonrpc` / `method` / `params`。因此它不走 `ProviderRuntimeJsonRpcPeer`，需要 Pi 自有的 LF-only JSONL transport。

## 盘点基线

- Zeta 契约：`lib/src/features/agent/domain/agent_provider_bundle.dart` 与 `agent_provider_capabilities.dart`
- Pi 版本：`0.84.1`，源码基线 `6d520c58d`
- Pi 协议真源：`pi/packages/coding-agent/docs/rpc.md` 与 `src/modes/rpc/rpc-types.ts`
- 本地历史真源：`pi/packages/coding-agent/docs/session-format.md`
- 安全边界：`pi/packages/coding-agent/docs/security.md`
- 路径均以 `zeta/` 和 `pi/` 代表两个本地仓库根目录，不记录用户绝对路径。

判定标识：“支持”表示现有中立端口足以无损表达；“部分支持”表示端口可暴露，但必须按子能力门禁；“不支持”表示端口为 `null`或 capability 为 `false`。

## Bundle 端口矩阵

| 现有端口 | 判定 | Pi 事实与接入边界 |
|---|---|---|
| `runtime` | 支持 | 可做版本/进程生命周期、事件流和 runtime scope；模型选择在下次 prompt 前通过 `set_model` / `set_thinking_level` 收敛。Pi 进程一次只绑定一个当前 session，应与 Zeta 的 session-scoped Binding 一一对应。 |
| `conversation` | 支持 | 新建走新 RPC 进程；恢复用 `--session <path|id>` 精确打开；发送用 `prompt`；取消用 `abort`。文本和图片有原生字段；`mention` 不可降级为普通路径文本后宣称支持。 |
| `threadCatalog` | 部分支持 | `get_entries` / `get_tree` / `get_messages` 可读当前 session；Pi v3 JSONL 会话文件可由 Pi data adapter 做跨会话 list/history。Pi 无 archive 语义，`archived=true` 不能返回“空列表”伪装成功。RPC 也无 unsubscribe 命令；现有端口缺少对应子 capability，记入第二轮契约审查。 |
| `threadMutations` | 部分支持 | `renameThread` → `set_session_name`；`compactThread` → `compact`。`archiveThread` / `unarchiveThread` 无协议支持。虽然 Pi 文档说可删除 JSONL，Pi RPC 没有删除命令，首版不直接把文件删除当作稳定协议能力。 |
| `threadBranching` | 部分支持 | 当前头分支可用 `clone`。`fork(entryId)` 的语义是在某条 user message **之前**分支并返回原 prompt，不等价于 Zeta 的“保留到指定 turn 结束”，因此 `canForkThreadAtTurn=false`。 |
| `turnSteering` | 支持 | 用 `steer`，文本和图片均可发送。Pi 线上事件普遍没有 turn id，`expectedTurnId` 必须在 Pi-local reducer/runtime 中核对；`follow_up` 是“完全结束后再发”的另一种队列语义，不能冒充 steering。 |
| `interactions` | 部分支持 | Extension UI 的 `select` / `confirm` / `input` / `editor` 可映射为中立用户提问并用 `extension_ui_response` 回写。它们没有 command/file permission 的 typed 语义，一律不映射成权限审批；Guardian action 也不支持。 |
| `modelCatalog` | 支持 | `get_available_models` 返回 provider/model、输入类型、context window 等；推理档位可结合 model metadata 与 `get_available_thinking_levels`。没有 service tier 目录或选择语义。 |
| `conversationModes` | 不支持 | Pi 没有 Default/Plan 等运行时模式目录与每回合 mode 配置。不发送 `/plan` prompt 伪造协议能力。 |
| `skills` | 支持（有完整性门禁） | `get_commands` 可筛选 `source=skill`，并返回 name/description/path/scope；prompt 以 `/skill:<name>` 触发 Pi 原生展开。Pi RPC 没有 skill-changed 事件，只有在 adapter 实现 provider-local 文件监听且 `forceReload` 真正启动新快照后才暴露该端口；不得用永不发事件的空 stream 敷衍。 |
| `localThreadList` | 支持 | 这是 Zeta 本地隐藏语义，不删除 Pi session。可像 Claude Code 一样由 app 注入版本化、宽容解码的 ID 白名单 store，list 时真实过滤，不是 no-op。 |
| `sessionConfiguration` | 支持 | 可暴露 `steeringMode`、`followUpMode`、`autoCompactionEnabled`；对应 `get_state` 与 set RPC。`autoRetry` 只有 setter、没有可靠的当前值，首版不列入 option。未列出的 config id 必须拒绝。 |
| `planApproval` | 不支持 | 没有 typed Plan request/decision 子协议。普通 Extension UI confirm 不等价于 Plan 审批。 |
| `permissionPolicy` | 有限支持 | Pi 只能用进程启动参数 `--no-tools` / `--tools` / `--exclude-tools` 控制模型可调用工具。可暴露为明确标注“不是 sandbox”的保守目录，未有用户选择时默认 `--no-tools`；apply 返回 `nextSession`，运行中不得伪报立即生效。`--approve` 只表示是否加载项目资源，不映射为权限选项或预授权。 |
| `usageQuota` | 不支持 | `get_session_stats` 是 session 的 token/cost/context 统计，不是账号套餐、限额窗口、余额或 reset time。 |

## 事件与身份边界

这些不是新端口，但是声明上述能力的前置条件：

- Pi 的 `agent_end` 可后续自动 retry、compaction retry 或 queued continuation；只有 `agent_settled` 可作为 session-level 稳定终态。
- `message_update` 只给 delta，且大部分事件没有 turn/message id。Pi-local reducer 必须自己决定 turn、message segment、reasoning phase、entryId、去重和 first-terminal-wins，再输出语义完整的 `AgentEvent`；不修改 TimelineStore/CoalescingPolicy/Buffer 来猜。
- `toolCallId` 可稳定关联 tool start/update/end。对 Pi 内建 `edit` 和 `write` 可在 Provider-local tracker 映射 typed 文件证据；普通 `bash` 只是命令事实，禁止猜测文件改动。
- live、history、replay 使用独立 reducer/tracker。在逐位 canonical signature 回归通过前，文件证据只标记 `liveOnly`，不伪报 `replayable`。

## 不支持能力的表达规则

1. 整个能力域不支持：可选端口为 `null`，对应 capability 为 `false`。本轮包括 `conversationModes`、`planApproval`、`usageQuota`。
2. 同一端口内只支持部分操作：支持项的 capability 为 `true`，不支持项为 `false`；被误调时抛 `UnsupportedError`。例如 archived list/unsubscribe、archive/unarchive/delete、through-turn fork、permission response 和 Guardian approval。若现有契约没有这个子 capability，则在第二轮补契约，不先写 no-op。
3. 输入变体不支持：在 data adapter 发送前拒绝并抛 `UnsupportedError`，不得丢弃 `mention`、mode、service tier 或其他字段后继续 prompt。
4. 不得用近似语义伪造支持：不把 generic confirm 当 permission/Plan approval，不把 `follow_up` 当 steer，不把 `/plan` 文本当 conversation mode，不把 session stats 当账号 quota。
5. Pi 没有内建 sandbox，进程与 extension 拥有启动用户的 OS 权限。工具 allowlist 只限制模型可调用的工具，不得向 UI 宣称已形成安全边界。

## 留给第二轮的已知审查点

本轮不设计新端口，仅记录现有契约无法完整表达的事实：

- `threadCatalog` 把 list/read 与 unsubscribe 绑在一个端口，但 unsubscribe 没有独立 capability。
- Pi `follow_up` 是不同于 steering 的持久队列语义，现有 bundle 无对应端口。
- Pi model/Skill/extension 目录可随 cwd 变化，现有 `modelCatalog.listModels()` 不带 workspace context。
- Extension UI 还有 notify/status/widget/title/editor-text 类型，现有 `interactions` 只表达需回写的对话。
