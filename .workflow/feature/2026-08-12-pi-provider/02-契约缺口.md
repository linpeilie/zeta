# Pi Provider 契约缺口

## 决策摘要

现有 Bundle 足以完成 Pi 的核心对话，但有四个边界不应通过 Pi 分支、raw 字段或 no-op 补齐。建议新增四个 **Provider 无关的可选端口**：

| 新端口 | 解决的缺口 | Pi 初始暴露 |
|---|---|---|
| `AgentThreadSubscriptionPort` | 将远端 thread 订阅释放从 list/history 中拆出 | `null` |
| `AgentQueuedInputPort` | 无损区分同 turn steering 和当前 turn 后续输入 | 暴露两种 delivery |
| `AgentWorkspaceResourcePolicyPort` | 在启动前显式决定是否加载项目配置、extension、hook、Skill | 暴露，默认 deny |
| `AgentScopedModelCatalogPort` | 模型目录可随 workspace 与项目资源策略变化 | 暴露 |

不新增 `supportsXxx` 静态布尔位：单一能力用端口是否为 `null` 表达；只有 `AgentQueuedInputPort` 内部存在多种 delivery，由该端口的 typed capabilities 表达。

## 1. `AgentThreadSubscriptionPort`

### 问题

`AgentThreadCatalogPort` 同时包含 list、history 和 `unsubscribeThread`。Pi、Grok ACP 与 Claude Code 都能读历史，但没有远端 thread 订阅协议；当前结构迫使它们实现空方法。

### 中立契约

```dart
abstract interface class AgentThreadSubscriptionPort {
  Future<void> unsubscribeThread(String threadId);
}
```

- `threadCatalog` 只保留 list/read；Bundle 新增可空 `threadSubscription`。
- 语义仅是停止 Provider 为该 thread 维持的远端观察/推送资源；不取消 turn、不删除历史、不销毁 Binding。
- 已经退订后重复调用可以幂等成功；这是真实支持的幂等状态转移，不是用 no-op 伪造不支持。
- Application 只在端口非空时退订。迁移期旧 `AgentProvider.unsubscribeThread` 的不支持实现改抛 `UnsupportedError`。

### 为什么是跨 Provider 语义

Codex app-server 真实提供 `thread/unsubscribe`；Grok ACP、Claude Code 和 Pi 都没有这个资源模型。“Provider 是否要求客户端显式释放 thread 订阅”是远程 Agent 协议的通用生命周期差异，不是 Pi 字段。

## 2. `AgentQueuedInputPort`

### 问题

Pi 把活动 turn 期间的输入分为：

- 当前工具链结束后、下一次模型调用前交付（`steer`）；
- 当前 turn 完成后再作为后续输入交付（`follow_up`）。

现有 `turnSteering` 只表达第一种。把 `follow_up` 也编成 steer 会改变 turn 边界；在 application 等终态后再调 `sendMessage` 也不等价于 Provider 已接受的运行时队列。

### 中立契约

```dart
enum AgentQueuedInputDelivery {
  beforeNextModelInvocation,
  afterActiveTurn,
}

abstract interface class AgentQueuedInputPort {
  AgentQueuedInputCapabilities get capabilities;

  Future<void> enqueueInput({
    required AgentQueuedInputDelivery delivery,
    required AgentSession session,
    required String expectedTurnId,
    required AgentContext context,
    String? message,
    List<AgentUserInput>? inputs,
    String? clientUserMessageId,
  });
}
```

- `beforeNextModelInvocation` 是同 turn 指令；`afterActiveTurn` 必须开启新的逻辑 turn。Provider-local reducer 负责产出完整边界和 entryId。
- Future 在 Provider **接受入队**后完成，不等到该输入执行完毕。进程退出或队列丢失通过正常错误/终态事件收敛。
- `expectedTurnId` 不匹配是作用域错误，不得默认发给新 turn；不支持的 delivery 抛 `UnsupportedError`。
- 端口不承诺单条队列项取消，因为 Pi RPC 没有稳定 queue item id。不把 raw 队列文本写入日志或持久化。
- 迁移期 `turnSteering` 保留为 `beforeNextModelInvocation` 的兼容视图；application 不按 Provider 分支选择编码。

Pi 的 delivery 集合为两项；Codex 可映射 `turn/steer` 为 `beforeNextModelInvocation`；Grok 和 Claude Code 当前端口为 `null`。

### 为什么是跨 Provider 语义

这个契约表达的是“用户输入相对于活动 turn 的交付时机”。Codex 和 Pi 都有同 turn steering，Pi 另外实现了 after-turn delivery。Domain 不出现 `steer`、`follow_up` 或 `streamingBehavior` 等 wire 名称，任何具有相同时序语义的 Agent 都可实现。

## 3. `AgentWorkspaceResourcePolicyPort`

### 问题

Pi 的项目 trust 决定是否加载项目级 settings、extensions、skills、prompts、system prompt 等资源。这些资源可包含可执行代码，但它不是 tool permission，也不是 sandbox。现有 `permissionPolicy` 和 `sessionConfiguration` 都不适合：前者管工具权限，后者在 session runtime 启动后才可用，时机太晚。

### 中立契约

```dart
abstract interface class AgentWorkspaceResourcePolicyPort {
  Future<AgentWorkspaceResourceCatalog> listOptions({
    required AgentContext context,
  });

  Future<AgentWorkspaceResourceApplyResult> applySelection({
    required AgentContext context,
    required AgentWorkspaceResourceSelection selection,
  });
}
```

配套模型全部为中立 typed model：

- `AgentWorkspaceResourceOption`：不透明 id、label、description、allowed。
- `AgentWorkspaceResourceCatalog`：options + 保守的 `defaultOptionId`。
- `AgentWorkspaceResourceSelection`：只含 optionId，不含 CLI flag。
- `AgentWorkspaceResourceApplyResult`：归一化 selection + `currentRuntime` / `nextRuntime` 生效范围 + warning。
- `AgentWorkspaceResourceRequestSnapshot`：application 在启动请求前冻结的不可变选择与来源。

约束：

- 默认必须 deny；不得因为 workspace 被打开、用户选了工具权限或计划中提到某 extension 而自动 allow。
- 该端口与 `AgentPermissionPolicyPort` 使用独立 model、controller、pending state 和持久化 key，互不推导。
- 选择必须通过新的中立 `AgentSessionLaunchConfiguration` 冻结到 start/resume/fork；不允许 data adapter 从全局“最后选择”猜当前 workspace。
- `AgentSessionLaunchConfiguration` 聚合现有 permission snapshot 与 workspace-resource snapshot；turn 级权限仍留在 `AgentTurnConfiguration`，两种安全语义不合并。
- Pi data adapter 才能把 optionId 编码为 `--approve` / `--no-approve`；共享层不识别这些字符串。
- Zeta 只持久 providerId、规范化 workspace identity 和 optionId。不记录项目资源内容、路径列表或 Provider raw payload。

### 为什么是跨 Provider 语义

- Pi 有受 trust 控制的 `.pi` 设置、extension 和 Skill。
- Codex schema 已存在 cwd-aware project config layer 与 hook `trustStatus`。
- Claude Code 也有项目级 hooks、skills、plugins、MCP 与可关闭自动发现的 bare 启动形态。

三者的协议字段不同，共同语义都是“在启动 Agent 前，是否允许它加载 workspace 提供的配置或可执行扩展”。因此该端口不含 Pi/trust-file/CLI flag 名称，其他 Provider 可按自身粒度返回两档或多档目录。

## 4. `AgentScopedModelCatalogPort`

### 问题

`AgentModelCatalogPort.listModels()` 没有 workspace context。Pi 的 project extension 可注册 Provider/模型，所以用一个 global runtime 在 workspace A 拉到的目录不能当作 workspace B 的目录，也不能用全局空目录覆盖某个 workspace 的 last-known-good。

### 中立契约

```dart
sealed class AgentCatalogScope {
  const factory AgentCatalogScope.global() = AgentGlobalCatalogScope;
  const factory AgentCatalogScope.workspace({
    required AgentContext context,
    required AgentWorkspaceResourceRequestSnapshot resourceSnapshot,
  }) = AgentWorkspaceCatalogScope;
}

abstract interface class AgentScopedModelCatalogPort {
  Future<AgentModelList> listModels({
    required AgentCatalogScope scope,
    int limit = 20,
    bool includeHidden = false,
    bool forceRefresh = false,
  });
}
```

- Bundle 新增可空 `scopedModelCatalog`。有 workspace 且该端口非空时优先使用；无 workspace 或 Provider 只有全局目录时继续使用 `modelCatalog`。
- `AgentModelCatalogRepository` 的 single-flight、fresh/stale 和 last-known-good identity 必须加入 scope + resource option，不得跨 workspace 共用失败/空结果。
- 持久化 scoped cache 不保存原始项目路径；使用已有 workspace identity 或不可逆的 scope key。
- Pi 的 global runtime 仍是唯一 owner；它可在目标 cwd 启动短命的 discovery RPC 进程，不得为目录读取创建 session runtime。
- 同一 `AgentCatalogScope` 也应加入 `AgentSkillsPort.listSkills` 请求，代替只有 `cwds` 却无 resource snapshot 的不完整形态；这是扩展现有可选端口，不再另建一个 Skill 端口。

### 为什么是跨 Provider 语义

workspace 作用域已经是 Zeta 的中立概念：`AgentContext`、thread list 与 Skill 目录都按 cwd 工作；Codex 的有效配置/特性也会根据 cwd 解析 project layer。“目录是全局的还是 workspace-scoped”是任何可扩展 Agent runtime 都可能具有的发现作用域，而不是 Pi 的路径编码规则。当前只有全局模型目录的 Provider 不必实现新端口。

## Bundle 目标形态

```dart
final AgentThreadSubscriptionPort? threadSubscription;
final AgentQueuedInputPort? queuedInput;
final AgentWorkspaceResourcePolicyPort? workspaceResourcePolicy;
final AgentScopedModelCatalogPort? scopedModelCatalog;
```

Pi 的初始组合：

| Bundle 字段 | Pi |
|---|---|
| `threadCatalog` | 非空，只负责 list/read |
| `threadSubscription` | `null` |
| `turnSteering` | 保留兼容视图 |
| `queuedInput` | 非空，支持两种 delivery |
| `workspaceResourcePolicy` | 非空，默认 deny，只在下一 runtime 生效 |
| `modelCatalog` | 非空，全局/无 workspace 目录 |
| `scopedModelCatalog` | 非空，显式消费 workspace + resource snapshot |

Application 只按端口与 typed delivery/scope 选择路径，禁止按 `AgentProviderKind` 或 provider id 分支。

## 不新增契约的 Pi RPC 功能

| Pi RPC 事实 | 决策 |
|---|---|
| Extension UI `notify` / `setStatus` / `setTitle` | 只有能无损映射为现有 typed status/thread-name/system event 时才输出；否则做脱敏计数诊断。 |
| Extension UI `setWidget` / `set_editor_text` | 不把任意 Provider UI 或编辑器改写穿透到 presentation。Pi 协议允许客户端忽略这类 fire-and-forget 请求。 |
| `get_commands` 的 extension/prompt command | Zeta 当前只有 Plan 与 Skill 的明确 Composer 语义。通用命令还涉及“是否创建 turn、是否立即执行扩展、参数与审批”，应另开功能流程，不在 Pi 接入中只建一个目录端口却没有完整执行契约。 |
| `bash` / `abort_bash` / `export_html` | 当前 Zeta 没有客户端主动远程 shell 或会话导出产品入口；不为了覆盖 Pi 命令数量而扩张 Bundle。 |
| `set_auto_retry` / `abort_retry` | 可观测且可回读的选项继续使用 `sessionConfiguration`；只有 setter 时不伪造 current value。取消正在进行的 retry 由 turn cancel 收敛。 |
| `queue_update` 中的原始文本 | 不持久、不记日志。如 UI 后续需要队列状态，先设计只含 scope/count/client identity 的 typed event，不把 raw 文本放入共享 extra。 |

## 门禁结论

- 四个端口均是可选且以中立领域语义命名；Pi wire 名称仅存在 Pi data codec/adapter。
- 不需要修改 `AgentEventCoalescingPolicy`、`CoalescingEventBuffer`、`AgentEventPipeline` 或 `AgentConversationTimelineStore`。
- 不支持的整个端口为 `null`；端口内不支持的 typed 变体抛 `UnsupportedError`。
- workspace-resource 选择与权限审批、权限策略、Plan 审批保持四套独立语义，不存在“信任项目 = 允许执行命令”的暗示转换。
- 这些契约会改变 Provider 边界；按开发者指南§7，实现前必须先就端口变更完成 Issue/评审决策，不在 Pi adapter PR 中边写边定。
