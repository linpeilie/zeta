# 命令集实时展开与滚动 · 需求分析

- 日期：2026-08-12
- 阶段：需求分析（未进入设计与实现）
- 需求类型：Agent 时间线命令集交互调整
- 决策状态：D1–D5 已确认

## 1. 实际要解决的问题

### 问题陈述

用户需要在实时回合中持续确认 Agent 刚刚执行了什么，同时仍能回看较早的对话。当前命令集把连续的非文件编辑操作压缩成一行摘要，能降低时间线噪声，但实时执行时也隐藏了最新命令；一旦手动展开较长的命令集，列表又会不断撑高整条时间线。

本需求实际要解决的是：让“当前正在推进的命令集”默认可见并自动跟随最新命令，同时把展开后的占用高度限制在稳定范围内；过去的命令集保持收敛，避免长命令序列挤走上下文或迫使用户反复操作。

### 当前行为与绕行方式

- 命令集默认折叠；实时新增工具调用只更新摘要，组内命令仍不可见。用户必须点击命令集标题才能查看每条命令。
- 展开体当前按全部条目纵向铺开，没有最大高度和独立滚动区域。条目较多时，用户只能滚动整条 Agent 时间线寻找最新命令，并在看完后手动折叠以恢复上下文密度。
- 新的命令集不会自动展开，旧的命令集也不会因失去“当前”身份自动折叠。用户需要重复点击多个命令集来判断执行进展。
- 外层 Agent 时间线已经具备“停留在末尾附近时跟随新增内容、用户主动上滚后停止抢回”的行为；但折叠命令集只露出摘要，因此该机制不能直接让用户看到组内最新命令。

### 已确认的现状边界

- 现有“命令集”是 presentation 层对连续非文件编辑操作的渲染分组；文件编辑组是另一类操作组。
- 命令集展开后只显示每项的类型与标题，不展示工具输出正文。
- “类似 Cursor”只描述期望交互，不代表恢复 Cursor Provider、读取 Cursor 数据或引入 Cursor 专属分支。

## 2. 可观察的验收标准

1. **展开一个条目超过固定高度的命令集时，会看到卡片高度停在该上限。** 继续查看后续条目时只滚动命令集内容区，外层时间线不会被全部条目持续撑高；条目未超过上限时不出现多余空白或无意义滚动。
2. **当前台 thread 的运行中 turn 末尾是命令集，且其后没有其他类型消息时，会看到这个最后命令集自动展开。** 同一视图中未被用户手动展开的非当前命令集保持折叠，用户无需先点击标题就能看到当前执行序列。
3. **后续内容使原命令集不再满足“当前命令集”定义时，会看到系统管理的原命令集自动折叠。** 新的当前命令集按同一规则展开；用户手动设置的展开/折叠结果优先，后续实时更新不会反向覆盖。
4. **当前命令集持续追加并超过固定高度时，会看到其内部列表自动滚动到最新命令。** 该行为只滚动命令集内部，不联动外层时间线；用户主动滚动命令集查看旧内容时不会被强制抢回，回到内部末尾后恢复跟随。

> 每条标准都应落成可重复的 Widget 测试与桌面手动场景；固定高度的具体像素值属于方案阶段的布局参数，不再作为产品歧义。

## 3. 明确不做的部分

- 不改变哪些事件会被合并为命令集，也不改变命令顺序、摘要计数、标题映射或文件编辑组的分组规则。
- 不把范围扩展到文件编辑组、单独工具详情卡、消息、reasoning、权限、提问或 Plan 卡片的展开行为。
- 不新增命令输出、原始工具 payload 或文件内容展示；本需求中的“最新命令”仍指现有命令集摘要项。
- 不增加 Provider 专属逻辑，不修改 Codex、Grok、Claude Code 的协议语义，也不恢复已退役的 Cursor Provider。
- 不改变用户主动离开末尾后的自由阅读语义，不以自动跟随为由强制抢走滚动位置。
- 不新增跨应用重启的命令集展开态或滚动位置持久化；若以后需要持久化，另行评估 G7 与迁移范围。
- 不在本阶段决定具体 Widget、状态归属、像素值、动画曲线或实现路径。
- 不涉及产品当前“暂不包含”的内置编辑器、文件编辑/保存、云同步、账号支付、完整插件系统或移动端。

## 4. 已拍板的需求决策

| 编号 | 决策结果 | 对后续设计的约束 |
|---|---|---|
| D1 | “当前命令集”是前台运行中 turn 的最后一个命令集，且它后面没有其他类型的消息。 | 同一 turn 不能把所有命令集同时视为当前；后续出现其他类型消息后，原命令集失去当前身份。 |
| D2 | 两个自动覆盖问题均为“否”：用户手动折叠当前命令集后，新命令到达不再次自动展开；用户手动展开旧命令集后，实时更新不立即把它折叠。 | 用户手动操作优先于自动规则，系统不得在后续实时更新中反复夺回展开态。 |
| D3 | 命令集使用固定最大高度。 | 具体像素值在方案阶段结合现有 token、文字缩放和窄窗口验证确定，不改成按行数或视口比例动态计算。 |
| D4 | 自动滚动只作用于命令集内部。 | 不新增命令集到外层时间线的联动滚动；外层继续沿用既有 follow/free 行为。 |
| D5 | 自动展开、折叠和内部跟随只作用于当前前台 thread。 | 后台 thread 不执行这套自动 UI 行为；切换到前台后再按当前可见状态判定。 |

D1–D5 的产品歧义已关闭，可以进入方案设计；当前仍不应直接写代码。

## 5. 门禁预判与复杂度

### 预计直接命中或高度相关的门禁

| 门禁 | 命中原因 | 需求阶段约束 |
|---|---|---|
| G1 | 现有命令集展开 id 由 `AgentConversationTimelineStore` 持有，而该文件属于共享适配层硬门禁范围；自动展开/折叠很容易把 presentation 分组语义写入共享 Store。 | 方案阶段必须先确认状态归属；不得把“最后一个分组”“当前 Provider”或 UI 滚动语义塞进共享层。若确需修改该文件，必须按 L 档处理并论证中立性。 |
| G2 | “当前/非当前”涉及 turn、entry 与渲染分组身份，不能用 `sourceItemId`、raw payload 或 Store 中的最后一条记录猜边界。 | 只消费 Provider 已规范化的 turn/entry 状态；不改变 entryId、消息边界、工具 upsert 或终态判定。 |
| G3 | 实时追加会触发展开态和滚动副作用。 | reducer 仍只同步产出状态/请求；滚动控制、动画和调度不得进入 reducer，live/history/replay 状态不得串用。 |
| G6 | 需求是中立时间线交互，不是 Provider 协议能力。 | 改动应停留在 agent presentation/application 的中立状态与 UI，不新增任何 Provider 分支或协议字段。 |
| G8 | 涉及折叠卡、最大高度、嵌套滚动、自动跟随、稳定 Key、长时间线虚拟化和 resize 热路径。 | 使用 Graphite token 与现有 UI 原语；遵守 reduce motion；不得 post-frame 测高、`GlobalKey` 查高或在用户滚动时强制定位。实现后需要 Widget 回归及 Windows Profile 的 resize/时间线采样。 |

### 不应被本需求触发的边界

- G4/G5：不新增 capability，也不改变权限、提问、Plan 审批或 Plan 执行交接。
- G7：本次不持久化展开态、滚动位置、命令或工具输出。
- 不新增或修改 `AgentEvent`、Provider adapter、共享 coalescing 策略或文件变更 evidence；若后续方案发现必须触及，停止并重新判档。

### 档位结论：L（保守预判）

需求本身是时间线 UI 行为，但现有命令集展开状态落在 G1 明确列名的 `AgentConversationTimelineStore` 中。自动展开/折叠会改变这份状态的生命周期，因此在方案证明可以完全留在 presentation 层之前，按“拿不准就当 L”处理，先走完整五阶段，不能直接实现。

如果方案阶段确认无需修改共享层、`AgentEvent`、Provider 端口、持久化或跨 feature 契约，且只调整 presentation 层及其测试，可以在记录理由后降为 M；需求分析阶段不预先替方案作这个判断。

## 6. 与产品需求文档的冲突检查

对照 `docs/product/product_requirements.md`：

- 需求直接服务于“在连续时间线中理解执行过程”“展示 Agent 消息与工具调用状态”和“允许用户滚动回看上下文”，属于现有产品范围。
- 最大高度与受控滚动也符合桌面窗口变化时避免内容明显溢出的非功能要求。
- 不涉及内置编辑器、文件内容读取/编辑/保存、远程仓库、云同步、Zeta 账号与支付、完整插件系统或移动端。
- “类似 Cursor”仅作为交互参照；不启动 Cursor、不读取或改写其私有数据，也不让 Cursor 回到 catalog、UI 或运行时，因此不与 Cursor 退役边界冲突。
- 保持 Provider 中立且不持久化命令正文，可继续满足协议隔离与敏感内容不落盘要求。

结论：**该需求与产品文档的“暂不包含”没有冲突，且强化了当前版本的可审计工具时间线目标。**
