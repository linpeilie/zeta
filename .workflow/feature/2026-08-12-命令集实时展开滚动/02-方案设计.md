# 命令集实时展开与滚动 · 方案设计

- 日期：2026-08-12
- 前置需求：`01-需求分析.md`，D1–D5 已确认
- 阶段：方案设计（未进入任务拆解与实现）
- 最终档位：**M**（方案确认不修改 G1 共享层、domain、Provider 端口或持久化）

## 结论先行

采用“**presentation 派生当前组 + 手动状态优先 + 卡片内独立跟随**”方案：

1. 当前命令集不进入 domain 或 Store。它由前台 `AgentPane` 使用当前 live turn 的 presentation render blocks 直接判定：turn 仍为 running，且最后一个 render block 是命令集。
2. 现有 `AgentExpansionState.commandGroupIds` 继续只表示用户显式展开的正向状态；新增 presentation-local controller，只保存“用户拒绝当前组自动展开”的负向覆盖。两者与自动当前组共同计算最终展开态。
3. 展开内容区固定最大高度为 **200 logical px**，标题行不计入该高度。短列表按内容自然收缩，长列表使用有稳定 item key 的 `ListView.builder` 和独立滚动条。
4. 每个已挂载的命令集卡片拥有自己的 `ScrollController` 与 `IdeVirtualScrollCoordinator`。前台当前组追加新命令时，只通知内层 coordinator；follow 模式下无动画贴底，用户上滚后进入 free，滚回底部再恢复。
5. 外层 Agent 时间线继续沿用现有 `AgentRequestAutoScroll` 与 follow/free 行为；本需求不新增、改写或屏蔽外层滚动 effect，也不调用外层 controller 定位命令项。
6. 虚拟列表的 command-group extent estimate 使用与 Widget 相同的 200px 上限和行高函数，展开后超过上限的新增命令不再持续抬高外层 sliver。
7. 不修改 `AgentConversationTimelineStore`、reducer、`AgentEvent`、Provider adapter、bundle/capability 或任何持久化结构。

推荐按此方案进入任务拆解。它满足 D1–D5，同时把新增语义完整留在 presentation，不扩大现有共享 Store 的 UI 状态职责。

## 1. 现状与关键调用链

### 1.1 live 事件到命令集卡片

当前链路为：

```text
Provider-local adapter / reducer
  → 中立 AgentEvent
  → AgentEventPipeline
  → AgentConversationReducer
  → AgentTimelineMutation
  → AgentConversationTimelineStore / AgentConversationTurnState
  → AgentConversationViewModel.liveTurnListenable
  → _AgentConversationTimeline
  → AgentTimelineProjectionCache.resolve
  → buildAgentTimelineRenderBlocks
  → AgentTimelineCommandGroupRenderBlock
  → AgentBlockViewportItem
  → _AgentTimelineBlockSection
  → _AgentCommandGroupCard
```

关键符号：

| 符号 | 当前职责 |
|---|---|
| `AgentConversationTurnState` | 保存 live turn 的规范化 entries、running 状态与 content/meta revision。 |
| `AgentTimelineProjectionCache.resolve` | 按 turn id + content revision 缓存 presentation render blocks；live 更新只失效对应 turn。 |
| `buildAgentTimelineRenderBlocks` | 把连续非文件编辑操作规约为 `AgentTimelineCommandGroupRenderBlock`；文件编辑组、消息等会切断分组。 |
| `AgentTimelineCommandGroup.id` | `command-group-<turnId>-<首条 entryId>`，组内追加命令时保持稳定。 |
| `projectAgentTimelineViewportItems` | 生成 block / activity / footer 粒度的稳定 viewport items；live block 带 `isLive=true`。 |
| `AgentTimelineExtentDescriptorFactory` | 用内容与展开指纹生成 layout revision 和冷启动估高，供动态 sliver 做锚点修正。 |
| `_AgentCommandGroupCard` | 读取 ViewModel 展开态，使用 `IdeCollapsibleCard` 渲染标题与无界 `Column`。 |

`buildAgentTimelineRenderBlocks` 已经决定了“用户可见顺序”。`think` 工具等既有隐藏项继续按当前规则跳过；本方案不会从 raw event、source id 或命令文本重建另一套顺序。

### 1.2 当前展开状态

当前手动展开调用链为：

```text
点击 _AgentCommandGroupCard header
  → AgentConversationViewModel.toggleCommandGroup(groupId)
  → AgentConversationTimelineStore.toggleCommandGroup(groupId)
  → AgentUiRegion.expansion
  → AgentExpansionState.commandGroupIds
  → Widget + AgentTimelineExtentDescriptorFactory
```

现状只有“显式展开 id 集合”这一位状态：集合内为展开，集合外为折叠。因此它无法表达：

- 当前组默认自动展开，但用户明确要求折叠；
- 当前身份改变后，只撤销系统默认值，不覆盖用户手动选择。

本方案不向 Store 增加“当前组”“最后 render block”或“自动折叠”语义。现有正向手动状态保留不动，缺失的负向覆盖由 presentation-local controller 补齐。

### 1.3 当前高度与虚拟列表

`_AgentCommandGroupCard` 展开体是包含全部条目的 `Column`，没有高度上限或自己的 controller。`AgentTimelineExtentDescriptorFactory._estimateCommandGroup` 同样按 `30 + itemCount × 28` 线性估高。

结果是：命令越多，单个 viewport item 越高；外层 sliver 的最大滚动范围持续增长。现有动态 sliver 能修正锚点，但不能替命令集提供内部滚动。

### 1.4 当前外层自动滚动

工具、消息等 live mutation 会产出既有 `AgentRequestAutoScroll`：

```text
AgentRequestAutoScroll
  → _AgentPaneState._handleUiEffect
  → IdeVirtualScrollCoordinator.notifyContentChanged
  → followEnd：frame-coalesced jumpTo(maxScrollExtent)
  → free：忽略，保留用户阅读位置
```

这条链路控制的是 `agent-message-list` 外层时间线。D4 只要求新增“命令集内部跟随”，因此本方案保持该链路原样，不复用外层 controller，也不为命令集新增 application effect。

### 1.5 前台状态与保活约束

`IdeHome` 为每个 workspace entry 创建独立 `AgentPane(viewModel, isActive)`，由 `IdeRetainedPageView` 保留已访问 thread。`_AgentConversationTimeline` 在 `isActive=false` 时不监听 live 高频信号，这是 D5 可复用的现有边界。

`AgentPane` 的响应式子树由 `IdeConstraintBucketBuilder` 缓存。当前 `didUpdateWidget` 只在 ViewModel 变化时替换 builder；方案必须让 `isActive` 变化也更新 builder identity，否则 compact/regular 档位不变时，缓存的 `_AgentConversationTimeline.isActive` 可能停留在旧值。

## 2. 目标行为与状态模型

### 2.1 当前命令集判定

新增纯 presentation helper：

```text
resolveAgentCurrentCommandGroupId(
  isForeground,
  liveTurn,
  liveRenderBlocks,
) → String?
```

只有同时满足以下条件才返回 group id：

1. `isForeground == true`；
2. `liveTurn != null`；
3. `liveTurn.status == AgentHistoryTurnStatus.running`；
4. `liveRenderBlocks.last` 是 `AgentTimelineCommandGroupRenderBlock`。

否则返回 `null`。activity/footer viewport item 不属于 turn render blocks，不参与 D1 的“后面是否还有其他类型消息”判定。若最后 block 是消息、文件编辑组、system/plan/interaction entry，则此前命令集立即失去自动当前身份；后续再形成新的末尾命令集时，新 group id 成为当前。

这里读取的是 `AgentTimelineProjectionCache` 已生成的稳定 render blocks，只决定展示默认值，不生成 id、不修改 narrative boundary，也不回写 Store。

### 2.2 展开态合成

新增 `AgentCommandGroupAutoExpansionController`，由 `_AgentPaneState` 持有。它只保存：

```text
suppressedAutoExpansionIds: Set<String>
```

最终展开态按以下优先级计算：

```text
explicitlyExpanded = AgentExpansionState.isCommandGroupExpanded(groupId)
autoCurrent = groupId == currentCommandGroupId
suppressed = controller.isSuppressed(groupId)

effectiveExpanded = explicitlyExpanded || (autoCurrent && !suppressed)
```

点击转换固定为：

| 当前状态 | 点击前有效态 | 点击后的状态 |
|---|---:|---|
| 非当前，未显式展开 | 折叠 | 调用既有 ViewModel toggle，写入显式展开。 |
| 非当前，已显式展开 | 展开 | 调用既有 ViewModel toggle，移除显式展开。 |
| 当前，仅由自动规则展开 | 展开 | 写入 suppression；后续新命令不重开。 |
| 当前，已被 suppression 折叠 | 折叠 | 移除 suppression，并写入显式展开；失去当前身份后仍保持展开。 |
| 当前，已有显式展开 | 展开 | 移除显式展开并写入 suppression，确保当前规则不会立即重开。 |

这张表直接固定 D2：系统默认只在用户没有明确选择时生效，后续 live rebuild 不反向覆盖用户。

controller 生命周期：

- 与一个 `AgentPane` State 同寿命；使用不可修改集合对外暴露诊断状态。
- `isActive` 在同一 ViewModel 上切换时不清空，保证暂时离开页面不会忘记用户选择。
- ViewModel 真正替换时清空，避免不同 thread 的 group id 串用。
- `dispose` 时释放 listenable；不使用 Timer、Future 或 Flutter scheduler。

现有 `AgentExpansionState.commandGroupIds`、`AgentConversationViewModel.toggleCommandGroup` 与 Store 的正向集合接口保持不变。未来若要把全部 UI 展开态移出 Store，应单独走等价重构，不与本功能混做。

### 2.3 固定高度与列表结构

在 `IdeMetrics` 新增语义尺寸：

```text
commandGroupBodyMaxHeight = 200 logical px
```

200px 只约束展开内容区，标题行和 `bodyPadding.top` 不计入。行高使用 `IdeMetrics.compactRowHeight` 作为 1.0 文本缩放下的基准，并随 `MediaQuery.textScaler` 放大：

```text
rowExtent = compactRowHeight × normalizedTextScale
naturalBodyExtent = itemCount × rowExtent
bodyExtent = min(naturalBodyExtent, commandGroupBodyMaxHeight)
```

Widget 使用同一计算结果：

- `SizedBox(height: bodyExtent)` 提供确定约束；
- `ListView.builder(itemExtent: rowExtent, primary: false)` 只构建可见行；
- 条目继续使用 `ValueKey('agent-command-group-item-<entryId>')`；
- 仅 `naturalBodyExtent > 200` 时形成可滚动范围，短列表的 `maxScrollExtent == 0`；
- 使用现有 Flutter `Scrollbar`，不创建新的跨 feature 滚动条原语；
- 文本仍单行 ellipsis，系统文字放大后通过更高 row extent 保持可读，200px 内可见行数相应减少。

`_AgentCommandGroupCard` 因持有内层滚动状态改为 `StatefulWidget`。`ScrollController` 必须在 `dispose` 中释放；卡片被 sliver 回收后，历史命令集的内部 offset 可以回到默认值，本需求不承诺持久化内部滚动位置。当前组重新挂载时会按 follow 规则回到最新命令。

### 2.4 命令集内部 follow/free

每个卡片 State 复用通用 `IdeVirtualScrollCoordinator`，绑定自己的 `ScrollController`：

```text
group.items.last.id 改变
  + effectiveExpanded
  + group 是前台 currentCommandGroup
  → innerCoordinator.updateLastItemId(lastItemId)
  → followEnd：下一帧无动画 jumpTo(inner.maxScrollExtent)
  → free：忽略
```

约束：

- 初次自动展开当前组时也提交 last item id，首帧布局完成后显示最新命令。
- 连续多条命令在同一帧合并为一次 reveal，禁止每条都启动 `animateTo`。
- 内层 `ScrollNotification` 只交给内层 coordinator；用户离内部底部超过既有阈值后进入 free，回到底部阈值内恢复 follow。
- `followLatest=false`、卡片折叠、非前台或 group 非当前时，不发内部 reveal。
- 不调用 `Scrollable.ensureVisible`、不使用 `GlobalKey` 查位置、不读取子项实测高度。
- 不向外层 `_scrollCoordinator` 发送命令项 id。外层是否根据既有 `AgentRequestAutoScroll` 跟随整条会话，继续由现有 outer follow/free 状态决定。

### 2.5 动态 sliver 的高度一致性

`AgentTimelineExpansionLookup.isCommandGroupExpanded` 的签名不变，但 `_AgentConversationTimeline` 传入的是上文的 `effectiveExpanded` closure，而不是直接传 `AgentExpansionState.isCommandGroupExpanded`。

同一个 closure 同时供：

- `_AgentCommandGroupCard.expanded`；
- `AgentTimelineExtentDescriptorFactory.describeAll` 的 expansion fingerprint。

新增共享的 presentation 几何函数，Widget 与 descriptor 都使用它计算 row/body extent。`_estimateCommandGroup` 的展开估高改为：标题估高 + body top padding + `min(自然列表高度, 200)` + 既有外间距。命令数超过上限后，内容 revision 仍会更新，但 estimated extent 不再线性增长；实测校正与估高不会因两套公式漂移。

当前 group id 变化时，旧/新 block 的 expansion fingerprint 分别变化，只有相关 descriptor 失效；历史前缀继续复用原实例，不重算 grouping 或 Markdown。

### 2.6 reduce motion 与前台切换

`IdeCollapsibleCard` 当前的 `AnimatedRotation` / `AnimatedSize` 固定使用 `IdeMotion` 时长。因为本功能会触发系统自动展开，必须在该共享 UI 原语内部读取 `MediaQuery.disableAnimationsOf(context)`：开启 reduce motion 时两处 duration 都为 `Duration.zero`，其他调用方行为不变。

`AgentPane.didUpdateWidget` 在 `oldWidget.isActive != widget.isActive` 时替换 `_responsiveBodyBuilder` identity，使 `IdeConstraintBucketBuilder` 失效缓存并把新的前台状态传到 `_AgentConversationTimeline`。该操作不清空草稿、外层滚动、projection cache 或命令组手动覆盖。

## 4. 契约变更

### 4.1 Domain 模型

**无变更。** 当前命令集是 presentation render block，不是 Provider 或业务领域事实；不向 `AgentToolCall`、turn、thread 或其他 domain 模型增加字段。

### 4.2 Bundle 端口与 capability

**无变更。** 三个活跃 Provider 都已经输出中立 tool/message 事件；自动展开和内部滚动不是 Provider 能力，不能新增 capability 或可选端口。

### 4.3 AgentEvent 与 reducer/effect

**无变更。** 不新增事件，不修改 tool/message identity、边界、终态或 reducer。内层滚动由 Widget 观察 `group.items.last.id` 变化触发，不增加 `AgentRequestAutoScroll` 变体。

### 4.4 持久化字段

**无变更。** suppression、内部 follow/free 和 offset 都是内存 UI 状态；应用重启后回到默认规则。不会保存命令、工具输出、group id 或滚动位置。

### 4.5 Presentation 内部契约

新增或调整的内部契约：

- `resolveAgentCurrentCommandGroupId(...) -> String?`：纯函数，不访问 ViewModel、Provider 或 BuildContext。
- `AgentCommandGroupAutoExpansionController`：持有 suppression set，暴露 `Listenable`、有效展开查询和用户 toggle 转换；集合只读暴露。
- `_AgentCommandGroupCard`：由“传 ViewModel 后自行读取状态”改为显式接收 `expanded`、`followLatest`、`onToggle`，降低 Widget 对全量 facade 的耦合。
- `agentCommandGroupRowExtent(textScale)` / `agentCommandGroupBodyExtent(itemCount, textScale)`：Widget 与 descriptor 共用的 presentation 几何函数。
- `AgentTimelineExpansionLookup` 类型签名保持不变，调用方改传 effective closure。

这些都不是跨 feature 稳定 API；无需 compatibility facade。

## 5. 门禁合规

### G1 · 共享适配层零 Provider 依赖

本需求**没有中立协议契约缺口**：

- Provider 已经产出语义完整的中立 entries；
- 命令集只在 `buildAgentTimelineRenderBlocks` 中出现；
- “前台”“最后 render block”“展开”“内部滚动”都是 presentation 事实。

因此不应修改共享 Store，也不应退回 Provider adapter/reducer——这里不存在某个 Provider 的兼容差异。方案明确不向 G1 文件加入 current-group、最后条目、自动折叠或滚动逻辑。现有 Store 的显式展开集合只作为未改动的兼容输入；新增 suppression 完全位于 presentation。

若实现时发现必须改 `AgentConversationTimelineStore`、CoalescingPolicy、Pipeline 或 ACP shared mapper，应立即停下：那说明实现偏离本方案，而不是发现了 Provider 契约缺口。

### G2 · 身份由 Provider 决定，Store 不猜

- group id 继续使用现有 presentation 稳定 id，不改写 entryId/source id。
- last render block 只决定 UI 默认展开，不生成 narrative boundary、segment 或 dedupe key。
- 不读 raw/extra，不按 Store 最后一条开放 entry 猜身份，不改变 tool upsert。

### G3 · reducer 纯同步，副作用走正确边界

- reducer 和 application effect 不变。
- 内部滚动是挂载 Widget 的展示副作用，由卡片 State + 通用 scroll coordinator 执行。
- controller 无 Timer/Future；frame coalescing复用 presentation/ui-core 的 coordinator。
- `isActive` 门控保证后台 pane 不订阅 live 高频流，也不执行自动展开/滚动。

### G6 · 分层依赖单向

- 新状态和布局都在 agent presentation；通用尺寸与 reduce-motion 行为在 ui/core。
- domain/data/application 不依赖 Flutter 滚动器或 render blocks。
- 不新增 Provider import、kind/id/display-name 分支。

### G7 · 敏感内容与持久化

- 不新增持久化；controller 只保存 group id 的内存 set。
- 内层列表仍只渲染现有摘要标题，不扩大到 command/output/raw payload。

### G8 · token、可访问性与时间线热路径

- 高度使用 `IdeMetrics`，颜色/文字继续走既有 Graphite token。
- 行使用稳定 ValueKey，长组改为 builder 而非无界 Column。
- 不测高、不使用 `GlobalKey`/`ensureVisible`、不在 layout 后 `setState`。
- 自动展开遵守 reduce motion，用户上滚后不强制定位。
- descriptor estimate 与 Widget 共用封顶公式；只失效当前相关 block。
- 实现验收必须补 Windows Profile 1280→1000→1280 十秒采样，Debug 结果不作性能结论。

G4/G5 不命中：不增加能力入口，也不改变任何审批或 Plan 语义。

## 6. 兼容性

### 6.1 旧数据

没有 JSON/schema 变化，不需要迁移或宽容解码。重启后 suppression 和内部 offset 不恢复，符合需求非目标。

### 6.2 旧调用方

- `AgentConversationViewModel.toggleCommandGroup`、`AgentExpansionState.commandGroupIds` 与相关测试辅助函数继续可用。
- 历史/完成 turn 仍默认折叠，用户手动展开/折叠语义保持；差异仅是展开内容超过 200px 后改为内部滚动。
- 现有文件编辑组、工具详情卡、Plan 卡和消息卡不使用新 controller。
- `AgentTimelineExpansionLookup` 不改签名，descriptor 的其他调用方只需继续提供 bool resolver。
- `IdeCollapsibleCard` 仅在系统开启 reduce motion 时把动画时长置零；正常动画兼容。

### 6.3 Provider 与 capability

Codex、Grok、Claude Code 共用同一中立 UI 行为。catalog、bundle、capability 和 unavailable/fallback 行为完全不变；Cursor 仍保持退役。

### 6.4 外层滚动

外层 `agent-message-list` 的 follow/free、滚到底部按钮、导航跳转和锚点修正保持现状。内部自动滚动不直接改变外层 offset；当外层本身处于 followEnd 时，既有 live effect 仍可能让整条会话保持贴底，这是原行为，不是新联动。

## 8. 风险与取舍

### 8.1 接受的风险

- **嵌套滚动的输入归属。** 鼠标位于溢出的命令集内容区时，滚轮优先操作内层列表；本方案不实现滚到边界后把剩余 delta 手工转发外层。这样职责确定且符合 D4，但用户需要把指针移出内容区才能直接滚动外层。
- **历史卡片被虚拟化后的内部 offset。** 卡片 State 被回收后 offset 可重置；需求只要求当前实时组跟随最新，不要求历史内层位置跨回收保存。保存每组 controller 会造成长会话资源累积，因此不做。
- **现有正向展开状态仍在 Store。** 本功能只叠加 presentation suppression，不借机迁移所有旧 UI 展开态。这样避免触碰 G1，但短期内有效展开态来自两个明确来源；转换表和 controller 单测必须锁定组合语义。

### 8.2 否决的方案

1. **把 current group / auto-expand 写进 `AgentConversationTimelineStore`。** 否决：命令组只存在于 presentation projection；Store 扫最后 entry 会违反 G1/G2，并把前台 UI 状态污染 history/replay。
2. **让 Provider adapter 标记“当前命令集”。** 否决：前台、render block 和展开滚动不是协议事实；会制造三套 Provider 分支和伪 capability。
3. **本次顺便把全部 command-group 展开状态迁出 Store。** 否决：这是独立等价重构，需迁移既有 ViewModel/UI state 与大量测试；与新增行为混做会扩大 G1 改动面。当前兼容输入不阻碍本方案。
4. **复用外层 `AgentRequestAutoScroll` 或新增 inner-scroll application effect。** 否决：外层 effect 没有 group/item 目标，且 D4 要求内层独立；Widget 已能从稳定 item id 观察内容追加，无需扩大 reducer 契约。
5. **继续使用 `Column`，外面包 `SingleChildScrollView`。** 否决：长组会一次性构建全部行，也不提供 builder 级可见项约束；嵌入动态 sliver 后性能不可控。
6. **每条命令调用 `animateTo` 或 `Scrollable.ensureVisible`。** 否决：流式更新会堆叠动画；`ensureVisible` 还可能带动外层 scrollable，并诱导 GlobalKey/测高路径。frame-coalesced 无动画 reveal 更稳定。
7. **按窗口比例计算最大高度。** 否决：D3 已拍板固定高度；200px 与现有紧凑桌面密度、Plan 可滚动列表上限一致，窄宽窗口行为可预测。
