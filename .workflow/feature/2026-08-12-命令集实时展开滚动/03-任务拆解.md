## 执行规则

1. 严格按序号执行；每次只做一步，完成、验证并提交后再进入下一步。
2. 每步先运行该行列出的定向测试，再按顺序执行固定门禁：

   ```sh
   dart format .
   flutter analyze
   flutter test
   git diff --check
   ```

   四条命令均退出为 0，且定向断言符合该步的可观察结果，才可把状态改为“完成”并提交。
3. 新 helper、controller 和几何契约先加入并由测试固定；生产 Widget 后续再接入。替换无界命令列表时，也先建立受限列表路径和测试，再移除旧 `Column` 路径。
4. `04-实现记录.md` 只记录方案偏离、临时决策或阻塞；顺利完成的步骤只更新本表状态。
5. 若实现中发现必须修改 G1 共享适配层、domain、`AgentEvent`、Provider adapter/reducer、bundle/capability 或持久化，立即停线，保持当前步骤未完成并回到方案评审，不得自行扩大范围。
