# 多语言支持 · 需求分析

- 日期：2026-08-12
- 状态：已确认
- 档位：L
- 原始需求：软件先支持英文和中文，可在设置中切换；默认使用当前系统语言，不支持时回退英语。

## 1. 用户实际要解决的问题

用户需要在自己能稳定理解的语言中操作 Zeta，而不必为了软件界面修改操作系统语言；首次使用时还应自动得到可用语言，避免在看不懂设置页的情况下寻找语言入口。系统语言不在支持范围时，界面也必须落到确定可用的英语，而不是随机、空白或中英混杂。

这包含三个直接问题：

1. 英文用户目前难以理解以中文为主的导航、设置、状态、错误提示和操作按钮。
2. 首次启动没有按系统语言选择界面语言，也没有明确的 unsupported fallback。
3. 用户无法在 Zeta 内主动切换语言并获得一致的应用自有文案。

### 当前行为与绕行方式

- 应用根组件目前没有配置应用 Locale、支持语言列表或本地化资源。
- 设置页只有常规、外观和 Agent 管理分区，没有语言选项；常规设置也没有语言字段。
- 现有界面文案大量直接写成中文，系统语言变化不会驱动 Zeta 切换界面。
- 仓库没有记录产品内的绕行方案。英文用户只能继续使用中文界面、依赖图标和既有记忆，或借助系统/OCR 等外部翻译；修改系统语言本身不能解决问题。

## 2. 可观察的验收标准

1. 首次使用 Zeta 时，把系统语言设为简体中文后启动，会看到 Zeta 界面显示简体中文。
2. 首次使用 Zeta 时，把系统首选语言设为英语后启动，会看到 Zeta 界面显示英语；把首选语言设为繁体中文或其他不受支持的语言后启动，即使后续首选语言列表中包含简体中文，也会看到界面回退为英语。
3. 首次启动完成后更改系统语言并重启 Zeta，会看到 Zeta 继续使用首次确定的语言；系统语言不再自动覆盖它。
4. 从已有版本升级并启动 Zeta，会继续看到现有中文界面；在设置中改选英语后，重启前界面保持中文，重启后会看到界面切换为英语。反向切换同样只在下次启动生效。
5. 在任一已选语言下依次打开 Zeta 的全部自有界面并触发空态、加载、错误、确认、Toast、对话框和系统通知，会看到所有 Zeta 自有文案使用所选语言；无障碍语义标签、窗口标题和应用菜单也一致。用户输入、Provider 回复、工具原始输出、代码、命令、模型名、项目名、文件名和路径保持原文，日期、时间、数字、百分比、复数和相对时间格式不随界面语言改变，`Agent`、`Provider`、`Thread`、`Token` 等产品术语保留英文；操作系统拥有的原生界面可以继续显示系统语言。

## 3. 明确不做

- 首期不支持英语、中文之外的第三种界面语言。
- 不自动翻译用户输入、Agent/Provider 生成内容、工具原始输出、代码、命令、模型名、项目名、文件名或路径。
- 不因为界面语言变化而改变发送给 Provider 的 Prompt、模型回复语言、Provider 协议、能力协商或运行行为。
- 不引入在线机器翻译、云端翻译服务、Zeta 账号体系或完整翻译管理平台。
- 不借本需求重做设置页、工作台布局、主题或导航，也不扩展内置编辑器、云同步、插件、支付等产品能力。
- 不扩展到移动端；本期仍以现有 macOS、Windows、Linux 桌面应用为范围。
- 不要求 Zeta 控制原生文件选择器等操作系统拥有界面的语言。

## 4. 产品决策与剩余歧义

### D1 · “中文”的 locale 边界（已确认）

中文仅指简体中文。繁体中文不在首期支持范围，按不受支持语言回退英语。

### D2 · “默认选择系统语言”的持续语义（已确认）

系统语言只在新用户第一次启动 Zeta 时用于确定初始语言。此后不持续跟随系统；首次确定的语言和用户后来在设置中选择的语言都应在后续启动中继续生效。

### D3 · 首期本地化覆盖面（已确认）

覆盖所有界面，不只覆盖工作台与设置核心流程。至少包括 Agent 管理、使用统计、时间线状态与审批卡、空态、加载态、错误、Toast、对话框、系统通知、无障碍语义标签、窗口标题和应用菜单。操作系统拥有的原生表面边界见 D8。

### D4 · 切换语言的生效时机（已确认）

设置中的语言选择在下次启动 Zeta 时生效，不要求当前进程即时切换。

### D5 · 已有用户的升级行为（已确认）

升级前已经使用 Zeta 的用户继续使用现有中文，不因升级时的系统语言自动改变；只有用户在设置中主动选择其他语言并重启后才切换。

### D6 · locale 是否同时控制格式与术语（已确认）

首期不随界面语言切换日期、时间、数字、百分比、复数或相对时间格式。`Agent`、`Provider`、`Thread`、`Token` 等现有英文产品术语继续保留英文。

### D7 · 多条系统首选语言的选择规则（已确认）

首次启动只判断系统首选语言的第一项。第一项不受支持时直接回退英语，不继续从后续列表中寻找简体中文或英语。

### D8 · 操作系统原生界面的语言边界（已确认）

原生文件选择器等操作系统拥有的界面可以继续使用操作系统语言，不要求跟随 Zeta 的手动语言选择。“覆盖所有”指覆盖所有 Zeta 自有界面与文案。

## 5. 与产品需求“明确不做”的冲突检查

结论：**没有冲突。**

`docs/product/product_requirements.md` §5 的“暂不包含”限定了内置编辑器、文件内容编辑/保存、远程仓库或云同步、自建账号与支付、完整插件系统、移动端以及 Cursor 相关能力。本需求只扩展现有桌面应用的界面语言与设置能力，不依赖也不放宽上述任何边界；第 3 节也显式排除了这些范围。

产品需求文档目前尚未把本地化列为已有能力、非功能需求或成功指标。需求获批并进入实现后，需要按真实最终范围同步长期产品文档；这属于补充新能力，不是修复现有冲突。

## 6. 预判门禁与复杂度

| 门禁 | 预判原因 |
|---|---|
| G6 | 语言解析会落在应用组合边界，文案覆盖跨越多个 feature 的 presentation；不得把 Locale 或展示文案下沉到 Provider 协议层，也需处理现有 domain 中带展示语义的中文标签。 |
| G7 | 已确认首次语言与手动选择需要跨启动保留，将修改 `~/.zeta/config/general.json` 的字段/版本语义，必须版本化、宽容读取并明确旧数据行为。 |
| G8 | 设置入口及跨页面文案调整仍需复用现有 UI 原语、Graphite token 和 `shadcn_flutter as sf` 约束，不得借本地化引入第二套主题/UI 路径。 |

预期不命中 G1–G5：本需求不应修改共享 Agent 事件层、entry identity、reducer 副作用边界、Provider capability 或四类审批语义；方案若需要改动这些边界，应视为范围异常并重新评估。

本需求判为 **L 档**：它是应用级、跨 feature 的结构调整，并且已确认要持久化语言选择，同时命中跨 feature 调整与持久化格式/迁移两项 L 档判据。依据 AGENTS.md 的本地化规则，后续还需同步权威规则与相关长期文档，并完整走方案设计、任务拆解、实现和验收阶段。
