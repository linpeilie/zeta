# 多语言支持 · 方案设计

- 日期：2026-08-12
- 前置需求：`01-需求分析.md`，D1–D8 已确认
- 阶段：方案设计（未进入任务拆解与实现）
- 最终档位：**L**

## 结论先行

推荐采用“**启动期冻结 Locale + ARB 类型安全资源 + feature-owned 文本目录端口 + 常规设置版本迁移**”这一套方案：

1. 新增纯 domain 枚举 `AppLanguage.english` / `AppLanguage.simplifiedChinese`，持久化为 `en` / `zh-Hans`。Flutter `Locale` 只在 app/UI 组合层出现。
2. 首次启动只读取 `PlatformDispatcher.instance.locales.first`。显式简体中文与无 script/region 的 `zh` 选择简体中文；繁体中文和其他不支持语言选择英语。结果先写入 `general.json`，以后启动只读设置，不再跟随系统。
3. `MainApp` 在构建任何有文案的界面前等待常规设置加载完成，并把本次进程的有效语言冻结；设置页修改的是“下次启动语言”，当前 Widget 树不切 Locale、不重建 Workbench。
4. 使用 Flutter `gen-l10n`、英文模板 ARB 和简体中文 ARB。Widget 文案直接通过 `AppLocalizations` 获取；application/data/reducer 中必须生成的 Zeta 自有文案，通过各 feature 定义的纯 Dart 文本目录端口注入，禁止把 `BuildContext` 或生成类下沉。
5. `shadcn_flutter 0.0.53` 只有英语资源，因此补 Zeta 自有的 `ShadcnLocalizations` 适配器，覆盖英语和简体中文；本需求不顺带升级或 fork 组件库。
6. `general.json` 升到 v3，存储迁移 marker 升到 v2。旧安装统一播种简体中文，真正的新安装按首次系统语言播种；写语言成功后才完成 marker。
7. 不修改 `AgentEvent`、Provider wire、bundle 端口或 capability。为覆盖共享时间线内部现有的中文 fallback，允许向 G1 的 `AgentConversationTimelineStore` 注入中立、不可变的 `AgentUiTextCatalog`，但实施前必须先开架构 Issue 并通过第 4.1 节的中立性审查。

这是唯一推荐方案。它完整满足 D1–D8，同时把语言选择、资源解析和 Provider 语义分开；后文列出的其他做法仅是已否决的取舍，不是待选方案。

## 1. 现状：关键符号与调用链

### 1.1 启动与根组件

当前启动链路是：

```text
main()
  → ZetaDataPaths.fromEnvironment()
  → _prepareZetaStorage()
  → ZetaStorageMigrator.migrate()        // 当前 marker v1
  → bootstrapDesktopWindow()
  → runApp(MainApp(dataPaths))
  → MainAppState.initState()
      → GeneralSettingsController.load() // unawaited
      → AppearanceSettingsController.load()
  → MainAppState.build()
      → sf.ShadcnApp(
          title: 'Zeta',
          home: IdeHome(...),
        )
```

关键现状：

- `pubspec.yaml` 没有开启 `flutter.generate`，也没有把 `flutter_localizations` / `intl` 声明为直接依赖；仓库没有 `l10n.yaml`、ARB 或应用级 Locale 配置。
- `sf.ShadcnApp` 未传 `locale`、`supportedLocales` 或本地化 delegates，应用实际使用组件库默认英语 Locale，但 Zeta 自有文案大多直接写成中文。
- 常规设置异步加载期间 `IdeHome` 已经可以构建。若直接在现状上增加语言字段，会先显示默认语言再跳到存储语言，产生错误语言闪现。
- `MainApp` 已是唯一装配点，适合冻结有效语言并组装各 feature 的文本目录；`lib/main.dart` 继续只负责启动编排。

### 1.2 常规设置与持久化

当前链路是：

```text
SettingsPage / IdeHome / DesktopAttentionController
  → GeneralSettingsController
  → GeneralSettingsStore
  → FileGeneralSettingsStore
  → ~/.zeta/config/general.json
```

`GeneralSettings` 当前为 v2，只包含发送快捷键和通知设置。`tryDecode` 能读 v1/v2；文件缺失、损坏或版本未知时回到默认值。`GeneralSettingsController._applySettings` 先改内存、再异步保存并吞掉写入错误，而且多个 setter 没有串行化，因此新增语言字段后存在两项风险：保存失败时 UI 误以为下次启动会生效，以及语言/通知/快捷键并发写入时后写结果覆盖前一次字段。

`ZetaStorageMigrator` 当前 marker 为 v1。每次正常启动都会写 marker，因此它可作为“已经运行过旧版 Zeta”的主要证据；旧 target 文件和旧 SharedPreferences key 可覆盖更早版本直接升级的情况。

### 1.3 Zeta 自有文案的产生位置

文案并不只在 Widget 中，当前至少有四条路径：

| 路径 | 当前代表符号 | 现状问题 |
|---|---|---|
| 直接 UI | `SettingsPage`、`IdeHome`、Agent/Usage/Management presentation、`ui/core` | `Text`、label、tooltip、semantic label、Toast、dialog 等大量硬编码中英文字面量。 |
| 共享 Agent 时间线 | `AgentConversationReducer` → `AgentConversationTimelineStore` → `AgentConversationViewModel` | reducer/store 会创建“思考”“计划就绪”、错误引导和系统事件等用户可见字符串；其中 TimelineStore 属于 G1 共享层。 |
| feature application/data | `AgentManagementController` 与三种 Provider management repository、Usage controller/repository、`IdeShellController` | 检测进度、错误、建议和回退说明先被拼成中文字符串，再交给 UI。 |
| 桌面/原生表面 | `DesktopAttentionController`、`FlutterDesktopNotificationService`、`IdeHome._windowMenus`、`MenuActionBridge`、macOS `AppDelegate` | 通知标题/正文和 Linux action 为中文；Windows/Linux 菜单为中文；macOS 自有 `File/Open Project…` 为英语。 |

此外，`UsageTimeRangePreset.label`、`UsageTaskStatus.label`、`UsageErrorCategory.nextAction`、`agentActivitySegmentLabel`、`agentToolKindLabel`、`AgentToolCall.displayTitle` 等把展示语言写进 domain helper。它们应保留中立 enum/facts，把语言映射移到 presentation 或显式文本目录解析器。

Provider/user 动态内容与 Zeta 文案必须分开：Provider 返回的标题、回复、模型描述、权限选项、工具输出，以及用户输入、项目名、文件名和路径保持原文；只有 Zeta 添加的标签、包装句、fallback 和引导需要本地化。

### 1.4 当前菜单、通知与第三方组件

- Windows/Linux 标题栏菜单由 `IdeHome._windowMenus` 构造，可直接读取当前 `AppLocalizations`。
- macOS 自有菜单由 `AppDelegate.installFileMenu()` 先创建，再由 `zeta/menu` 通道把点击转给 `MenuActionBridge`；当前通道只支持动作，不支持同步文案。
- `DesktopAttentionController` 根据中立 `AgentAttentionKind` 生成中文通知标题和安全正文；payload 已是版本化白名单，方案保持其结构不变。
- `shadcn_flutter 0.0.53` 的 `ShadcnLocalizations.supportedLocales` 只有 `en`。根 Locale 直接设为 `zh-Hans` 而不补 delegate，部分表单、Command、Calendar 等组件会缺资源或落回英语，不能满足“覆盖所有”。

## 2. 目标调用链与分层归属

### 2.1 启动期语言决策

目标启动链路固定为：

```text
main 捕获系统首选语言第一项（只捕获一次）
  → Zeta 启动存储编排
      → 只读判定 fresh / existing
      → ZetaStorageMigrator v2
      → 创建或升级 general.json v3
      → 返回 dataPaths + fallbackLanguage
  → MainApp 创建 GeneralSettingsController
  → await controller.load()
  → 冻结 effectiveAppLanguage
  → 加载 AppLocalizations / 组装不可变 feature 文本目录
  → sf.ShadcnApp(
      locale: explicit frozen Locale,
      supportedLocales: [en, zh-Hans],
      localizationsDelegates: [...],
    )
  → IdeHome 与 Provider/application services
```

等待阶段只渲染无文字的中性背景，不挂载 `IdeHome`、不创建会产生用户文案的 controller/reducer，因而不会出现中文/英文闪现。`effectiveAppLanguage` 不监听后续设置变化；系统在进程中发送 locale change 也不会改变它。

启动存储编排返回一个纯结果（建议命名 `ZetaStartupBootstrapResult`），至少包含“本次是否可使用文件持久化”和 `fallbackLanguage`。`FileGeneralSettingsStore` / `MemoryGeneralSettingsStore` 都由 app 组合层显式接收该 fallback：有效 v3 值优先；文件缺失、损坏或未知版本时才使用 fallback。这样宽容解码不会偷偷退回某个构造器默认语言。

首次 locale 解析放在纯函数中，app 层只把 Flutter `Locale` 拆为 `languageCode/scriptCode/countryCode`：

1. `en-*` → 英语；
2. `zh-Hant` → 英语，script 优先于 region；
3. `zh-Hans` → 简体中文；
4. `zh-TW` / `zh-HK` / `zh-MO` → 英语；
5. `zh-CN` / `zh-SG` → 简体中文；
6. 不带 script/region 的 `zh` → 简体中文；
7. 空列表或其他第一语言 → 英语。

`zh` 归入简体中文是本方案的技术规范化：它没有显式繁体证据；显式 `Hant` 或繁体地区仍严格按 D1 回退英语。解析函数只接收第一项而非整个列表，从 API 形状上固定 D7。

### 2.2 文案解析的两条路径

**路径 A：有 `BuildContext` 的展示代码。**

presentation 和 `ui/core` 通过 `context.l10n` 读取生成的 `AppLocalizations`。英文 ARB 是 key、description 和 placeholder 的模板真源；中文 ARB 必须一一对应。所有动态值使用具名、带类型的 placeholder，避免按中文语序拼接。

**路径 B：无 `BuildContext`、但必须产生即时用户文案的代码。**

每个相关 feature 在自己的 domain 边界声明窄接口，例如：

```text
AgentUiTextCatalog
AgentManagementTextCatalog
UsageStatisticsTextCatalog
DesktopAttentionTextCatalog
```

接口只接收中立 enum/facts 和必要的原文参数，返回当前进程语言的字符串；不暴露 ARB key、Flutter `Locale`、`BuildContext` 或 Provider raw payload。`lib/src/app/localization/` 中的 `ZetaTextCatalogs` 组合对象包装同一个 `AppLocalizations`，向外暴露按 feature 拆分的强类型适配器，再由 app composition 注入 reducer、store、controller、repository 和桌面通知实现。

目录对象不可变、无监听、无异步，因此适合 D4 的“重启生效”，也不会破坏 reducer 的同步性。live/history/replay 仍各用独立 reducer 实例，只共享无状态目录对象。

处理规则：

- Zeta 自有状态、错误包装、建议、按钮和 fallback 由目录生成。
- Provider 或用户给出的字符串作为 opaque placeholder 原样嵌入，不翻译、不改大小写。
- 日志文本不本地化；日志继续使用稳定技术英语并遵守脱敏规则。
- localized string 只进入当前进程的 UI state/timeline/通知，不写入 session、cache、usage index 或其他持久化 JSON。
- 只在 presentation 使用的 domain `label` getter 迁到 presentation localization extension；确需 application/data 使用的 formatter 改为显式接收对应目录，禁止隐式全局 Locale。

### 2.3 Flutter 资源与 `shadcn_flutter` 适配

新增：

```text
l10n.yaml
lib/src/ui/localization/arb/app_en.arb
lib/src/ui/localization/arb/app_zh_Hans.arb
lib/src/ui/localization/generated/...
lib/src/ui/localization/app_localizations_x.dart
lib/src/ui/localization/zeta_shadcn_localizations.dart
lib/src/app/localization/zeta_text_catalogs.dart
```

配置原则：

- `pubspec.yaml` 设置 `flutter: generate: true`，直接依赖 Flutter SDK 的 `flutter_localizations`，并把当前由工具链间接带入的 `intl` 声明为直接依赖。
- `MainApp` 显式传入 `AppLocalizations.delegate`、`GlobalMaterialLocalizations.delegate`、`GlobalWidgetsLocalizations.delegate`、`GlobalCupertinoLocalizations.delegate` 和 Zeta shadcn delegate；自有 delegate 排在 `ShadcnApp` 追加的包内英语 delegate 之前。
- 生成输出放在源码目录并使用本地 import；当前 Flutter 3.44 已不允许启用旧 `synthetic-package`，因此配置中不使用它。
- `l10n.yaml` 固定英文模板、`AppLocalizations` 输出类、非 nullable getter、required resource attributes、escaping 和 format；生成文件不手工编辑。
- 首期不使用 ARB plural/date/number format。日期、时间、数字、百分比和相对时间继续调用现有语言无关算法，目录只翻译外围静态文字；相关回归测试见第 6 节。
- Zeta 自有 `LocalizationsDelegate<sf.ShadcnLocalizations>` 覆盖 `en`/`zh-Hans`，把组件库公开抽象 API 转接到同一批 ARB 资源。参数化方法保留上游当前运算和格式，只翻译静态模板。组件库升级时，抽象成员变化必须由编译和契约测试暴露。
- 不升级 `shadcn_flutter`：升级会扩大为 Overlay/API 回归任务，也不能保证上游已有简体中文资源。

### 2.4 设置页与重启语义

语言选择放进现有 `_GeneralSettingsPane`，使用 `IdeSettingsRow` + `IdeSelect<AppLanguage>`，不新增设置分区、不改变 Workbench slot。选项始终用自称 `English` / `简体中文`，让用户即使误选语言也能找回。

交互链路：

```text
用户选择语言
  → GeneralSettingsController.setAppLanguage()
  → 串行化更新队列
  → AtomicTextFile 成功写 general.json
  → 再发布 settings.appLanguage
  → 当前界面显示“重启后生效”状态
  → 当前 effectiveAppLanguage 保持不变
```

若保存失败，controller 不修改内存选择，返回失败结果；设置页显示当前语言的错误 Toast。所有常规设置写操作进入同一串行队列，防止语言、通知和快捷键互相覆盖。用户在重启前把选择改回当前有效语言时，待生效提示消失。

### 2.5 平台表面

- Windows/Linux：`IdeHome._windowMenus` 从 `context.l10n` 生成“文件 / 打开项目 / 退出”。
- macOS：扩展 `zeta/menu` 协议，Flutter 在 Locale 就绪后发送自有 `File` 和 `Open Project…` 标签；`AppDelegate` 收到配置后才安装/更新该自有菜单，避免先出现错误语言。Cocoa 标准应用/Edit/View/Window/Help 菜单和文件选择器按 D8 视为系统拥有表面，可继续采用系统语言。
- Linux 通知 action label 通过 `DesktopAttentionTextCatalog` 注入 `FlutterDesktopNotificationService`；通知标题/安全正文由 `DesktopAttentionController` 使用同一进程目录生成。
- 窗口标题 `Zeta` 是不翻译的品牌名；`window_bootstrap.dart` 与 `sf.ShadcnApp.title` 继续一致。

### 2.6 分层与预计改动归属

| 层 | 新增/修改 | 原因 |
|---|---|---|
| `settings/domain` | `AppLanguage`；`GeneralSettings.appLanguage`。 | 语言偏好是纯业务状态，不依赖 Flutter Locale 或 JSON key。 |
| `settings/application` | 第一系统 locale 的纯解析策略；controller 串行、persist-first 更新。 | “首次选什么”和“何时发布设置”是应用策略。 |
| `settings/data` | `GeneralSettingsCodec` v1/v2/v3 宽容读写；file/memory store。 | JSON schema、字段名和版本只属于 data。 |
| `app` | 启动存储编排、语言冻结、目录组合、MainApp 服务装配、macOS 菜单桥。 | app 是跨 feature 和平台端口的唯一组合边界。 |
| `ui/localization` | ARB、生成类、BuildContext extension、shadcn delegate。 | Flutter 本地化与第三方 Widget 适配是跨 feature UI 基础设施。 |
| 各 feature `domain` | 必要的窄文本目录 port；移除带固定语言的 label helper。 | application/data 只依赖纯接口，不反向 import UI。 |
| 各 feature `application/data` | 注入目录并本地化 Zeta 自有即时文案；保留 Provider/raw 原文。 | 文案必须在产生点正确组合，同时协议结构仍只在 data。 |
| 各 feature `presentation` | 把直接 literal 和拼接替换为 `context.l10n`；补 semantics/空态/Toast/dialog。 | 用户界面文案由当前 Flutter localization 提供。 |
| `macos/Runner` | 自有菜单的 configure/update 通道。 | 仅原生壳能修改 NSMenu；业务动作仍回到 Flutter。 |
| tests/tool/docs | 资源契约、架构 guard、三平台验收清单；同步长期文档。 | 防止漏翻译、层级回流和后续新增硬编码。 |

不新建 `localization` feature：语言偏好属于 `settings`，Flutter 资源属于 `ui`，跨 feature 组装属于 `app`；单独 feature 只会增加一层没有独立业务生命周期的宽泛目录。

## 3. 契约变更

### 3.1 Domain 与应用契约

新增：

```text
enum AppLanguage {
  english,             // storage id: en
  simplifiedChinese,  // storage id: zh-Hans
}

GeneralSettings.appLanguage: AppLanguage
```

新增各 feature 的纯文本目录接口，以及必要的显式 formatter 参数。`AgentToolKind`、`AgentTurnActivityPhase`、usage status/range/error enum 等中立事实不变；原先返回固定中文的 getter 改由 presentation extension 或目录解析。

`GeneralSettingsController.setAppLanguage` 返回可观察的保存结果，供 UI 区分成功、无变化和持久化失败；其他 setter 保持现有调用形态，但共用串行 persist-first 内核。

建议结果类型固定为 `GeneralSettingsUpdateResult.applied / unchanged / persistenceFailed`，不把 I/O exception 文本直接交给 UI。第一系统 locale 解析函数接收拆开的 language/script/country 三个字符串；`AppLanguage` 到 Flutter `Locale('en')` / `Locale.fromSubtags(languageCode: 'zh', scriptCode: 'Hans')` 的映射留在 app/UI。

### 3.2 持久化契约

`~/.zeta/config/general.json` 从 v2 升到 v3：

```json
{
  "version": 3,
  "appLanguage": "en",
  "sendMessageShortcut": "enter",
  "notifications": {
    "enabled": true,
    "turnTerminalEnabled": true,
    "actionRequiredEnabled": true
  }
}
```

读取规则：

- v1：保留快捷键，通知取既有默认，语言补 `zh-Hans`。
- v2：保留快捷键和通知，语言补 `zh-Hans`。
- v3：识别 `en` / `zh-Hans`；未知语言 id 按“不支持”回退英语，未知字段忽略。
- 缺字段、损坏 JSON、未知 schema 版本不得阻断启动；未知版本若仍含可识别的 `appLanguage` 则只读采用但不自动改写，否则按启动期已判定的安全 fallback 进入应用，且不会用空状态覆盖其他存储。

存储 marker 升到 v2。迁移前先做只读 cohort 判定：有效 v1 marker、任一已知 Zeta target 文件或任一旧 Zeta SharedPreferences key 都视为 existing；完全没有证据才视为 fresh。

迁移规则：

| 输入 | 写入/保留语言 |
|---|---|
| existing + 无 general 文件 | 创建 v3，`zh-Hans`。 |
| existing + 有效 general v1/v2 | 原字段无损升级到 v3，`zh-Hans`。 |
| 有效 general v3 | 保留用户已有语言。 |
| fresh + 无 general 文件 | 创建 v3，写第一系统 locale 的解析结果。 |
| 损坏或未知未来版本 | 启动不失败、不在自动迁移中破坏未知内容；本次使用 cohort 对应 fallback，用户显式保存语言时再写当前 v3。 |

只有 general 的创建/升级与其他迁移步骤都成功后才写 marker v2。失败时保持当前“本次运行禁用文件持久化、下次重试”的保护，并把只读 cohort/系统解析得到的 fallback 注入内存 store。当前正常版本每次启动都会留下 v1 marker；对于“从早于 marker 的版本直接升级且从未留下任何已知数据”的安装，磁盘上与全新安装不可区分，这是唯一不可观测边界，按 fresh 处理并在风险中记录。

### 3.3 Agent、bundle、事件与 capability

- **AgentEvent：不新增、不修改。** Locale 不是 Provider 事件语义，不进入 raw/extra，也不要求 Provider 上报已翻译标题。
- **AgentProviderBundle：不新增端口。** 本地化是 Zeta app/UI 基础能力，不是 Provider 可选能力。
- **capability：不变化。** 不增加 capability flag，不隐藏任何现有入口，也不使用 no-op 降级。
- **审批契约：不变化。** 权限、问题、Plan 审批和 Plan 执行交接只替换 Zeta 自有展示文案，request/decision/pending registry/回写路径原样保留。
- **时间线状态：不持久化语言。** 共享 store/reducer 只接收本进程不可变的 `AgentUiTextCatalog`；entryId、segment、terminal、coalescing、tool upsert 和 replay signature 均不变。

### 3.4 平台通道契约

`zeta/menu` 保留原生到 Flutter 的 `openProject` 事件，新增 Flutter 到原生的版本化菜单配置（至少包含 schema version、`fileMenuLabel`、`openProjectLabel`）。未知版本/缺字段时原生侧不安装或不更新 Zeta 自有菜单，不能伪装成功；通道不承载路径、用户内容或 Provider 数据。

## 4. 门禁合规

### 4.1 G1 · 共享适配层零 Provider 依赖（直接命中）

全量覆盖发现 `AgentConversationTimelineStore` 当前亲自生成“思考”等用户可见 fallback；若不改它，英语模式必然残留中文。这里是**中立展示契约缺口**，不是 Provider 兼容逻辑，理由是：

1. 同一 fallback 由 Codex、Grok、Claude Code 的中立 `AgentToolKind` / error facts 共同触发，与 providerId、kind、显示名或 wire 字段无关。
2. 变更只把固定中文替换为构造函数注入的 `AgentUiTextCatalog`；不读取 raw/extra，不增加 Provider 分支。
3. 不改变 event identity、entryId 分配、message segment、reasoning phase、去重、终态、文件变更 snapshot、coalescing 或 merge。
4. catalog 是不可变同步值；共享层仍输出相同形状和顺序的中立 timeline mutation，只是 Zeta 自有展示字符串按启动语言生成。
5. 实施中一旦某条文案需要识别 Provider wire/kind 才能决定，立即退回对应 Provider adapter/reducer；不得把该分支放入 Store、CoalescingPolicy 或共享 ACP mapper。

按 G2 的升级警告，**修改 TimelineStore 前必须先开架构 Issue，附上述论证、改动点和 provider-neutral architecture test；未通过评审则此实现步骤阻塞，不能静默绕过。** `AgentEventPipeline`、CoalescingPolicy/Buffer、Dispatcher 和共享 ACP decoder/codec/mapper预计不改。

### 4.2 其他门禁

| 门禁 | 命中方式 | 合规措施 |
|---|---|---|

## 5. 兼容性

### 5.1 旧数据与升级用户

- general v1/v2 宽容读取并升级，快捷键/通知值不丢失，语言固定补简体中文，满足 D5。
- 有 marker/旧 target/旧偏好的用户即使从未写过 `general.json`，也会生成中文 v3。
- v3 未知字段忽略；未知语言 id 回退英语；损坏文件不阻断应用启动。
- 旧通知 payload、IDE session、Provider config、usage index、model cache 和 Provider history schema 均不变。
- 升级前已投递到系统通知中心的通知不会被追溯改写；重启后新投递通知使用当前有效语言。

### 5.2 旧调用方与测试

- `MainApp` 增加可选的启动语言/系统 locale 注入点；现有未指定语言的测试 fixture 默认简体中文，避免把语言迁移与无关测试同时混在一起。英语专项测试显式注入 `AppLanguage.english`。
- 新增 required 文本目录的内部构造器由 app composition 与统一 test fixture 一次补齐，不提供隐藏的全局 singleton；这是仓库内部 source migration，不是对外 SDK 破坏。
- `GeneralSettingsController` 现有 shortcut/notification 方法保持签名和成功路径；保存改为串行 persist-first 后，失败不会再产生“仅本次内存看似生效”的假状态。
- Provider 返回值、命令、路径、模型名和用户内容不通过 ARB，因此现有动态内容断言保持原文。

### 5.3 运行时与 capability

- 当前进程只持有一个有效 Locale；切换设置不销毁 `IdeHome`、AgentPane、thread binding、草稿、滚动位置或 Provider runtime。
- 下一次进程启动后，所有新的 controller/reducer/catalog 从新 Locale 一次组装；不存在半中文半英文的旧单例。
- Provider catalog、能力协商、permission policy 和 wire 参数完全不变，因此不需要 Provider CLI/schema smoke；只需要现有三 Provider 的中立 UI/replay 契约回归。

## 7. 风险、取舍与已否决方案

### 7.1 主要风险与控制

| 风险 | 控制 |
|---|---|
| 文案分散，人工迁移易漏 | 先生成可审计 inventory，再按 surface/feature 清零；ARB parity、literal guard 和双语言真实 `IdeHome` 测试共同兜底。 |
| 英文通常更长，现有中文布局可能溢出 | 对导航、卡片、按钮、错误态跑窄视口和 text scale；继续使用有界布局、ellipsis、Wrap/Flexible，不借机重做视觉。 |
| shadcn 只有英语，适配器随包 API 漂移 | 版本保持 0.0.53；公开抽象 API 全量实现；编译和代表组件测试作为升级门禁。 |
| 启动等待设置造成短暂空白 | 只显示中性背景，存储读取失败走宽容 fallback；优先保证无错误语言闪现，避免先挂载再销毁整个 Workbench。 |
| localized string 在 application 中生成后长期存活 | D4 保证进程语言不变；目录不可变且只用于内存对象，持久化写入点加 guard。 |
| 旧安装 cohort 判定存在理论盲区 | marker + target + legacy key 覆盖所有可观测证据；完全无磁盘证据的史前安装无法与 fresh 区分，明确记录并按 fresh 处理。 |
| macOS 自有菜单在 Flutter 就绪前出现错误语言 | configure 前不安装该自有菜单；就绪后一次安装，动作继续走现有通道。 |

### 7.2 已考虑但否决

- **当前进程即时切换 Locale**：与 D4 冲突，还会重建根本地化依赖并放大 AgentPane/overlay/菜单/第三方组件状态一致性风险。
- **把语言放进 appearance 或 ide_session**：语言是全局常规偏好，不是主题或可丢弃会话状态；会使迁移与 ownership 错位。
- **依赖 Flutter 默认 locale list resolution**：它可能继续扫描第二项，也可能把繁体中文匹配到 `zh`，违反 D1/D7；必须显式解析第一项并传冻结 Locale。
- **在渲染末端按完整中文字符串查表替换**：动态拼接、placeholder 和未来改文案都会失配，且无法覆盖 notification/reducer/native menu。
- **让 application/data 直接 import `AppLocalizations` 或传 `BuildContext`**：把 Flutter 展示层反向渗入协议和业务层，违反 G6，也让 reducer 无法保持纯同步可测。
- **新增一个全局、字符串 key 驱动的万能翻译字典**：失去编译期 key/参数校验并形成跨 feature 上帝接口；采用 feature-owned 窄端口和 app 层的强类型适配器集合。
- **给每个 `AgentEvent` 增加已翻译 title，让 Provider adapter 负责补文案**：Locale 不是 Provider 语义，会复制三套逻辑并把 UI 需求推入 wire mapper；本需求保持事件不变。
- **升级/fork `shadcn_flutter` 来取得中文**：当前版本没有上游中文可直接采用；升级/fork会引入 Overlay/API 和长期维护范围，不是本需求必要条件。
- **把所有 Provider 错误、模型描述和用户内容都翻译**：违反明确不做；只翻译 Zeta 自己的包装和 fallback，动态原文保持不动。
