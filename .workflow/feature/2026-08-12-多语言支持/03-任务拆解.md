## 执行规则

1. 严格按序号执行；每次只完成、验证并提交一步，再进入下一步。每次提交同时把本表对应状态改为“完成”。
2. 每步先运行该行列出的定向命令，再按顺序运行固定门禁：

   ```sh
   dart format .
   flutter analyze
   flutter test
   git diff --check
   ```

   定向断言符合预期且四条固定门禁全部退出为 0，才允许提交。
3. 步骤 1—6 只增加护栏、资源、契约和中文等价路径；步骤 7—13 按 feature 切换文案来源；步骤 14a 先收口已接线 chrome 与架构护栏；步骤 14b 再摘除剩余旧 literal 并重建 allowlist；步骤 15 才正式启用系统首选语言与设置切换。
4. 步骤 11 开始修改 G1 的 `AgentConversationTimelineStore` 前，必须已有经确认的架构 Issue。Issue 未通过时停在步骤 10，不得用 Provider 分支或 `AgentEvent` 翻译字段绕过。
5. `04-实现记录.md` 只记录方案偏离、临时决策或阻塞。若发现必须修改 `AgentEvent`、bundle/capability、审批语义，或某一步无法独立保持全绿，立即停止并重新评审拆分。
6. 不修改 `dart_test.yaml` 并发度；不升级 `shadcn_flutter`；除 Flutter SDK 的 `flutter_localizations` 和直接声明 `intl` 外不增加运行时依赖。

## 提交与验收边界
