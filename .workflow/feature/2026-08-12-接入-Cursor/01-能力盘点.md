# Cursor ACP 能力盘点

日期：2026-08-12  
阶段：第一轮（只做协议与契约盘点，不写代码）

## 结论

Cursor CLI 现在已有官方 `agent acp` / `cursor-agent acp` 入口，使用 stdio、JSON-RPC 2.0
和换行分帧；官方文档明确覆盖初始化、认证、新建/加载 session、prompt、流式 update、
权限请求、取消、Agent/Plan/Ask 模式，以及用户提问和 Plan 审批扩展。这是退役时没有的
新证据，值得重新评估。

但本轮**不能把 Cursor 视为已准入 Provider**：仓库当前权威规则仍要求 Cursor 在 catalog、
选择、恢复、factory、进程、live/replay/load 与 ACP 扩展边界 fail-closed。因此本文件只记录
“解除退役门禁后的候选能力”，不改变以下当前事实：

- `AgentProviderCapabilities.defaultsFor(AgentProviderKind.cursorAcp)` 仍为全关闭；
- `CursorRetirementPolicy` 仍过滤 Cursor；
- `DefaultAgentProviderFactory` 仍抛 `UnsupportedError`；
- 本轮没有启动 Cursor 进程，没有读取或改写 `~/.cursor`、项目 `.cursor` 或遗留索引。

进入实现前，必须先有明确的重新准入决策，并按 `AGENTS.md` §6 同步修订退役事实与相关
架构文档；在此之前，任何“候选支持”都不得转成 UI 入口或运行时能力。

## 判断口径

状态含义：

- **候选支持**：Cursor 官方 ACP 文档明确声明，仍须用锁定 CLI 版本的真实脱敏 fixture 验证。
- **动态支持**：只能以实际 `initialize` / `session/new` 返回的 capability 或目录为准；省略
  即不支持。
- **按不支持处理**：ACP 标准可能有该能力，或 Cursor 的交互式 CLI 有类似功能，但 Cursor
  官方 ACP 契约没有给出足够证据。按 G4 保守关闭。
- **Zeta 本地机制**：不是 Cursor 协议能力，但实现仍必须真的完成资源或状态操作，不能用
  空实现伪造成功。

证据优先级是：锁定版本的真实握手/fixture（本轮尚无）＞ Cursor 官方 ACP 文档 ＞ ACP v1
标准。ACP 标准只说明协议能表达什么，不能证明 Cursor 实现已经支持。

## Bundle 端口能力矩阵

| `AgentProviderBundle` 端口 | 候选判断 | Cursor 证据与边界 | 解除退役后的保守表达 |
| --- | --- | --- | --- |
| `runtime`（必选） | 部分候选支持 | 官方支持 `agent acp`、stdio JSON-RPC、`initialize`、认证与 `session/update`。生命周期、scope、事件流和 dispose 可由 adapter 完整实现；`runtimeInfo` 可为空。ACP 未明确给出可靠的运行中模型切换契约。 | 端口必选；`initialize`/`dispose`/events/lifecycle/scope 实现真实行为。`updateModelSelection` 在模型选择未验证时同步抛 `UnsupportedError`。bootstrap 暂定 `workspaceScoped`，以项目目录和项目 MCP 语义为准。 |
| `conversation`（必选） | 候选支持，恢复与图片为动态能力 | 官方流程明确包含 `session/new`、`session/load`、`session/prompt`、`session/cancel`。`loadSession` 和图片输入仍应服从握手；省略就不调用。 | `canCreateSession=true`、`canPrompt=true`、`canCancelTurn=true`；`canResumeSession`/`canReadHistory` 仅在握手确认后为 true。未确认时 `resumeSession` 抛 `UnsupportedError`，绝不回退成“新建并假装恢复”。 |
| `threadCatalog` | 部分候选支持 | `session/load` 可以回放完整历史，因此可映射 `readThreadHistory`。Cursor ACP 文档没有声明 `session/list`；交互式 `agent ls` 不是等价的结构化 ACP 契约。 | 只有 `canReadHistory` 可动态开启；`canListThreads=false`，调用 `listThreads` 抛 `UnsupportedError`。`unsubscribeThread` 只能释放 adapter 实际拥有的订阅/回放资源；没有远端订阅不应被包装成新的能力。 |
| `threadMutations` | 按不支持处理 | Cursor ACP 文档未声明 rename/archive/unarchive/delete/compact。ACP v1 的可选 `session/delete` 本身不能证明 Cursor 支持；`/summarize` 也不等于结构化 compact RPC。 | 端口为 `null`；`canRenameThread`、`canArchiveThread`、`canUnarchiveThread`、`canDeleteThread`、`canCompactThread` 全为 false。旧必选门面误调用时抛 `UnsupportedError`，不能发 slash prompt 代替。 |
| `threadBranching` | 按不支持处理 | Cursor 文档没有 fork；ACP session fork 仍不能作为 Cursor 实现证据，更没有指定历史 turn 边界的证据。 | 端口为 `null`；`canForkThread=false`、`canForkThreadAtTurn=false`；不能用 load + 新建 session 冒充分支。 |
| `turnSteering` | 按不支持处理 | Cursor 交互式 CLI 的排队 follow-up 不等于 ACP 对活动 prompt 的 steer；官方 ACP 流程未声明相应方法。 | 端口为 `null`；`canSteerTurn=false`。不能用 cancel + 新 prompt 伪造 steer。 |
| `interactions` | 部分候选支持 | 标准 `session/request_permission` 支持逐请求选择；Cursor 扩展 `cursor/ask_question` 支持结构化问题、Skip 与 Cancel。没有 Guardian denied-action 放行方法。 | 端口可因前两项存在而暴露；`supportsPermissionRequests=true`、`supportsUserQuestions=true`。`approveGuardianDeniedAction` 必须抛 `UnsupportedError`；权限、问题各用独立 pending registry。 |
| `modelCatalog` | 本轮按不支持处理 | 交互式 CLI 官方支持 `agent models`/`--model`，但 Cursor ACP 文档未承诺稳定的模型目录、当前模型 ID 或 session 内切换结果。人类可读命令输出不能直接当稳定协议。 | 端口为 `null`；`supportsModelSelection=false`、`supportsReasoningOptions=false`、`supportsServiceTierSelection=false`。后续真实 ACP `configOptions` 或版本化机器输出证明闭环后，可复用现有端口，不返回空目录伪装成功。 |
| `conversationModes` | 候选支持，但映射存在契约风险 | Cursor 官方明确列出 `agent`、`plan`、`ask` 三种 ACP session 模式；ACP 可通过 mode/config option 改变 session 状态。现有 Zeta 回合配置却要求非空 `effectiveModelId`，且把模式选择冻结在下一回合，二者并不天然等价。 | 在第二轮先审查契约缺口；缺口解决且真实 `session/new` 返回可用目录前，端口为 `null`、`supportsModeSelection=false`。不得通过提示词伪造 Plan/Ask。 |
| `skills` | 按不支持处理 | Cursor 交互式 CLI 有 Skills，但官方 ACP 文档没有结构化 skill 目录、变更信号或 prompt skill block。 | 端口为 `null`；`supportsSkillInput=false`。不能把结构化 `AgentUserInput.skill` 静默降级为 `$name` 文本。 |
| `localThreadList` | 按不支持处理 | 该端口语义是只删 Zeta/Provider 本地列表记录，不删服务端历史。当前没有获准读取或维护 Cursor 会话索引，也没有 Cursor ACP 对应操作。 | 端口为 `null`；`canRemoveThreadFromList=false`。尤其不得触碰退役遗留 `cursor_sessions.json` 或 Cursor 自有目录。 |
| `sessionConfiguration` | 动态、当前按不支持处理 | ACP v1 能表达 `configOptions` 与 `session/set_config_option`，但 Cursor ACP 文档没有承诺实际返回哪些 option，也没有本轮真实 round-trip 证据。 | 只有 `session/new/load` 返回合法非空 options，且逐项 set 后返回权威完整快照时才可暴露。当前端口为 `null`；不能用空 options 表示“支持”。 |
| `planApproval` | 候选支持 | Cursor 官方 `cursor/create_plan` 是阻塞请求，结果为 accepted/rejected/cancelled，与现有独立 Plan 审批语义吻合。 | 端口可暴露；`supportsPlanApproval=true`。它只响应 Provider 发起的审批，绝不替代 Zeta 本地 Plan 执行交接，也不预授权计划中的操作。 |
| `permissionPolicy` | 按不支持处理 | `session/request_permission` 是逐请求审批，不是“列出并应用会话权限策略”。Cursor CLI 配置中的持久权限也不是已验证的 ACP policy catalog。 | 端口为 `null`。不能把 allow-once/allow-always 选项伪装成全局 policy，也不能读取/改写 Cursor 配置来制造该能力。 |
| `usageQuota` | 按不支持处理 | Cursor CLI 的 `/usage` 是用户界面能力；官方 ACP 文档未声明 Zeta 所需的账号套餐、用量窗口、余额和重置时间结构化接口。 | 端口为 `null`；`supportsUsage=false`。不得返回 `null`/空窗口并宣称成功，也不得解析 TUI 文本。 |

## 输入与交互细分

| 能力 | 候选判断 | capability 表达 |
| --- | --- | --- |
| 文本输入 | 候选支持 | `supportsTextInput=true` |
| 文件/路径 mention（ACP `resource_link`） | 候选支持 | `supportsResourceInput=true`；只编码引用，不擅自读取正文 |
| 本地图片 | 动态支持 | 初始化前 false；仅当 `promptCapabilities.image == true` 且 adapter 能发送真实 MIME/base64 block 时改为 true |
| 结构化 Skill | 不支持 | `supportsSkillInput=false`，误调用抛 `UnsupportedError` |
| 权限审批 | 候选支持 | `supportsPermissionRequests=true`；只回写用户当次选择，不自动选择 allow-always |
| 结构化用户提问 | 候选支持 | `supportsUserQuestions=true`；空答案只表示 Skip，不与权限决定混用 |
| Plan 审批 | 候选支持 | `supportsPlanApproval=true`；与 Plan 执行交接隔离 |

## 候选 capability 基线

即使完成重新准入，初始化前也只声明可以由版本门槛和官方稳定契约确认的最小集合；动态项
在握手或 session 建立后收紧/开启：

| capability | 初始化前候选值 | 动态规则 |
| --- | --- | --- |
| `canCreateSession` | true | `session/new` 契约失败则初始化失败，不静默降级 |
| `canResumeSession` | false | 仅 `loadSession == true` 后开启 |
| `canListThreads` | false | 仅未来握手明确声明并通过分页 smoke 后开启 |
| `canReadHistory` | false | 与经过验证的 `session/load` replay 同步开启 |
| `canPrompt` | true | 依赖 `session/prompt` 基线 |
| `canCancelTurn` | true | 依赖 `session/cancel` 基线 |
| 所有 thread mutation / fork / steer | false | 不从 CLI 同名交互或提示词推断 |
| `supportsTextInput` | true | ACP 基线 |
| `supportsResourceInput` | true | ACP `resource_link` 基线 |
| `supportsLocalImageInput` | false | 仅握手 image=true 且编码器验证后开启 |
| `supportsPermissionRequests` | true | Cursor 官方流程与 fixture 双重固定 |
| `supportsUserQuestions` | true | 以锁定版本的 `cursor/ask_question` fixture 固定 |
| `supportsPlanApproval` | true | 以锁定版本的 `cursor/create_plan` fixture 固定 |
| model / mode / reasoning / tier / usage | false | 分别等待可回写目录、模式契约、结构化 usage 证据 |
| `bootstrapPolicy` | `workspaceScoped` | 项目 cwd 与项目级 MCP 需要明确 workspace；禁止 eager 启动 |

当前仓库的实际默认值仍是 `AgentProviderCapabilities.unsupported`，上表不是代码变更建议。

## 不支持能力的统一表达

若后续获准实现，所有不支持项按同一规则处理：

1. 有独立 capability 位的，一律为 false，UI 不展示入口。
2. 整个可选能力域不支持时，bundle 端口为 `null`。
3. 一个已暴露端口中只有部分方法可用时，每个方法仍独立校验；不支持的方法抛
   `UnsupportedError`。
4. 必选 `runtime` / `conversation` 上被 capability 关闭的方法也抛 `UnsupportedError`。
5. 禁止用空列表、空 answers、`null` 快照、成功完成的 no-op、提示词/slash command、
   cancel+重发或“新建当恢复”伪造能力。
6. ACP 未声明的 capability、未知扩展、method-not-found 和握手省略字段都按不支持处理；
   网络失败、超时、malformed response 则作为真实错误抛出，不能降级成 unsupported 后静默成功。

## 进入第二轮前的阶段门

- 用户确认这是“重新准入评估”，并接受必须先解除/同步 Cursor 退役门禁；
- 第二轮只设计中立契约，不恢复 Git 历史中的旧实现，不使用 synthetic Cursor fixture；
- 实现前另行锁定最低 Cursor CLI 版本，并以 `cursor-agent` 作为优先可执行名，避免与 Grok
  的通用 `agent` 名称碰撞；
- 实现前采集 macOS、Windows、Linux 的真实、脱敏 `initialize → session/new/load → prompt`
  fixture；缺设备或凭据的平台明确标为阻塞，不能推断通过；
- fixture 必须证明 messageId/event identity、delta/snapshot、终态、权限、问题、Plan 审批、
  mode/configOptions 与 replay 语义，且不得包含 prompt、回复、文件正文、凭证或原始敏感路径。

在这些条件成立前，本任务停留在能力盘点，不进入代码实现。
