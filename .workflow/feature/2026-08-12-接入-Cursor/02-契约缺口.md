# Cursor ACP 契约缺口

日期：2026-08-12  
阶段：第二轮（只设计 Provider 中立契约，不写代码）

## 结论

**本轮不新增 `AgentProviderBundle` 可选端口，新端口数量为 0。**

Cursor ACP 的所有可调用操作都已能由现有端口表达；它的三个非阻塞扩展是
Provider 向 Zeta 发送的入站通知，应该映射为中立 `AgentEvent`/工具载荷，不是增加
“可被 UI 调用”的 bundle port。为厂商通知创建端口，会把协议方向和 capability
语义都做反。

真正的缺口是现有中立模型丢失了四类语义：

1. 权限请求当次实际提供的选项，以及用户精确选中的 option id；
2. 用户提问的 answered / skipped / cancelled 三种结果；
3. “会话模式”与“必选模型”不应被绑定；
4. Plan/Todo 条目的 cancelled 终态。

这些是 domain 数据形状与 Provider-local reducer 的缺口，不是新的调用端口。
当前 Cursor 退役门禁仍然有效；本文不恢复 catalog、factory 或运行时入口。

## 什么情况才新增端口

只有同时满足以下条件，才应在 `AgentProviderBundle` 新增可选端口：

- application/UI 需要主动发起一个有可观测后置条件的操作；
- 该操作无法由现有端口等价表达，也不是已有请求/响应模型少一个字段；
- 至少两类 Provider 协议可以实现同一个业务语义和后置条件；
- 不支持时能自然表达为 capability=false、port=null，误调用抛
  `UnsupportedError`。

入站 notification、协议编解码、pending registry、reducer 状态和厂商扩展路由均不符合
第一条，不得伪装成端口。

## 现有端口复用决策

| Cursor ACP 语义 | 使用的现有契约 | 决策 |
| --- | --- | --- |
| 进程、`initialize`、协议 `authenticate`、生命周期 | `AgentRuntimePort` | 认证是 transport bootstrap，由 runtime adapter 内部完成；不是会话功能端口。 |
| `session/new`、`session/load`、`session/prompt`、`session/cancel` | `AgentConversationPort` | 现有方法与后置条件一致。 |
| load 回放的历史 | `AgentThreadCatalogPort.readThreadHistory` | 只开 `canReadHistory`；不因此伪造 list 能力。 |
| `session/request_permission` | `AgentInteractionPort.respondToPermission` | 端口足够，但 request/decision 模型必须补齐精确选项。 |
| `cursor/ask_question` | `AgentInteractionPort.respondToQuestion` | 问题结构可复用；需补齐三态 disposition。 |
| `cursor/create_plan` | `AgentPlanApprovalPort` | accepted/rejected/cancelled 与现有独立 Plan 审批语义一致。 |
| ACP `configOptions` / legacy modes | `AgentSessionConfigurationPort` | ACP 官方已将 config options 定义为模式、模型、推理档位等 session 配置的通用入口；仓库也已有 mapper 和通用 UI。 |
| `cursor/update_todos` | `AgentPlanUpdatedEvent` | 这是入站通知；Cursor reducer 先处理 merge/replace，再输出完整 typed snapshot。 |
| `cursor/task` | `AgentToolCallEvent` | 这是 subagent 执行证据，映射为 `kind=other` 的工具生命周期；不暴露启动/控制端口。 |
| `cursor/generate_image` | `AgentToolCallEvent` 的摘要/location | 这是生成结果通知，不是 Zeta 发起图像生成。基线只展示经校验的摘要与位置。 |

`sessionConfiguration` 只在真实 session 返回合法 option 并验证 set round-trip 后才有可观测
入口。过期 config id、不受支持的类型或 port 误调用必须失败，不能以“不做任何事”
完成 Future。

## 契约缺口 A：当次权限选项与精确决策（必修）

### 现状风险

`AcpPermissionMapper` 已解析 `optionId` / name / kind，但这些选项停留在 data 层的
`AcpPermissionMapping`，`AgentPermissionRequest` 中没有对应 typed 字段。
`AgentPermissionDecision` 主要只有 approved 布尔值；现有 ACP 响应会先找 allow_once，
找不到时退到任意 allow 甚至第一个 option。这会把“同意一次”错写为“记住同意”，
违反 G5 的不预授权要求。

### 中立模型设计

- 新增 `AgentPermissionRequestOptionKind`：`allowOnce`、`allowAlways`、`rejectOnce`、
  `rejectAlways`、`unknown`。它表示当次请求的选项效果，不是全局权限 policy。
- 新增 `AgentPermissionRequestOption`：`id`、`label`、`kind`、可选 `description`。`id`
  是仅限本请求的不透明回写值，不按名称猜语义。
- `AgentPermissionRequest` 新增有序、不可变的 `options`。
- `AgentPermissionDecision` 新增中立 `selectedOptionId`。对带 options 的请求，
  data adapter 只能回写该请求实际提供的 id；取消 turn 则回写 cancelled outcome。
- 为平滑迁移可暂保留 approved / command decision 兼容字段，但 ACP 路径不得再用
  布尔值启发式选 option。未知、重复、过期或非当次选项一律拒绝。

不复用 `AgentPermissionOption`：它属于 `AgentPermissionPolicyPort` 的主动 session/global
策略目录；本设计是 Provider 已发起单次安全决策后的 request-scoped 选项。

### 为什么是跨 Provider 语义

ACP v1 标准本身要求 Agent 下发可选 option，Client 回写被选中的不透明 id；
Grok 已经使用这一标准路径，Cursor 也官方声明 allow-once / allow-always /
reject-once。Codex 的单次、session 内同意、拒绝和取消决策也具有同样的用户意图。
因此这是安全决策的中立精度，不是 Cursor 特例。

## 契约缺口 B：用户提问的三态结果（必修）

### 现状风险

`AgentQuestionResponse.answers` 的空 map 只能表示 Skip，无法区分“用户主动跳过”
和“用户取消/关闭交互”。Cursor 的阻塞请求明确要求 answered、skipped、cancelled
三种 response；混合会让 Agent 在用户已取消时仍按“跳过并继续”执行。

### 中立模型设计

- 新增 `AgentQuestionResponseDisposition`：`answered`、`skipped`、`cancelled`。
- `AgentQuestionResponse` 新增必选 `disposition` 与可选 `reason`。
- 不变式：answered 需要有效 answers；skipped/cancelled 的 answers 必须为空。
- `AgentInteractionPort.respondToQuestion` 的名称和语义不变；每个 disposition 由
  Provider data mapper 编码为真实协议结果。

ACP 的通用 elicitation 也区分 accept / decline / cancel，要求 Client 提供清晰的拒绝和取消
控件；Cursor 扩展只是已经落地的一个例子。Grok 的结构化提问也能从这一区分中
保留更准确的用户意图。它仍是“提问”，不与权限决策或 Plan 审批合并。

## 契约缺口 C：会话模式不应强制绑定模型（条件必修）

### 现状风险

`AgentConversationModeSelection` 强制要求非空 `effectiveModelId`，控制器也会在没有
模型 id 时拒绝产生回合快照。但 ACP 将 mode 和 model 定义为两个独立的 session
config category，并明确推荐 Client 优先使用 `configOptions`。一个 Provider 完全可以
声明 Agent/Plan/Ask 模式，却不暴露模型目录或模型选择。

### 基线决策

Cursor 首个实现优先把模式当作 `AgentSessionConfigurationPort` 中 category=mode 的动态
option。因此基线不暴露 `conversationModes`，`supportsModeSelection=false`；真实 session
没有返回 mode option 时，UI 不显示模式入口。这条路径不需要新端口。

如果产品要求在第一个 session/回合建立前就选择 Plan/Ask，则先做中立模型修正：

- `AgentConversationModeSelection` 只必选 `modeId`；
- 将当前两个模型字段收敛为可选 `AgentModelSelection modelOverride`，空值表示不覆盖
  Provider 的模型默认值；
- adapter 在自己的串行化 `sendMessage` 边界内先应用模式，得到成功的权威快照后再
  发 prompt。set 失败则 prompt 不得发出；不用 prompt 文本模拟模式。

这项修正同时适用于 ACP 的任意 agent，也适用于“只定义行为/工具策略，不建议
模型”的其他 Provider 预设。它消除了 domain 对 Codex 当前预设形状的偶合，不引入
Cursor 名称或 ACP 字段。

## 契约缺口 D：Plan/Todo cancelled 终态（扩展开启时必修）

`AgentPlanEntryStatus` 目前只有 pending / inProgress / completed / unknown，Cursor 的 Plan 和
Todo 载荷则明确有 cancelled。映射为 unknown 会丢失终态，并可能让 UI 把已取消条目
继续显示为未知/待执行。

- 中立枚举新增 `AgentPlanEntryStatus.cancelled`，规范化常见 cancelled/canceled 值；
- `cursor/update_todos(merge=true)` 不穿透到 Store。Cursor-local reducer 按稳定 todo id 合并，
  然后只输出包含全部条目的 `AgentPlanUpdatedEvent`；merge=false 则替换本地快照；
- live、history、replay 各用独立 reducer 状态，TimelineStore 仍只机械替换 typed snapshot。

取消是任务/计划条目的通用生命周期终态，现有 `AgentToolStatus` 也已有 cancelled；
因此这是中立状态对称性，不是对 Cursor wire value 的特判。

## 明确拒绝的端口方案

| 候选端口 | 不采用原因 | 正确归属 |
| --- | --- | --- |
| `CursorExtensionPort` | 名称和语义都绑定厂商，违反 G1/G6。 | Cursor data adapter 识别扩展方法后输出中立事件。 |
| `AgentTodoPort` | Todo update 是 Provider 推给 Client 的通知，没有可供 UI 调用的操作。 | `AgentPlanUpdatedEvent` + Provider-local snapshot tracker。 |
| `AgentSubagentPort` | Cursor 只通知任务结果，没有声明客户端启动、恢复或取消 subagent 的 RPC。 | `AgentToolCallEvent`。未经证据不暴露控制能力。 |
| `AgentImageGenerationPort` | 目前是结果通知，不是 Zeta 发起的生成操作。 | 工具载荷/location；未来需要预览时优先补中立 typed artifact。 |
| `AgentSessionModePort` | 与现有 `AgentSessionConfigurationPort` 重复，ACP 也正在废弃专用 mode RPC。 | category=mode 的 session config option；旧 mode payload 由共享 ACP mapper 宽容映射。 |
| `AgentAuthenticationPort` | ACP `authenticate` 是连接初始化，不是对话 capability；交互式 login/logout 也不属于 conversation bundle。 | 协议认证在 `AgentRuntimePort.initialize`；若未来做账号动作，在 `agent_management` 设计独立中立契约。 |
| `AgentModelSelectionPort` | Cursor ACP 本轮无稳定模型目录/写回证据，且现有 model catalog、session config 与 runtime 选择已覆盖可观测操作。 | 保持 capability=false 与 port=null；以后有真实证据时复用现有契约。 |

## 实现前契约门禁

- 权限 option 必须从 request 原样保留有序、按当次 request id 绑定，回写不做任何
  allow/reject 猜测；永不默认选择 allow-always。
- 权限、用户提问、Plan 审批保持三套 pending registry 和响应编码；Plan 执行交接
  仍是 Zeta 本地工作流，不调用任何一套 Provider 审批。
- `cursor/task` 的 prompt、`generate_image` 的图像数据/参考路径和所有 raw payload 不进日志、
  持久化或中立事件正文；只输出渲染所需的规范化白名单字段。
- 未知扩展忽略并做脱敏诊断；阻塞扩展如果无法安全响应，必须回写明确取消/错误，
  不能让 turn 永久挂起。
- 真实 fixture 必须确认 `update_todos` / `task` / `generate_image` 到底是不带 id 的
  notification 还是需要 response 的 request。若锁定版本与文档分类不一致，停止实现并
  重回本轮设计；不自动回写 accepted 伪造成功。
- 如果修改 `AgentEvent` 或事件处理语义，实现前另走“新增或修改 AgentEvent”的
  十六问清单，并用测试固定每个答案。
- 任何不暴露的候选能力仍按第一轮结论处理：capability=false、optional port=null、
  底层误调用抛 `UnsupportedError`，不以空结果或 no-op 伪造成功。

## 第三轮的输入

实现计划应以以下优先级排序：

1. P0：精确权限 option 与三态 question response；
2. P0：真实、版本化、脱敏 fixture 固定 identity、replay、终态与扩展响应；
3. P1：开启 todo/plan 扩展时补 cancelled 并在 Provider reducer 内解决 merge；
4. P1：只有要做“首回合前选模式”时，才解除 mode 与 model 的强绑定；
5. 新增 bundle port：无。
