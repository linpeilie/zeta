# Cursor ACP 实现计划

日期：2026-08-12  
阶段：第三轮（按 `developer_guide.md` §7 十二步规划，不写代码）

## 结论与范围

实现顺序必须是：**重新准入决策 → 真实协议证据 → 中立契约修正 →
Cursor-local adapter/reducer → factory/catalog 组合 → 共享层回归 → 三端真机验收**。

保持第二轮决策：不新增 `AgentProviderBundle` 端口。首个版本支持经证据固定的
core session、history/load、prompt/cancel、精确权限选项、结构化提问、Plan 审批、
session config 和官方扩展通知。不支持 list/mutation/fork/steer/model/skill/
permission policy/usage quota；它们保持 capability=false、port=null，底层误调用抛
`UnsupportedError`。

预计不增加第三方依赖：复用现有 stdio JSON-RPC transport、ACP codec、scheduler
和 Dart/Flutter 内建能力。

## 实现前的三个阻塞门

以下是前置门，不计入开发者指南的十二步。任一项未满足都不进入代码实现。

### A. 重新准入与旧数据隔离

- 先做文档级重新准入决策，将权威规则从“所有 Cursor 运行时都退役”改为
  “旧 Cursor 配置仍退役，新 ACP 集成只在版本和 fixture 门禁下准入”。
- 新运行时使用新稳定 Provider ID `cursor_acp`，复用 `AgentProviderKind.cursorAcp`。
  旧 ID `cursor` 及其保存配置继续 fail-closed，不因升级自动恢复、启用或被选中。
- 新内置配置默认 `enabled=false`，只有用户在成功检测后显式启用才入目录。
- `~/.zeta/state/cursor_sessions.json`、旧配置和 Cursor 自有目录不迁移、不删除、不借新
  Provider 重写。历史恢复只走经验证的 ACP `session/load`。
- 同步 `AGENTS.md`、engineering standards、design document、overview 中英文、
  developer guide、glossary 中英文、CONTRIBUTING 中英文和产品/故障排查文档。
  长期协议事实新增 `docs/protocols/cursor_acp_protocol.md`；历史 Cursor 文档仅留指针。

### B. 版本、可执行文件与真实 fixture

- 从 macOS、Windows、Linux 三端真实 CLI 握手得出唯一 `CURSOR_ACP_BASELINE`；
  不从官网发布日期或旧 synthetic fixture 猜版本号。
- locator 优先使用用户显式路径。对通用名称 `agent`，必须用脱敏 `--version`
  输出确认是 Cursor CLI；不得只按 basename 启动。若存在 `cursor-agent` alias，同样以
  真实指纹决定优先级。
- 新 fixture 放在 `test/fixtures/cursor/acp/<cli-version>/`，每份记录脱敏的
  OS/架构、CLI 版本、真实采样 provenance 和 schema 版本。使用 sentinel 替换正文、
  id 与路径；不保留 prompt、回复、凭证、stderr 或用户目录。
- fixture 至少覆盖 initialize/auth、new/load、prompt/update/terminal、cancel、permission、
  ask-question、create-plan、config/mode、todo/task/image，并确认后三者是 notification
  还是需要 response 的 request。
- `test/fixtures/agent_stream_identity/cursor_*_synthetic.json` 只是历史分析材料，禁止当作
  新 Provider 的协议证据或验收 fixture。

### C. 工作目录语义

Cursor 文档同时强调进程启动目录和 `session/new.cwd`。真实 fixture 必须证明
`session/new/load` 中的 cwd 已足以形成正确项目边界与项目 MCP 语义。若必须在启动进程前
传入 workspace，现有无参 `AgentRuntimePort.initialize()` 不足以表达：停止实现、重回
`02-契约缺口.md` 设计 Provider 中立的 launch context，不用全局 cwd、环境变量或延迟
initialize 伪造语义。

## 按开发者指南 §7 的十二步

### 1. 确认 bundle 端口，先落中立契约

以 `01-能力盘点.md` 和 `02-契约缺口.md` 为准，不新增 bundle port。在 Cursor 文件前先
落三项 Provider 中立修正：

- `AgentPermissionRequestOptionKind` / `AgentPermissionRequestOption`、request.options 与
  decision.selectedOptionId；删除 ACP 根据 approved 自动挑 option 的路径；
- `AgentQuestionResponseDisposition` 的 answered/skipped/cancelled 不变式，并更新
  Codex/Grok 现有 mapper 和全部调用点；
- `AgentPlanEntryStatus.cancelled` 与中立 Store/presentation 处理。

首版不做“首回合前选 Plan/Ask”，因此暂不改 mode-model 模型；模式只通过
session config 在 session 建立后展示。更改事件 payload 语义前，先完成 §7 的 AgentEvent
十六问文件，每条对应具体测试。

**测试：** domain 构造不变式、ACP option 顺序/类型映射、Codex/Grok 响应回归、
Plan cancelled 非活动终态，以及 pending interaction Widget 的精确选项、Skip 与 Cancel。

### 2. 定义静态/dynamic capabilities 与 bootstrap policy

新 `cursorAcp` 静态基线只打开：create、prompt、cancel、text、resource、permission、
question、plan approval；后三项只有在 baseline fixture 证明对应标准/阻塞请求时
才打开。todo/task/image 是入站映射，没有 capability 位；只有在 fixture 固定方向
和载荷后才注册对应 decoder。`canResumeSession` 只由 initialize 的 `loadSession=true`
动态开启；`canReadHistory` 还需要 load replay 能产出完整 canonical snapshot，不从 resume
能力自动推导。image 依真实 prompt capability 动态开启。其余 capability 全 false，
`bootstrapPolicy=workspaceScoped`。

`AgentProviderGlobalRuntime` 目前在 initialize 前固定 bundle。使用 Provider 无关 fake 先补一个
契约测试：Provider 握手后开启可选能力时，global runtime 交给调用者的必须是重新
adapt 的 bundle。修正只能重新读中立 capability/port，不得出现 Cursor 分支。

**测试：** `defaultsFor` 保守值、握手省略字段不开能力、method-not-found 收紧而非伪成
网络错误、global/Binding 都能看到握手后端口，旧 `cursor` 即使 kind 相同仍不可用。

### 3. 在 data 层新增 Cursor 实现

新代码放在 Provider 自有目录，例如
`lib/src/features/agent/data/datasources/cursor/`：

- `cursor_acp_agent_provider.dart`：实现必选 `AgentProvider` 与经验证的可选接口；
- `cursor_acp_process_starter.dart` / `cursor_cli_locator.dart`：版本、厂商指纹、三端命令解析；
- `cursor_acp_reducer.dart`：每个 live/history/replay 实例的纯同步叙事状态；
- Provider-specific extension/question/plan mapper 和 todo/file-change tracker。

provider 使用 `JsonRpcStdioTransport`，启动参数只规范化为经验证的 ACP 子命令。
禁止自动添加 `--trust`、`--force`、免审批或网络放行参数；禁止自动 login/update。
initialize 只广告 Zeta 确实实现的 client capability：不广告 fs/terminal/通用
elicitation，可广告已有 UI 支持的 boolean session config。

**测试：** locator 不误认其他 `agent`、参数不重复、cwd/env 值不进日志、缺 CLI/版本
过低时 fail-closed，以及每个未支持的旧必选方法都抛 `UnsupportedError`。

### 4. 把 wire 转成语义完整的中立模型

Cursor mapper/reducer 负责在进入 application 前决定 entryId、message segment、reasoning phase、
tool upsert、dedup、first-terminal-wins 和文件变更完整快照。具体规则只能来自
锁定版本 fixture，不从方法名、显示文本或旧 synthetic id 猜。

映射表：

| Wire | 中立输出 |
| --- | --- |
| standard message/reasoning/tool updates | 现有 message/reasoning/`AgentToolCallEvent` |
| permission request | 带当次有序 options 的 `AgentPermissionRequestedEvent` |
| `cursor/ask_question` | `AgentQuestionRequestedEvent`，三态结果精确回写 |
| `cursor/create_plan` | `AgentPlanApprovalRequestedEvent`，continuation=`providerManaged` |
| `cursor/update_todos` | reducer 先 merge/replace，再输出完整 `AgentPlanUpdatedEvent` |
| `cursor/task` | 只保留 description/type/duration 白名单的 `AgentToolCallEvent` |
| `cursor/generate_image` | 只保留摘要和经校验 location 的 `AgentToolCallEvent` |
| session config/mode snapshot | `AgentSessionConfigUpdatedEvent`；过期 set 失败 |

task prompt、imageData/reference paths、协议 raw、stderr 原文不进事件正文、日志、缓存、
通知或持久化。权限、提问、Plan 审批使用三套 pending registry；任何一类的
重复/过期响应都不能消耗另一类请求。

**测试：** 真实序列的 canonical signature、todo merge/replace/cancelled、权限精确 id 与
allow-always 不默认、question/plan 每个 outcome、未知扩展脱敏忽略、敏感字段哨兵。

### 5. 组装可选能力域，不扩张端口

bundle 只暴露：必选 runtime/conversation，以及经协商的 threadCatalog(read-only)、
interactions、sessionConfiguration、planApproval。`threadCatalog.listThreads`、
`interactions.approveGuardianDeniedAction`、`runtime.updateModelSelection` 等同组未支持方法仍在
provider 内二次校验并抛 `UnsupportedError`。

session 返回 `configOptions` 时使用 `session/set_config_option`；只返回 legacy modes 时使用
`session/set_mode`。每个 session 记录实际协议形状，不按 option id/name 猜路由。

**测试：** capability/port 一致性表；整域不支持时 port=null；分组端口中的支持方法
发真实 RPC、不支持方法抛错；无 config option 时无 UI 入口，不用空成功伪造支持。

### 6. 只复用无状态 ACP 机制，厂商语义留在 Cursor

复用 `AcpSessionUpdateDecoder`、`AcpContentCodec`、`AcpPermissionMapper` 和
`AcpSessionConfigMapper`。共享 ACP 只可补标准字段语法；例如权限 mapper 输出有序 typed
options，但不识别 `cursor/*`、不保存 pending 状态、不决定 entryId。

`TimelineStore`、`CoalescingPolicy`、`Buffer` 不接受 Cursor 分支。Plan cancelled 如果需要调整
Store/UI，先以中立 enum 和 Provider 无关 fixture 落契约，再做通用 switch 分支。

**测试：** 新增 Provider 无关 `acp_permission_mapper_test.dart`；回归 session decoder/content/config
mapper；架构守卫确认共享文件没有 Cursor import/name/kind/id/raw 分支。

### 7. 接入 factory、catalog 和 app 组合

- 保留 decode-only 的旧 `defaultCursor(id=cursor)`；新增 opt-in
  `defaultCursorAcp(id=cursor_acp)`。`CursorRetirementPolicy` 收窄为旧 ID/非准入配置的
  保护策略，factory 只为新 ID 创建 `CursorAcpAgentProvider`。
- 配置 codec 宽容保留旧记录与 active id，不自动写回；新记录由用户启用动作创建。
- 新增 Cursor 的 `AgentDefinition`、CLI locator 与 management repository；自动检测只做版本/
  路径指纹，显式“测试连接”只做 initialize/auth，不发模型 turn。
- Agent 管理页用 Provider 中立的 management surface metadata 控制模型/配置/日志页签；
  Cursor 没有结构化证据的页签隐藏，底层方法抛 `UnsupportedError`。顺手移除当前
  空目录时的 Codex 专属提示文案，不按 Provider id 分支。
  这是 `agent_management` 的中立展示 metadata，不是新 bundle port；现有 Provider 也可用
  同一语义表达各自的管理面差异。
- `IdeHome` 只负责注入 management repository/factory 依赖；其他 UI 只看 bundle capability
  和端口。

**测试：** factory 新 ID 成功/旧 ID 抛错；旧 active Cursor 仍内存回退且文件字节不变；
新 Provider 显式启用后才出现；management detect/test 无 turn；不支持的页签/操作不显示。

### 8. 使用 `ProviderRuntimeJsonRpcPeer` 完成生命周期门控

Cursor provider 不直接持有裸 peer。顺序固定为：start → initialize → 选择实际广告的
`cursor_login` auth method → `markReady`。任一环失败调 `markFailed`；不记录 auth
参数或 stderr 原文。

dispose 顺序是：`beginClosing` → 停止新 RPC → 将三类 pending request 以取消/错误收尾
→ 关闭 scheduler/reducer 资源 → drain in-flight → close peer/event stream。迟到的旧 epoch
响应/事件必须丢弃。

**测试：** initialize single-flight、失败重试策略、ready 前普通 RPC 被拒绝、dispose 幂等、
closing 期只允许 pending response、in-flight drain、旧 runtime scope/epoch 丢弃、进程异常终止。

### 9. Thread 操作经 `ProviderOperationScheduler`

`readThreadHistory` 在 global runtime 上以 Thread `sharedRead` 运行，每次 load 使用独立
replay reducer/context；`resumeSession` 以 Thread `exclusive` 运行。不支持的 list/mutation/
fork/compact 在进 scheduler 前就抛 `UnsupportedError`。

prompt RPC 可持续到 turn 终态，不得用同一 exclusive queue 堵住 cancel；cancel 必须能
直接针对当前 session/turn 发送。`unsubscribeThread` 必须清理 provider 真实拥有的
replay accumulator/subscription，不做空成功的“伪退订”。

**测试：** 同 thread read/read 可并发，read/resume 有序，不同 thread 互不阻塞，cancel 不被
pending prompt 堵住，同 key 重入拒绝，dispose 取消尚未入场任务并等待已入场任务。

### 10. 补齐单元、application 与 Widget 测试

建议新增/扩展的主要测试文件：

| 层 | 测试 |
| --- | --- |
| domain | permission option/decision、question disposition、plan cancelled、Cursor capability/default config |
| shared ACP | `acp_permission_mapper_test.dart`、现有 content/session update/session config mapper 回归 |
| Cursor data | locator、process starter、initialize/auth、session/prompt/cancel、history、extension mapper、reducer、fixture privacy |
| bundle/factory | `agent_provider_bundle_test.dart`、`default_agent_provider_factory_test.dart` |
| application | dynamic global bundle、settings legacy isolation、Binding/runtime registry/scheduler |
| presentation | pending permission options、question Skip/Cancel、Plan 三态、session config、management 页与 provider selector |

特别修正 G4 路径：ViewModel 在 interaction/session-config port 为 null 时不得直接 return。
它必须在移除卡片/更改 UI 前完成 capability + port 校验，误调用抛 `UnsupportedError`；
回写失败时保留或恢复 pending 交互，不伪造已处理。

**测试：** 除成功路径外，每个方法都覆盖 unsupported、timeout、malformed、transport error、
duplicate/late response 和 dispose race；错误类型不得全部降级为 unsupported。

### 11. 使用版本化真实 fixture 做 adapter/reducer 序列回归

每个 fixture 从 raw frame 开始，断言完整 `AgentEvent` canonical signature，至少覆盖：

- 连续 text、reasoning→text、text→tool→text、重复 update、status-only update、终态后迟到数据；
- tool pending/in-progress/completed/failed/cancelled，以及 diff 的完整累计 snapshot；
- permission/question/plan 的请求、解决、turn cancel/dispose 清理与 registry 隔离；
- todo merge/replace、task/image 白名单、未知扩展、session config 权威快照；
- live 与 `session/load` replay 各建 reducer，可回放语义逐位置 canonical signature 相等。

新 Provider 测试只消费新真实 fixture。共享 CoalescingPolicy/Buffer/Pipeline/TimelineStore
回归只消费 Provider 无关 fixture，不 import Cursor 类、不读 Cursor fixture。

**测试：** `cursor_acp_reducer_sequence_test.dart`、
`cursor_acp_history_live_parity_test.dart`、`cursor_acp_fixture_contract_test.dart`，加上全部共享管线回归。

### 12. 覆盖 Binding/runtime 生命周期与多会话隔离

用 Cursor fake provider 扩展 Binding Manager/Runtime Registry 契约测试：

- 创建 workspace entry、打开已有 thread、读历史都不创建 session runtime；首次
  `beginTurn()` 才为该 Binding 创建一个实例；
- 同 Binding 并发 acquire 只有一个实例，两个 thread 有独立进程/reducer/pending registry/
  permission/session config；一个 turn 终止不得结束另一个；
- 覆盖 draft→thread 原子晋升、冲突拒绝、TTL、运行中 turn/RPC 不回收、重叠 sweep、
  ABA identity、dispose/acquire 屏障、配置失效、旧 generation 丢弃与 global 永不回收；
- 旧 `cursor` Binding 不能 acquire，新 `cursor_acp` Binding 才能进入运行时；
- fork capability=false，因此 A→B fork 场景不适用；改为断言 port=null、旧方法抛
  `UnsupportedError`，不用 new/load 伪造 fork。

**测试：** `agent_conversation_binding_manager_test.dart`、
`agent_provider_runtime_registry_test.dart` 和独立 Cursor multi-session contract test；不放宽现有通用断言。

## 验证命令与顺序

开发中先跑定向测试，收尾固定为：

```sh

```

G1 纯度自查：

```sh
grep -rnE "(codex|grok|claude|cursor)" \
  lib/src/features/agent/application/agent_event_pipeline.dart \
  lib/src/features/agent/application/agent_event_coalescing_policy.dart \

  lib/src/features/agent/data/mappers/acp_*.dart \
  | grep -viE "^\S+:[0-9]+:\s*(///|//|\*)"
```

除注释外应无输出。架构测试同时搜索 Store/ViewModel/UI 是否读 raw/extra key、
source id、命令或 patch header 猜语义。

真实 smoke 脚本计划为：

```sh
python tool/smoke_cursor_acp.py --expected-version <CURSOR_ACP_BASELINE>
```

脚本只使用临时最小 workspace、保守权限和非破坏性操作，不打印 prompt、回复、凭证、
raw payload、session/turn id 或 stderr。macOS、Windows、Linux 分别记录 OS/架构、CLI 版本、
核心方法与结果。无设备或凭据时标记“待执行/阻塞”，不写通过。

## 发布验收矩阵

| 验收面 | 放行条件 |
| --- | --- |
| 协议 | baseline 版本的三端 initialize/new/load/prompt/cancel 真机通过；扩展方向已固定 |
| 安全 | 只回写用户选中的 permission option id；无预授权/信任参数；敏感哨兵不落盘 |
| 旧数据 | 无用户动作的升级/启动路径不触发保存，设置文件与 `cursor_sessions.json` 字节不变；显式 opt-in 只新增 `cursor_acp` 配置，旧 `cursor` 对象字段不变且仍不可启动 |
| 能力 | capability、bundle port、UI 入口与底层实现四者一致；未支持项无 no-op |
| 叙事 | Cursor-local reducer 完成 identity/边界/去重/终态；live/history/replay 独立且可比 |
| 并发 | 两 thread/两 Canvas 互不污染，cancel、pending interaction、session config 严格按 scope 隔离 |
| 共享层 | G1 搜索与架构守卫通过；共享测试不依赖 Cursor 类/fixture |
| 产品 | 新 Provider 经显式启用后可创建/恢复会话，管理页不显示伪模型/伪配置入口 |
| 工程 | format/analyze/full test 全过，`CHANGELOG.md` 的 `[未发布]` 和所有架构文档已同步 |

最终结果写入同一任务目录的 `04-验收报告.md`。任一真机平台、安全选项、旧数据
隔离或 G1/G2 门禁未通过，都不将 Cursor 从 preview 提升为活跃 Provider。
