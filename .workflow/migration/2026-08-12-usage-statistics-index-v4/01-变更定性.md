# usage_statistics_index.json v4 · 变更定性

- 日期：2026-08-12
- 目标文件：`~/.zeta/state/usage_statistics_index.json`
- 定性：从 Provider typed 的 v3 `providers.<provider>.sessions` 改为 Provider 不透明的
  v4 `providers.<sourceKey>.{schemaVersion,payload}`，属于结构变更，必须升版本并迁移。

## 已落盘形状

v2 是 Codex-only 顶层会话列表：

```json
{"version":2,"sessions":[{"sourceId":"<fingerprint>","fingerprint":"<stat>","threadId":"<id>","projectPath":"<project>","sourceKind":"codex_cli_rs","createdAt":0,"turns":[]}]}
```

v3 把 Codex/Grok 会话放入固定 Provider 分区：

```json
{"version":3,"providers":{"codex":{"sessions":[]},"grok":{"sessions":[]}}}
```

两版均为可重建派生索引，session 原始路径、正文、原始错误和凭据不在合法结构内。

## 升降级行为

1. 新版本首次读 v2/v3 时只在 data 边界包装为 schemaVersion 1 的不透明分区；首次成功
   写任一分区时整体输出 v4，并保留其它分区。
2. 迁移失败或文件损坏时返回空分区，由各 source 从 CLI 历史重建，不阻断启动，也不写
   完成 marker。
3. 旧版本读到 v4 时按未知版本回退为空索引，不会崩溃；历史源仍可重建。旧版若继续
   写入可能回到 v3，因此降级再升级仍按同一路径幂等迁移。

阶段门结论：结构变化和旧数据入口已明确，可以设计兼容策略。
