# usage_statistics_index.json v4 · 兼容策略

## 版本与迁移边界

- 根版本从 v3 升至 v4；每个 source 分区另带 `schemaVersion`，首版为 1。
- v2/v3 识别集中在 data 层 `LegacyUsageStatisticsIndexDecoder`；domain/application 不认识
  legacy key，也不接收文件路径或 raw payload。
- v2 顶层 `sessions` 映射到 `codex` 分区；v3 `providers` 下每个合法对象按旧统计字段
  白名单包装为 payload。未知旧分区保留 source key 和可识别 session，未知/敏感字段
  丢弃，避免迁移期把旧 raw 或私有路径重新落盘。

## 宽容读取

1. 缺文件、空文件、缺字段或未知根版本：返回空分区集合。
2. 截断 JSON、非法 UTF-8、IO 异常或非法嵌套类型：不抛到上层；整文件或单个损坏分区
   降级为空，其它合法分区继续可用。
3. v2/v3：不解释 Provider 协议语义，只提取可重建统计所需的 session/turn/token 白名单；
   首次分区写回时输出 v4。
4. v4 未知根字段忽略；未知 source 分区完整保留；分区未知 payload 字段由其 Provider
   codec 决定，Store 不擅自删除。

## 幂等与失败

- `writePartition` 在进程内串行执行 read-modify-write，只替换目标 sourceKey；目标文件
  当前内容优先，不用空值覆盖其它分区。
- 同一迁移/写回执行两次得到同一语义结果；不写 migration marker。
- 写入失败向 source 抛出，由 source 转为安全 warning；本次内存结果仍可展示，下次查询
  继续重试。
- Store 只接受 JSON-safe 的规范化 payload；不把不支持的对象转成字符串，避免意外落盘
  路径、异常或 Provider raw。

阶段门结论：四类宽容路径、幂等性和部分失败策略均已确定，可以实现。
