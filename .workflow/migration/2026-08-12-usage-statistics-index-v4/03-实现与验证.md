# usage_statistics_index.json v4 · 实现与验证

## 实现

- 新增 Provider 不透明 `UsageStatisticsPartitionStore`，文件实现用串行临界区完成
  read-modify-write，内存实现保持相同契约。
- 新增 `LegacyUsageStatisticsIndexDecoder`，只在该边界识别 v2/v3；通用 Store 不 import
  Provider snapshot，也不按 Provider kind/id 分支。
- payload 构造时递归冻结并校验 JSON-safe 类型，不把未知对象隐式字符串化。
- 主任务 T08 已完成生产切换，T10 已删除旧 v3 typed Store 与旧 repositories；Zeta
  SharedPreferences 迁移也直接归一并写出 v4。
- T11 新增 Claude Code schemaVersion 1 自有分区；通用 Store 无需增加 Provider 分支，
  codec 安全守卫与增量 fingerprint 命中测试已覆盖，生产注册留待 T12。

## 五项必测

1. v4 往返：`writes and reloads v4 partitions while preserving unknown sources`。
2. 旧版迁移：`migrates the real v2 top-level sessions shape` 与
   `migrates the real v3 provider shape and preserves every partition`；fixture 直接使用现有
   v2/v3 codec 的真实字段形状。
3. 损坏输入：`damaged JSON and damaged partitions degrade without blocking valid data`，并由
   既有 invalid UTF-8 测试覆盖文件编码损坏。
4. 缺/未知字段：同一损坏分区测试覆盖缺 payload、非法 schemaVersion 与未知字段；v4
   往返测试覆盖未知根字段和未知 source。
5. 幂等：`repeating a legacy migration is idempotent` 对同一 v3 文件连续写回两次并比较
   解码后的完整 v4 根对象。

额外覆盖：`parallel partition writes do not drop either source` 固定串行 merge；
`rejects non-JSON-safe payload values instead of stringifying them` 固定白名单边界。
