# 历史分页评估

来源：2026-09-03 会话 UI 改造的 WP-5。状态：跳过，未排期。

原计划希望减少超长会话一次载入的内存成本。后续收尾记录已明确跳过，因此不能把本页视为已批准的实现任务。

重新评估前需要采集长会话的加载时间、内存和滚动数据，区分磁盘解析、时间线存储与可见内容布局的成本。仅凭文件行数或主观卡顿不能决定加入分页。

若证据支持实施，设计必须覆盖：

- live、history、replay 的独立状态，以及分页前后的规范化事件一致性。
- 未加载历史对当前回合、导航锚点、分支位置和待确认交互的影响。
- 翻页、切换会话、关闭与迟到结果的竞态。
- 可复现的前后性能数据，以及现有业务断言回归。

现行结构见[架构总览](../../../docs/zh/architecture/overview.md)。没有确认需求和性能证据前，不预建分页框架。
