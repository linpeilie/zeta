## 结论先行

**建议做。** 但要说清楚定性：这不是等价重构，是**行为变更 + 生命周期重设计**。
`refactor/` 流程的 `06-等价性验收` 这一阶段对本任务不适用——目标态本来就和现状不等价（并发行为、进程数、启动时机全变）。验收要按「新行为的验收用例」写，不是按「行为不变」写。

## 1. 具体痛点

**可验证的一句话：**
> 在同一个 Zeta 进程里开两个 grok 会话并各发一条消息，第二个会话的 turn 静默挂起、prompt RPC 永不返回。

已在 grok 0.2.118 上于 2026-08-04 观测到（见该次 incident 记录）。这是**正确性缺陷**，不是代码整洁度问题——单个 CLI 进程（grok、claude code 同类）在协议层就只维护一个会话，共享它等于把两个会话的 turn 塞进同一条单车道，后到的那条不报错、直接不回。

附带的两条次级痛点（不单独构成重构理由，但会被一起解决）：

- **故障域是整个应用**：CLI 进程崩溃或被外部 kill，所有会话一起死，没有「重启这一个会话」这种粒度。
- **进程生命周期和用户意图对不上**：打开会话即持有进程，用户只是翻看历史也在烧一个常驻 CLI；反过来，长时间不用的会话也不会释放。

---

## 2. 不重构的代价

按「接下来哪些需求会被它拖慢」排序：

| 被拖慢的事 | 具体表现 |
|---|---|
| **多会话并行跑 agent** | 这是三栏工作台的核心卖点。现状下第二个会话必挂，等于功能不存在。 |
| **接入 claude code provider** | claude code 同样是单会话 CLI。不改生命周期就接，上线第一天复现同一个挂起。 |
| **会话级配置**（不同会话不同模型 / 工作目录 / profile） | 现状下切换配置要动全局那一个进程，等于影响所有会话。 |
| **故障恢复动作**（「重连此会话」「重启此会话」） | 没有会话↔实例的绑定关系，这类 UI 动作无处落。 |
| **长时间挂机的资源占用** | 现在是「开着就一直占」，改造后才有回收的抓手。 |
| **所有 provider 侧排查** | 每次排查都要先花时间排除「是不是串话了」这个变量。这个税会一直交下去。 |

| # | 触发条件 | 动作 |

## 4. 范围边界

### 这次做

- Provider 实例的**获取方式**包一层：会话 ↔ 实例的绑定与查找
- **全局实例**：不绑会话、不被回收，只服务用量 / skill / 模型列表这类会话之前的信息
- **懒启动**：新建或打开会话不起实例；用户首次提交输入才初始化
- **空闲回收**：非活跃且上次活跃超过 10 分钟 → 回收该会话的实例（线程安全）
- 回收后再次发送消息 → 自动重建实例

### 这次明确不碰

| 不碰 | 原因 |
|---|---|
| 事件管线 / coalescing / TimelineStore 的任何语义 | 与生命周期正交，动了就分不清是谁引入的回归 |
| 权限、提问、Plan 审批、Plan 执行交接四种语义 | **G5**。尤其：回收/重建**不得**顺手预授权任何操作 |
| 持久化格式 | 会话↔实例绑定只存内存，不落盘。**G8** 不触发 |
| `~/.codex` / `~/.grok` / `~/.cursor` 及项目 `.cursor` | **G7** |
| Cursor 相关路径 | 已退役 |
| 新增 provider（含 claude code） | 这次只保证架构留口，不接入 |
| 跨进程 / 跨 Zeta 实例的 provider 共享（daemon 池） | 明确不做 |
| 进程预热池、预启动等性能优化 | 先把正确性做对，性能另开 `perf/` |
| UI 重设计 | 最多加一个「会话未连接 / 已回收」的状态展示，且仅在必要时 |
| `dart_test.yaml` 并发配置 | 固定为 2，不改 |
| 全局实例的能力清单扩张 | 它只服务现有的全局信息，不借机往里塞东西 |

## 5. 验收用例（进入下一阶段前先钉死）

| ID | 用例 | 期望 |
|---|---|---|
| AC1 | 两个 grok 会话并发各发一条消息 | 两条都正常返回，无静默挂起 |
| AC2 | 新建会话 / 打开已有会话，不输入 | 不产生 provider 实例 |
| AC3 | 首次提交输入 | 此时才初始化实例 |
| AC4 | 会话闲置 > 10 分钟且非活跃 | 实例被回收；再次发送能自动重建并继续 |
| AC5 | 会话正在流式输出 | 永远不会被回收，不论闲置计时器状态 |
| AC6 | 单个会话的实例异常退出 | 只影响该会话，其他会话不受牵连 |
| AC7 | 所有会话实例都被回收后 | 用量 / skill / 模型列表仍可正常获取（全局实例存活） |
