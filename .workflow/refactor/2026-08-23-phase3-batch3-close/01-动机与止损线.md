# 第 3 批关批：动机与止损线

## 痛点

Project Threads 与 Usage Statistics 的生产入口已经只走 MVI 切片，但 Shell 仍保留
三个 ChangeNotifier owner、两个双路径 flag 和整套 usage 旧装配，导致同一业务事实
在代码层仍有两种所有权解释。

## 不做的代价

- 第 4 批继续拆 Shell 时仍要绕过已经退役的 usage 构造与 dispose 分支；
- application 的 Flutter 依赖燃尽清单无法减少两项；
- nullable store 与 false-path 分支会掩盖组合根漏接线，无法 fail-closed。

## 止损线

- 任一既有用户行为断言必须改变；
- Provider wire、能力语义或持久化 schema 必须改变；
- 必须引入第二个 Provider settings owner 才能维持现有测试/嵌入宿主；
- 页面切换造成 AgentPane、当前 Thread、草稿、滚动位置或 Pane 布局重置。

命中任一项就停止删除并恢复对应独立 flag，不把问题扩大到其他批次。

## 范围边界

本次只关第 3 批：删除 3a/3b legacy owner、Shell 旧装配、双路径 flag 与迁移期 UI
分支。保留 Project Threads 的 Provider 查询/写操作 runner、既有 repository、usage
partition store、Provider settings 第 2 批 flag，以及所有 Provider 协议与持久化格式。

用户已于 2026-08-23 明确要求直接进入下一阶段，接受跳过 3a/3b 剩余观察窗口。
