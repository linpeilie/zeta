# 动机与止损线

## 痛点

`IdeShellController` 仍直接构造并持有 `IdeSessionPersistenceCoordinator`，同时持有
Workbench layout 与启动恢复完成态。持久化调度、跨 feature 恢复编排和 UI 投影因此
挤在同一个 ChangeNotifier 中，无法把 Shell 收敛为纯 workflow coordinator。

## 止损线

- 需要修改 `ide_session.json` v4、`IdeSessionState`、codec/store 或白名单字段；
- 需要重写 coordinator 的 restore token、防抖 Timer、恢复期间 latest-wins 队列；
- 需要修改既有测试断言才能通过；
- flag 开启路径与旧路径同时写同一运行态或同一持久化入口；
- 需要翻转 4a/4b 生产 flag、删除回退路径或提前关批。

触及任一项即停止 4b 默认关闭实现，保留 `ideSessionSliceEnabled: false`。

## 范围

本轮只新增 IDE Session 的纯 Dart state/intent/effect/reducer/store、app runner/composition、
稳定 Riverpod 只读镜像和默认关闭双路径接缝。Provider、Binding、Workspace 4a flag、视觉
布局与 root `ZetaStateSnapshot` 不在本次默认关闭提交内；root snapshot 在第 4 批关批时建立。
