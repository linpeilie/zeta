# 现状测绘

## 当前调用链

- `MainApp` 每次构建向 `IdeHome` 注入 `IdeSessionStore`；
- `IdeHome` 创建 `IdeShellController`；
- Shell 构造 `IdeSessionPersistenceCoordinator`，启动时直接 `restore()`；
- Shell 把恢复结果分发给 Workspace、Project Threads、Agent workspace 与 Workbench layout；
- 所有状态变化通过 `_currentSessionState()` 生成 v4 白名单投影，再调用
  `requestSave` / `saveNow`。

## 当前 owner

| 事实 | 当前 owner | 4b flag 开启后的 owner |
| --- | --- | --- |
| restore 运行态/结果状态 | coordinator + Shell 控制流 | `IdeSessionSliceState` |
| 初始恢复 UI 完成态 | Shell 字段 | `IdeSessionSliceState` |
| 冷启动等待 Future | Shell completer | `IdeSessionSliceStore` 兼容等待口 |
| Workbench layout intent | Shell 字段 | `IdeSessionSliceState` |
| debounce/restore token/pending snapshot | coordinator | coordinator，改由 app runner 持有 |
| v4 snapshot | 临时 projection DTO | 临时 projection DTO，不成为运行态 owner |

## 生命周期与调用方

- `MainApp` 创建并释放 session composition；根 `ProviderScope` 始终注入同一个 store，
  不在 rebuild 时增删 override；
- Shell flag 关闭时只持有旧 coordinator，flag 开启时只消费
  `IdeSessionSliceOperations`，不释放 app 所有的 store；
- `IdeHome` 只 watch feature selector，不 watch root snapshot；
- Shell 继续负责把 typed restore result 编排到 Workspace / Project Threads / Agent workspace，
  slice 不复制这些 feature 的业务状态。
