# 动机与止损线

## 痛点

`IdeShellController` 同时持有工作区业务事实、执行文件系统 I/O、编排会话恢复并通知
Workbench；因此迁移或测试一个文件树字段必须同时理解 workspace、ide_session、Agent
workspace 和 Project Threads 四条链。

## 不重构的代价

Phase 3 无法把 Shell 收敛成跨 feature workflow coordinator，也无法建立所有权唯一的
`workspaceByProjectId` 与只读根快照。后续会话恢复、desktop attention 和 conversation
workspace 迁移都会继续依赖 Shell 的可变字段。

## 止损线

- 需要修改 `ide_session.json` v4、任何 codec key 或保存时序；
- 需要递归扫描文件树、跟随符号链接或改变忽略/排序规则；
- 需要修改既有测试断言才能通过；
- 4a 必须同时迁移 session restore lifecycle、Binding 或 conversation entry 才能成立；
- 新旧路径出现双写或需要互相同步。

触及任一项即停止 4a，回退 `workspaceSliceEnabled` 新路径，不把行为变化伪装成重构。

## 范围边界

本轮只执行第 4 批的 4a：工作区内存 owner、文件索引监听纯化、`@mention` 查询 port、
默认关闭 flag 与双路径安全网。4b 的 session persistence slice、生产翻旗、观察和关批
分别后续推进。Provider 协议、AgentEvent、Binding、Project Threads、视觉与路由不动。
