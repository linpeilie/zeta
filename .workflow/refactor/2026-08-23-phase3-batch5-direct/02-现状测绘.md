# 第 5 批直接迁移：现状测绘

## 当前 owner 与调用链

- `DesktopAttentionController` 同时持有未读表、可见性、通知 id、设置订阅，并直接调用
  notification service、indicator 与 target activator。
- `AgentThreadWorkspaceController` 在 agent application 层构造 presentation ViewModel、
  Binding lease 与 Phase 2 slice binding，形成 application→presentation 反向依赖。
- `IdeShellController` 额外持有 project→thread 映射、project home、entry listener 表和
  selected snapshot listener，并负责 entry↔Project Threads 同步。
- `AgentConversationViewModel` 分别构造 mode/model/skills 三个 ChangeNotifier controller；
  composer region 再把它们投影进 conversation slice。
- `AgentRegionBuilder` 仍按 resolver 是否返回 store 在 Riverpod selector 与 ViewModel
  listenable 之间二选一；生产由 `conversationSliceEnabled` 打开。

## 调用方清单

- 组合：`MainApp`、`IdeHome`、`IdeShellController`；
- UI：AgentPane 及其 sections/cards/messages/context/plan panel；
- workflow：项目打开/移除、session restore/save、draft/thread 选择、fork、archive/delete、
  notification activation、Project Threads runtime snapshot；
- conversation：send/cancel、mode、model、skill picker、Plan 交接；
- 根诊断：`ZetaStateSnapshot`；
- 测试：desktop attention、workspace Binding、三个 composer controller、conversation
  slice、Shell controller/Widget、架构与订阅守卫。

## 现有安全网

- desktop attention：可见抑制、去重、resolved、activation、分类开关、本地化与 payload；
- workspace：双 entry 隔离、懒启动、单 entry 失效隔离、跨 Provider 并行；
- Shell：恢复、持久化、project home、fork、通知定位、事件风暴 rebuild；
- composer：mode 竞态、model 保存/回滚、skills stale refresh；
- conversation slice：OperationId、scope、迟到结果、G5 四链路与 dispose；
-真实 `IdeHome`：跨页保活、Pane/Thread/草稿/滚动/宽度可见性。

## 专项结论

- G1/G2/G3：不动共享 pipeline、identity、reducer context；
- G4/G5：capability 与四种审批入口保持现有 typed port；
- G6：workspace runtime composition 移到 app，application 不再 import presentation；
- G7：IDE Session v4 原字段原样保存，未读仍不落盘；根快照不含正文或完整路径；
- Widget：保留 `IdeRetainedPageView`、稳定 entryId 和 AgentPane key；
- 性能：live turn 继续走局部 listenable，不进入 Riverpod slice。
