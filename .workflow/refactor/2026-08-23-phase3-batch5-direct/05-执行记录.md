# 第 5 批直接迁移：执行记录

## Desktop Attention

- 删除 `DesktopAttentionController`，新增纯 `State / Intent / Reducer / Effect / Store`；
- app runner 独占通知服务、任务栏 indicator、设置订阅、payload codec 与 target activation；
- `MainApp` 创建唯一 composition，`IdeHome` 只提交 visibility/attention intent；
- 根状态树新增无路径、无正文的 attention 计数与可见性投影。

## Conversation Workspace

- 删除 feature application 下的 `agent_thread_workspace_controller.dart`；
- app 层 `AgentConversationWorkspaceStore` 统一拥有 runtime entry、选择、project home、
  project→thread 映射与 entry ingress；
- Shell 删除逐 entry listener 表、selected snapshot listener、project home 与 thread map
  重复字段，只保留 Project Threads / IDE Session 的跨 feature 同步；
- Workspace 不可变 state 经纯 reducer 转移，Riverpod adapter 只镜像 store。

## Composer 与 Conversation Slice

- mode/model/skills controller 去掉 Flutter/ChangeNotifier，保留原 generation/revision
  与异步竞态语义；
- 新增 `AgentConversationComposerStateOwner`，ViewModel 构造器必须显式接收且统一释放；
- 每个 workspace entry 必建 `AgentConversationSliceBinding`；
- 根级同步 registry 在 `IdeHome.initState` 绑定，未知 BindingKey 直接抛错；
- 删除 `conversationSliceEnabled`、enabled provider、Notifier resolver、nullable store 与
  `AgentRegionBuilder.legacyListenable`，Widget 只读 selector。

## 偏差与处置

- 实现时发现 draft 首次发送后 BindingKey 会原子晋升为 thread。测试 registry 最初冻结
  旧 key，导致头栏专项测试 fail-closed；改为像生产 Workspace 一样按当前 Binding 身份
  动态解析同一个 store，并新增相关回归。Provider identity 与 entryId 没有改动。
- 首轮受影响全量发现两个 disabled Agent Widget 测试未注入必选 registry。修复测试组合为
  真实 `AgentConversationSliceBinding` 后定向与全量均转绿；生产仍保持未知 key fail-closed，
  没有恢复 fallback。
- 未引入新依赖、持久化字段、Provider wire、审批模型或 UI 文案。
