# 动机与止损线

## 痛点

新增一种 Provider 仍必须修改 core 的封闭 enum/default catalog 和集中式 factory switch，
与“providers 包 + 一行编译期注册”的目标改动面冲突。

## 不做的代价

compatibility 账本无法清零，Provider 扩展继续污染中立 core，Phase 3 第 6 批和 Phase 1
§8.1 都不能关批。

## 止损线

- 必须改变 Provider wire、CLI 参数、capability 内容或持久化 schema；
- 必须让 plugin handle 接管 runtime/Binding 生命周期；
- 无法保持 custom config id 按协议域路由；
- 需要修改 G1 五文件或四种审批模型。

触及任一项就停止并整体回滚，不以 compatibility fallback 掩盖问题。

## 范围边界

只收敛 Provider definition、plugin contribution 与启动组合；不做协议升级、UI redesign、
持久化演进、runtime/state 语义修改，也不提前关闭 Phase 3 第 1、2 批。
