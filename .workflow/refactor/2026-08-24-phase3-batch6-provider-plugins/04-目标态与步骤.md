# 目标态与步骤

## 目标态

- core 只保存开放 `AgentProviderTypeId` 和中立 config/settings；不认识任何内置 Provider。
- 三个 public plugin 各自拥有 definition、capability seed、legacy migrator 与单域 bundle factory。
- app catalog 同步激活三插件并解析一个不可变 definition catalog + type 路由 factory。
- 未激活、degraded、重复域、未知域全部 fail-closed；无 Codex fallback。
- compatibility/default factory 与旧 core catalog 同批删除。

## 执行步骤

| 步骤 | 完成判据 | 回滚点 | 状态 |
| --- | --- | --- | --- |
| 开放 core type-id | enum/内置 identity/default/display switch 从 core 清零，JSON 值不变 | 整体 revert | 已完成 |
| 建三插件与 definition catalog | 三个 essential plugin 各有单域 contribution，重复/未知 fail-closed | 整体 revert | 已完成 |
| 切 app/config/feature 消费 | 生产只从显式 catalog 取 metadata/factory，无旧分支 | 整体 revert | 已完成 |
| 删除 compatibility/default factory | 文件、barrel、构造点和旧断言全仓为零 | 整体 revert | 已完成 |
| 文档与门禁 | Phase 1/3/target docs 同步，format/analyze/full 通过 | 整体 revert | 已完成 |

按用户要求不建立中间可选路径；实现过程可以先建立新类型再一次切调用方，但最终工作树只
保留目标态，任何一步失败都回滚整批而不是恢复双轨。
