## 审查中发现并修复

1. activation/resolve 失败时，已激活 handle 可能失去 owner：改为失败即反序回收，并补
   生命周期回归。
2. Provider ID/type 只靠 debug assert 或允许首尾空白：catalog 改为 release-safe 的
   canonical 校验。
3. 损坏 active ID 会回退 JSON 首项：统一回退插件目录声明的 default definition，避免
   首项自定义配置被意外激活。
4. essential 插件可激活成功却不贡献 Provider：resolve 要求每个 active essential 插件
   恰好一个 typed contribution，拒绝部分目录。
5. 模型目录查询源可能先于 settings 到达：空目录期间返回不可用，不再读取不存在的
   active config。

独立复审结论：无剩余 P1/P2。第 2 批旧 application 对 providers identity 的依赖属于
既有阶段欠债，已列入 Phase 3 阶段级阻塞，不伪装成本批完成项。
