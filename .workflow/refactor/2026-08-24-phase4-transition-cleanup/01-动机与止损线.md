# 01 · 动机与止损线

任务：Phase 4「删除剩余旧路径与过渡层」
重构分型：**R4（结构改造）** —— 跨 feature 重排装配根、改状态广播结构。
范围、批次顺序与关批标准的权威源：[`docs/architecture/phase4_transition_cleanup.md`](../../../docs/architecture/phase4_transition_cleanup.md)。
本文只写止损线与边界，不复制计划书正文。

---

## 1. 痛点（一句可验证的话）

**改一处 Shell 状态要让整个 IdeHome 重建**：`IdeShellController` 继承 `ChangeNotifier`，
20 处 `_notifyStateChanged()` 汇到一个 `notifyListeners()`，`IdeHome` 用 20 处 `setState`
消费；同时 `IdeHome` 自己 `new` 三个 Agent Management Repository，`MainApp` 自己拼
session/config/cache 的构造分支——装配点散在 Widget 里，谁也说不清某个 owner 归谁释放。

三条可验证的现状（测绘数据见 `02-现状测绘.md`）：

- `lib/src/app/shell` 有 1 处 `extends ChangeNotifier` + 20 处 `_notifyStateChanged()`；
- `lib/src/ui` 有 3 处 `Repository(` 构造与 3 条 `features/*/data/` import，全在 `ide_home.dart`；
- presentation 有 2 处直接调用 Repository（`agent_conversation_view_model.dart` 的
  `modelCatalogRepository.record` / `.load`）。

## 2. 不重构的代价

1. **Phase 3 的收益取不到**：MVI slice store 已经是唯一状态 owner，但 UI 仍从 Shell 拿整页
   通知，slice selector 的定向重建优势被顶层 `setState` 抹平。
2. **新 feature 无处安放装配**：现在加一个 feature 只能继续往 `MainApp` / `IdeHome` 的
   构造分支里塞，这两个文件已经 813 / 1396 行。
3. **过渡层会被当成正路径抄**：`ProjectThreadsController → SliceRunnerAdapter → store`
   和 `AgentConversationSliceBinding` 是迁移期接缝，留着就会成为下一个 slice 的模板。
4. **守卫失去意义**：`feature_layering_guard_test` 的三个 known 集合、
   `package_boundary_candidate_graph_test` 的两个 violation 集合当前都是空的，却仍带着
   「只减不增」的燃尽脚手架——空 allowlist 不反转成零容忍，就随时可能被重新填回去。

## 3. 止损线

出现任一情况**立即停止该批并 revert 该批提交**，不硬做：

| # | 触发条件 | 动作 |
|---|---|---|
| S1 | 某个现有测试断言必须修改才能通过（非机械换 wiring / 类型名 / fixture builder） | 停批，revert，记进 `05-执行记录.md`，回到定性 |
| S2 | 为了让某批过关，需要新增 feature flag、双写 owner、compatibility factory 或新的 allowlist 条目 | 停批，revert |
| S3 | 一批内需要同时改动 Conversation 与 Shell 两座高风险桥 | 停批，拆成两批重来 |
| S4 | 需要改动持久化 writer / schema version / wire 参数才能推进 | 停批——那是需求变更，不是重构 |
| S5 | `bash tool/test_full.sh` 在某批收尾时非绿，且原因不能在当批内定位修复 | 停批，revert |
| S6 | 单批 diff 触及 3 个以上 feature 的 data 层 | 停批，重新拆批 |

止损后**不恢复运行时 fallback**：只 revert 版本控制里的该批提交。持久化 writer 与
backward reader 全程不动，所以代码回滚不需要数据降级。

## 4. 范围边界：这次明确不碰

- `AgentEventPipeline`、`CoalescingPolicy`、`Buffer`、`Dispatcher`、`TimelineStore` 的合并语义
  与 entry identity（G1 / G2）；
- reducer 纯度与 live/history/replay 三实例隔离、EffectRunner、Binding lease、runtime
  generation（G3）；
- G5 的四种审批语义与「绝不预授权」；
- Provider capability 协商结果、wire 参数、CLI 基线版本；
- 持久化 schema / version / writer；旧格式 backward reader 与其测试**保留**
  （保留边界清单见计划书 §4）；
- Flutter / Riverpod / shadcn 升级，新增 Package、状态框架、DI 容器；
- 产品行为、UI 视觉、文案与 ARB。
