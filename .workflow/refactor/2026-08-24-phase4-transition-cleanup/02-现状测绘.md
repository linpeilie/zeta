### 3.1 §7.2 零符号检查命令的缺陷（需要修）

计划书 §7.2 的这条命令**当前会输出 322 行**，不是 0：

```sh
rg -n "package:(zeta_foundation|zeta_plugin_kernel|zeta_agent_core|zeta_agent_providers|zeta_ui)/src/" lib packages
```

原因：它同时匹配了**包内自引用**（`zeta_agent_core` 自身 142 行、`zeta_agent_providers`
165 行、`zeta_ui` 10 行、`zeta_foundation` 4 行、`zeta_plugin_kernel` 1 行）。包内引用自己的
`src/` 是合法的，G6 禁止的是**跨包** `/src` 引用，实测为 0。

**P4-6 修正方向**：把该检查改成"每个包只允许引用自己的 `src/`，根 `lib` 一处都不允许"，
或直接以 `package_boundary_candidate_graph_test.dart` 的永久 DAG 守卫为准，
不在文档里维护一条会假红的 shell 命令。

## 4. Zeta 专项检查（重构流程 ② 的五问）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 搬迁后依赖方向会不会反向？（G6） | **有风险，是本阶段的主要收益点**。P4-2 把 `ide_home.dart` 的 3 处 Repository 构造搬进 Workbench composition，方向由 `ui → data` 变成 `app → data`，是**修正**反向依赖而非引入。新建的 composition 必须落在 `lib/src/app/`，不得在 `lib/src/ui` 下建装配类。P4-3a 同理修正 `presentation → Repository`。守卫：`feature_layering_guard_test` + P4-6 新增的 UI/presentation→data 零容忍守卫。 |
| 2 | 涉及的字段名有没有被持久化 codec 当作 JSON key？改名会不会读不出旧数据？（G7） | **待删符号中无持久化字段**。逐个确认：`renderRevision` / `mutedText` / `agentViewModel` / `displayTitle` / `selectServiceTier` 均为运行时内存字段；`codexUsageSourceId` 是路径→id 的纯函数转发，不落盘。`CallbackIdeSessionStore` 删的是**注入方式**，IDE Session 的 JSON 读写实现与字段不动。**红线**：本阶段不得改动任何 codec 的 key 常量；计划书 §4 的 backward reader 全部保留。 |
| 3 | 涉及的 Widget 有没有参与 `IdeHome` 跨页保活或稳定 Key？ | **是，P4-2/P4-5 直接命中**。`ide_home.dart` 是唯一 Workbench 组合边界，20 处 `setState` 改成 slice selector 会改变 rebuild 边界，有破坏 Element 复用的风险。`IdeRetainedPageView`、AgentPane 的稳定 Key 与 pane 宽度状态不得动。这两批必须跑真实 `IdeHome` 的集成级 Widget 测试（清单见 `03-安全网.md` §2）。 |
| 4 | 涉及的 reducer 是不是 live/history/replay 共用算法但必须各自独立实例？（G3） | **不动 reducer**。P4-4 只删 `AgentConversationSliceBinding` 这层 ingress/egress 接缝，reducer 实例的创建点、frame scheduler、EffectRunner、Binding lease 与 runtime generation 全部保持原样。若某批发现必须改 reducer 实例化才能推进 → 触发止损线 S4。 |
| 5 | 有没有把 Provider 专属逻辑上提到共享层的动作？（G1） | **没有**。Phase 4 全部改动在 `lib/src/app`、`lib/src/ui`、feature 的 presentation/application 装配层。唯二触及 `packages/` 的是 P4-1 删 `AgentThreadSummary.displayTitle`（zeta_agent_core domain 的死 getter）与 `kIdeUseAnchoredDynamicSliver` / `buildIdeVirtualSliver`（zeta_ui 虚拟列表死 flag），都是删除，不新增分支。 |
