## 4. Phase 4 守卫策略：为什么 P4-0 不新增守卫

计划书 P4-0 写「新增 Phase 4 守卫时先证明它能命中当前待清理面，再随对应批次反转为
零容忍」。P4-0 执行时发现这两个要求在同一批里**不可同时满足**：

- 一条"能命中当前待清理面"的守卫，在当前 commit 上就是**红的**（因为待清理面非零）；
- 要让它在 P4-0 提交后仍然绿，只能给它配一份写着待删符号的 allowlist；
- 而 P4-0 的关批标准明确禁止「把待删符号加入新的永久 allowlist」，
  §1.3 也禁止新增燃尽脚手架。

**因此 P4-0 不新增任何守卫**，改为固定下面这套**每批自证**的方法，写进本文件作为
后续各批的验收要求：

1. 守卫由**对应批次**编写，与该批的删除动作放在同一提交；
2. 守卫写成**零容忍**（断言计数为 0 / 集合为空），不带 allowlist；
3. 关批前做 **mutation check**：临时把该批删掉的某一个符号加回去，确认守卫变红，
   再撤销临时改动。红了才算守卫真的在保护；
4. mutation check 的结论记进 `05-执行记录.md`（写清 mutate 了哪个符号、哪条守卫变红）；
5. 高风险批（P4-3b / P4-4 / P4-5）的 mutation check 由独立 reviewer 复查（计划书 §6）。

`02-现状测绘.md` 的冻结清单就是这套方法的输入——它替代了"守卫先命中"的作用：
清单里的每个数字都是当前实测值，批次结束时该数字必须归零或按计划下降。

## 5. P4-0 发现的证据链缺陷（**已修复**，2026-08-24）

**`tool/test_full.sh` 的耗时报告在 Windows/git-bash 下读的是旧文件。**

- 脚本用 `repository_root="$(cd ... && pwd)"` 推导路径，git-bash 下得到 MSYS 形式
  `/d/Development/Workspace/zeta`；
- 该路径被原样传给 `flutter test --file-reporter "json:.../full.json"`，
  而 `flutter` 是 Windows 原生程序，无法解析 `/d/...`，**静默不写报告**；
- 随后 `dart run tool/report_test_timings.dart` 仍然成功执行，读到的是
  `.dart_tool/test-results/full.json` 里**上一次成功写入的旧数据**
  （本机该文件停留在 2026-08-17）；
- 后果：脚本 exit code 与"All tests passed"是可信的，但**打印出来的分片耗时、
  最慢用例排名不属于本次运行**。

**根因**（已定位并实证）：MSYS 只对**以 `/` 开头**的参数做自动路径转换。
`dart run tool/report_test_timings.dart "$report_path"` 的参数是裸 `/d/...`，会被转换，
所以它能读到文件；而 `--file-reporter` 的参数是 `json:/d/...`，**不以 `/` 开头**，
不在转换范围内，`flutter` 于是拿到无法解析的路径并静默放弃写报告。

对照实证（同一个测试文件、同一个目标路径）：

| 传参形式 | 报告是否生成 |
|---|---|
| `json:/d/Development/.../probe.json` | ❌ 未生成 |
| `json:D:\Development\...\probe.json`（`cygpath -w` 转换） | ✅ 生成，3646 字节 |

**修复**：`tool/test_full.sh` 与 `tool/test_shard.sh`（同一缺陷）在 `cygpath` 可用时
把报告路径转成原生路径再传给 `flutter test`；`[[ -f ]]` 判断与 `dart run` 仍用 POSIX
路径。`cygpath` 在 Linux/macOS 不存在，`command -v` 判空后行为不变，CI 不受影响。

**验证**：修复后 `bash tool/test_full.sh` 重跑，`full.json` 从 2026-08-17 的旧文件
刷新为本次运行（1.63 MB），门禁 **exit 0**、根测试 2371 + Package 74 与修复前一致。

对 P4-0 的影响：§1 的基线用例数与 exit code 一直可信；分片耗时基线在修复后已可采集，
Phase 4 后续各批可以引用 `tool/test_full.sh` 打印的耗时摘要。
