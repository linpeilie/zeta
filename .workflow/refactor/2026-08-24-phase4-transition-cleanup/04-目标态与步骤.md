## 1. 目标结构

P4-1 不改变任何结构，只**缩小后续批次的改动面**：把「同一语义有两个名字」和
「定义了但没人用」的符号删干净，让 P4-2～P4-5 面对的是单一路径。

## 3. 等价性论证（动手前先证明，不靠跑完再说）

### 3.1 `mutedText` → `textSecondary` 是视觉等价的

已实测两个调色板中两者取值**完全相同**：

- 暗色 `ide_colors.dart:99/101`：`mutedText: neutral[400]` == `textSecondary: neutral[400]`
- 亮色 `ide_colors.dart:138/140`：`mutedText: zinc[600]` == `textSecondary: zinc[600]`

且 `mutedText` **从未被单独覆盖**：全库 4 处 `mutedText:` 赋值全部在 `ide_colors.dart`
内部（两个调色板 + `copyWith` + `lerp`），`IdeColors(` 的 5 个构造点也全在该文件内。
因此 `agent_pane_header.dart` 的 3 处替换不改变任何一个像素。

### 3.2 `renderRevision` → `contentRevision` 是语义等价的

两处别名都已是纯转发：`agent_conversation_timeline_store.dart:1850`
的 `int get renderRevision => _contentRevision;`、`agent_timeline_projection_cache.dart:21`
的 `int get renderRevision => contentRevision;`，快照构造 `:1984` 也是
`renderRevision: _contentRevision`。

唯一有实际分支的是 projection 的兜底：

```dart
final contentRevision = turn.contentRevision != 0
    ? turn.contentRevision
    : turn.renderRevision;
```

由于 `AgentConversationTurnGroup` 的两个字段在唯一构造点被赋同一个 `_contentRevision`，
`contentRevision == 0` 时 `renderRevision` 必然也是 0，兜底分支恒等于
`turn.contentRevision`。**删除兜底不改变结果。**

> ⚠️ 步骤 3 必须先删 ctor 字段再删兜底：只要 `AgentConversationTurnGroup` 还允许
> 外部传入不一致的两个值，上面这条论证就不成立。

### 3.3 re-export 删除由编译器兜底

删掉 `export` 行后，任何依赖传递导出的下游都会**编译失败**，analyze 会逐个点名。
补显式 import 是纯机械操作，不存在"漏改但能跑"的中间态。

## 4. 测试改动的边界（止损线 S1 的具体化）

P4-1 会碰到测试文件，但**只允许**这三类改动，其余一律触发停批：

| 允许 | 例子 |
|---|---|
| 机械改名 | 测试里的 `turn.renderRevision` → `turn.contentRevision` |
| 补显式 import | re-export 删除后下游测试加 `import 'package:zeta_agent_core/...'` |
| 删除只证明被删符号存在的用例 | `appearance_settings_store_test.dart` 里构造 `CallbackAppearanceSettingsStore` 的那条；`app_dependencies_test` 里断言 provider `name` 的那条（若涉及） |

**不允许**：改断言的期望值、放宽 matcher、删除任何证明**行为**（而非符号存在）的用例。
每一条删除的用例都要在 `05-执行记录.md` 里点名，并说明它证明的是符号存在而非行为。

## 8. P4-2a 的关键设计：宿主模式必须显式

### 8.1 为什么不能按计划书字面迁移

计划书 P4-2 写「`MainApp.sessionLoader/sessionSaver` 改为 typed `IdeSessionStore`
或 composition input」。**只做这一步是错的**——这对回调实际承载 4 重副作用
（详见 `03-安全网.md` §7.1），字面迁移会让其中 3 重静默失效，widget test 会开始
写用户真实的 `~/.zeta` 并扫描本机已安装的 CLI。

### 8.2 目标形状（已获用户批准）

```dart
// 现在（隐式推断）
MainApp(sessionLoader: ..., sessionSaver: ...)

// 目标（显式）
MainApp(hostMode: ZetaHostMode.ephemeral, ideSessionStore: MemoryIdeSessionStore(...))
```

`ZetaHostMode` 只有两个取值，语义写死在一处：

| 取值 | 持久化 | 本机 CLI 探测 | 用量自动刷新 |
|---|---|---|---|
| `local` | 文件（`dataPaths`） | 开 | 开 |
| `ephemeral` | 全内存，不碰 `dataPaths` | 关（无安装 stub） | 关（显式注入统计仓储时可恢复） |

`ephemeral` 的三条 must 由 `03` §7.2 的 characterization test 钉住，
其中 4 条断言经 mutation 验证，1 条已如实标记为空断言。
