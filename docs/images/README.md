# 截图拍摄清单

这个目录存放 README 与文档使用的产品截图。下面是待补的清单——按这个规格拍，README 里的插图位已经写好，文件放进来就能显示。

## 通用规格

| 项 | 要求 |
| --- | --- |
| 主题 | 统一用**深色 Graphite Night**（`hero.png` 可另出一张浅色版对照） |
| 窗口尺寸 | 1440 × 900 逻辑像素，HiDPI 屏导出后约 2880 × 1800 |
| 格式 | PNG。超过 1 MB 的用 [oxipng](https://github.com/shssoichiro/oxipng) 或 [ImageOptim](https://imageoptim.com/) 压一下 |
| 缩放 | 保持系统默认，别手动放大字号 |
| 边框 | 直接截整个 Zeta 窗口，不用加外框和阴影 |

## 拍之前先脱敏

截图会长期挂在 README 上，请先准备一个干净环境：

- 用一个**演示仓库**，不要用真实的私有项目；
- 检查左侧项目列表里有没有暴露公司名或客户名的目录；
- 检查窗口标题栏和路径栏里的用户名；
- 使用统计页会显示真实用量，用演示数据或裁掉敏感数字；
- Agent 管理页会显示账号信息，注意遮挡邮箱。

## 清单

### 1. `hero.png` — 三栏工作台全貌 ⭐ 最重要

README 顶部的门面图。要求：

- 三栏都展开：左侧 Projects 有 2–3 个项目和几条会话，中间 Agent 时间线，右侧 Files 展开了一个目录；
- 时间线里能同时看到：一条用户消息、一段 AI 回复、至少一个工具调用卡片；
- 状态最好是「刚完成一个回合」，footer 上有耗时和 token 信息。

一张图要能立刻说清「这是个什么东西」。

### 2. `timeline-tools.png` — 工具调用与回合 diff

时间线局部特写，展示 Zeta 的核心卖点：

- 一个展开的工具调用卡片；
- 一段带语法高亮的代码 diff（增删行的绿红配色要能看出来）；
- 如果有推理过程折叠块，也一并入镜。

### 3. `approval.png` — 权限审批卡片

固定在输入框上方的审批卡：

- 展示一个真实的命令审批请求（比如 `git status` 这类无害命令）；
- 要能看清允许 / 拒绝的选项；
- 关键是让人看到「AI 在等你点头」这个状态。

### 4. `plan.png` — Plan 模式与执行交接

- 一份 AI 产出的行动计划，步骤清晰；
- 底部能看到「执行计划 / 继续规划」的操作栏。

### 5. `usage.png` — 使用统计

- 宽屏双栏布局，图表和表格都在；
- 筛选器（时间 / 项目 / 模型）可见；
- **注意遮挡真实用量数字**，或用演示数据。

### 6. `agent-management.png` — Agent 管理与诊断

- 设置页里的 Agent 详情，显示身份、版本、连接状态；
- 最好是连接测试**通过**的状态；
- **注意遮挡账号邮箱**。

## 可选加分项

- `demo.gif` — 15–25 秒的操作录屏：打开项目 → 发一条请求 → AI 调工具 → 弹出审批 → 你点允许 → 完成。控制在 5 MB 以内，用 [Gifski](https://gif.ski/) 或 `ffmpeg` 压。放在 README 顶部比静态图更有说服力。
- `hero-light.png` — 浅色主题版本，用于主题对比。

## 放进来之后

图片文件名和上面保持一致，直接放在 `docs/images/` 下。README 中英文版的插图位已经写好，会自动引用。这份清单文件本身可以保留（方便以后重拍）或删掉。
