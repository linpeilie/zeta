## 安装与首次启动

### macOS 提示「无法打开，因为无法验证开发者」

安装包没有做代码签名和公证，这是预期提示。两种打开方式：

- 在「访达」中**右键点击**应用 →「打开」→ 在弹窗里再次点「打开」；
- 或到「系统设置 → 隐私与安全性」，找到被拦截的提示，点「仍要打开」。

只需要做一次，之后正常双击即可。

### Windows 弹出 SmartScreen 蓝色提示

同样是未签名导致。点「更多信息」→「仍要运行」。

### Linux 上双击 deb 装完找不到应用

确认桌面环境已刷新应用菜单，或直接在终端执行 `zeta`。如果用的是 tar.gz 免安装版，解压后运行目录内的 `zeta` 可执行文件即可。

### 启动后窗口空白或立刻退出

先看日志目录 `~/.zeta/logs/` 下当天的文件。Zeta 的设计要求启动失败不崩溃，如果真的崩了，这属于缺陷，请带上日志开 Issue。

## Agent 连不上

这是最常见的一类问题。**Zeta 本身不含模型**，它只是驱动你本机已装好的 Agent CLI，所以第一步永远是确认 CLI 自己能跑。

### Agent 面板显示未检测到 CLI

先在终端里验证：

```sh
codex app-server     # Codex
grok --version       # Grok
claude --version     # Claude Code
```

- **命令不存在**：CLI 没装，或者没在 `PATH` 里。注意 Zeta 是图形应用，它读到的 `PATH` 可能和你终端里的不一样——如果你的 CLI 装在 `~/.local/bin` 或通过 nvm/asdf 这类版本管理器安装，图形应用往往看不到。
- **命令存在但 Zeta 还是检测不到**：打开「设置 → Agent 管理」，那里会显示识别到的可执行文件路径、版本和登录状态，能直接告诉你卡在哪一步。

### 「设置 → Agent 管理」里连接测试失败

连接测试只做三件事：查版本、查账号、做协议握手。**它不会发送真实的模型请求，所以不产生任何费用。** 失败时对照提示看是哪一环：

| 现象 | 通常原因 |
| --- | --- |
| 找不到可执行文件 | `PATH` 问题，见上一条 |
| 版本检测失败 | CLI 版本过旧或输出格式变了 |
| 账号未登录 | 在终端里先完成 CLI 的登录流程 |
| 协议握手失败 | CLI 版本与 Zeta 适配的协议不兼容 |

Claude Code 的连接测试只发送无 Prompt 的 initialize control frame，不会创建会话或请求
模型回复。它可能让 Claude CLI 访问网络或维护自身认证/bootstrap 缓存，因此“Zeta 不发送
Prompt”不等于 CLI 对其自有目录绝对零写入。

### 终端里 Claude 能对话，Zeta 却显示未登录

先在与 Zeta 尽量相同的环境中执行：

```sh
claude auth status --json
```

- `loggedIn: false` 是 Claude CLI 给出的明确认证证据；如需 Claude.ai 交互式登录，使用
  `claude auth login`，不要省略中间的 `auth`。
- 命令不存在、JSON 损坏或探测失败时，Zeta 显示“认证证据不可用”，不会再根据
  `.credentials.json` 等文件名猜测已登录/未登录。
- 终端会话可用与 Claude.ai 登录证据并不总是同一件事：API key、第三方 Provider 或不同
  `CLAUDE_CONFIG_DIR` 都可能造成差异。此时点“测试连接”；initialize 成功表示 Zeta 当前
  启动的 CLI/认证路径可用，即使 auth status 仍显示 logged out。
- macOS 图形应用的 `PATH`、环境变量和 Keychain 访问上下文可能与终端不同；Windows 也可能
  因 GUI 环境或安装 shim 不同而出现差异。这不是 macOS 专属登录流程，先核对管理页显示的
  CLI 路径和配置环境。

### Claude 模型列表为空或刷新失败

Zeta 从独立、无 Prompt 的 Claude CLI initialize 响应读取当前有效模型选项。这是 CLI
当前配置下的快照，可能受其 bootstrap/cache 影响，不是 Anthropic 实时远端全量目录。
Zeta 不再调用 `/v1/models`，也没有内置静态 Claude 目录：刷新失败时保留最多 7 天的旧
缓存；首次失败会显示“模型加载失败”。确认 CLI 路径后重试刷新，仍失败时检查
`claude auth status --json` 和“测试连接”。

### Grok 多开会话时状态错乱

Grok CLI 请升级到 **0.2.119 或更高**。这是 Zeta 的多会话兼容基线，更早的版本不支持多会话——同时打开或执行多个 Grok 会话时，会话状态、流式通知和回合终态可能无法正确隔离。

### 输入框不见了，只能看不能发

说明当前会话是只读的。常见于在设置里禁用了 Codex：已有会话仍可翻阅历史，但不再允许创建可写会话。重新启用即可。

### 旧的 Cursor 配置显示 unavailable

预期行为。Cursor 已退役，Zeta 会在内存中回退到任一已启用且未退役的 Provider
（Codex、Grok 或 Claude Code），**不会**自动覆盖你的旧配置，也不会读取或修改任何
Cursor 会话数据。

## 对话与时间线

### 权限或提问卡片没看到就消失了

审批卡片固定在输入框上方，不会被新消息冲走。它消失通常意味着：

- 你已经做出了决定；
- 请求超时；
- 你在别处（比如 CLI 自身）响应了同一个请求；
- Provider 进程退出了。

响应过的请求不会在时间线里重复出现，这是有意设计。

### AI 说要执行命令，但一直没动静

看看是不是在等你审批。Zeta 默认策略保守，**不会自动授权任何命令、文件写入或网络访问**。如果窗口在后台，检查一下系统通知。

### Plan 出来了，点「执行计划」没反应或行为不符预期

执行计划**始终会新建一个普通（Default）回合**，而不是在当前回合里继续。这是刻意的：计划审批和实际执行是两件独立的事，执行不会预授权计划里提到的任何命令或文件操作。如果你想继续改计划，用「继续规划 / 发送修改」。

### 时间线很长时滚动卡顿

时间线是虚拟化渲染的，正常不该卡。如果确实卡了，请带上大致的回合数量和消息规模开 Issue。

## 项目与文件树

### 文件树里少了某些目录

以下目录被有意忽略，避免打开大仓库时卡死：

```
.dart_tool   .git   .idea   .vscode   build   node_modules
```

这个列表目前是固定的，暂不支持自定义。

### 打开大仓库很慢

文件树是**懒加载**的——只在你展开目录时才读取那一层，不会一次性递归扫描。如果打开顶层就很慢，通常是仓库根目录本身条目极多，或者目录在网络盘 / 同步盘上。

### 选中文件后 AI 好像没看到文件内容

这是当前的设计边界：Zeta 只把**项目路径和选中的文件路径**作为上下文传给 Agent，**不会自动读取文件内容**。要不要读、读多少，由 Agent 自己通过工具调用决定——这样你能在时间线里看到它到底读了什么。

## 会话恢复

### 重启后项目从列表里消失了

恢复流程会过滤掉已经不存在的目录。请确认：

- 项目路径还在（没被移动或删除）；
- 应用有权限读取该目录（macOS 上外置磁盘、网络盘或受保护目录可能需要额外授权）。

### 重启后回到了首页，之前的会话还在吗

在。项目下的历史会话可以随时翻出来继续。如果某个会话点开是空的，可能是对应的 Provider 端会话已经不可恢复了。

## 桌面通知

### 任务跑完了但没收到通知

通知**只在你没有正在看那个会话时**才发。以下三个条件同时成立时，Zeta 认为你正盯着它，于是不打扰你：

1. Zeta 窗口处于焦点状态；
2. 当前页面是 Agent 首页（不是设置页或使用统计页）；
3. 当前打开的会话正是产生事件的那个会话。

只要有一条不满足就会发通知。另外检查「设置 → 常规」里的开关：**系统通知**总开关，以及**任务结束**和**需要确认**两个分类开关。

### 系统层面收不到通知

到操作系统的通知设置里确认 Zeta 有权限：

- **macOS**：系统设置 → 通知 → Zeta；
- **Windows**：设置 → 系统 → 通知；
- **Linux**：取决于桌面环境的通知守护进程。

### 通知内容为什么这么简略

有意为之。通知标题只写类别（比如「任务已完成」「需要确认权限」），正文只写「项目目录名 · Agent 会话」。**不会**出现你的 prompt、AI 回复、命令、完整路径、问题原文或错误详情——因为系统通知会进入操作系统的通知中心，那不是放这些内容的地方。

## 使用统计

### 数字和我在 CLI 那边看到的对不上

统计口径是明确的，可能和你的预期不同：

- 一次 turn 算一次调用；
- `completed` 记为成功，`failed` 和 `interrupted` 记为失败；
- **运行中和未知状态不计入成功率分母**；
- 默认统计 CLI、VS Code、`codex exec` 和 Zeta 发起的根会话，**包含已归档会话，排除子 Agent**（避免重复计数）。

Codex、Grok 和 Claude Code 的 Token 统计都来自各自 CLI 的本地历史。完全没有可读取历史时
显示“暂无 Token 历史”；已经存在历史、只是当前时间范围没有调用时显示 0。

### 首字响应时间（TTFT）显示样本数很少

只有 Codex 明确返回了 `time_to_first_token_ms` 的样本才会被采用，缺失的样本不做近似估算。页面上会标明有效样本数。

### 套餐额度显示不全

只展示 Provider 实际返回的字段：套餐类型、百分比窗口、重置时间和可选余额。Zeta **不推算**绝对 Token 总额度或 Provider 没提供的到期日。

Claude 的套餐名称来自上述 initialize metadata，和“额度详情增强”开关无关。五小时、周
窗口与 extra usage 才来自可选 usage API；增强关闭、API key 模式、OAuth scope 不足、token
过期、401/429、超时或断网时，页面会保留套餐名称并显示“额度详情暂不可用”。macOS 优先
读取 Claude Code Keychain 条目、失败后回退 Claude credentials 文件；Windows 使用 Claude
credentials 文件。凭据只在一次只读请求期间留在内存，不写入 Zeta 配置或缓存。

## Zeta 在你电脑上存了什么

全部在 `~/.zeta/` 下（Windows 上是 `%USERPROFILE%\.zeta\`），都是明文 JSON，随时可以打开看或删掉。

```
~/.zeta/
├── config/
│   ├── providers.json                 Agent provider 配置
│   ├── appearance.json                主题与字体设置
│   └── general.json                   发送快捷键、通知开关
├── state/
│   ├── ide_session.json               打开的项目、选中文件、展开状态、会话缓存
│   ├── usage_statistics_index.json    使用统计派生索引
│   ├── migration_marker.json          一次性迁移完成标记
│   └── cursor_sessions.json           退役遗留，运行时不读不写
├── logs/
│   └── zeta-YYYY-MM-DD.log            按天轮转的应用日志
└── cache/
    └── agent_models_v1.json           模型目录缓存，可随时删除
```

**Zeta 会按功能读取活跃 Agent CLI 的私有数据。** 对应 Provider 的 data adapter 可能读取配置、会话历史、日志和账号 metadata，用于连接、历史恢复、诊断与使用统计；原始正文、凭据和私有路径不会复制进 Zeta 的派生索引。读取权限不代表自动迁移、改写或删除；配置写入只发生在用户明确使用配置编辑功能时。Cursor 已退役，其会话数据仍不参与运行时读取或修改。

Claude 的模型探测和连接测试使用 `--no-session-persistence`，Zeta 也不保存 OAuth token；
但 Claude CLI 可能维护其自有认证、bootstrap 或缓存文件，这些不属于 Zeta 的持久化目录。

### 统计索引里有什么

`usage_statistics_index.json` 只保存规范化的白名单字段：会话 ID、回合 ID、时间、项目、模型、状态、时延、Token 数、错误分类。

**不保存** prompt、AI 回复正文、工具输出、原始错误文本、会话文件路径、环境变量、凭证或 Provider 原始数据。这个文件可重建，删掉只会丢失历史统计。

### 日志里有什么

日志按天轮转，记录应用级诊断信息。写入前会做脱敏处理：认证头、`Bearer` token、`sk-` 开头的密钥、`api_key` / `token` / `secret` / `password` 这类键值都会被打码，你的用户主目录路径会被替换成 `~`。

但**日志仍可能包含项目路径和文件名**，所以在 Issue 里贴日志前请自己再扫一眼。

日志目前**不会自动清理**，需要手动删除旧文件。

## 清理与重置

按影响范围从小到大：

| 想做什么 | 删除 |
| --- | --- |
| 清掉模型目录缓存 | `~/.zeta/cache/` |
| 清掉历史统计 | `~/.zeta/state/usage_statistics_index.json` |
| 忘掉打开过的项目和会话缓存 | `~/.zeta/state/ide_session.json` |
| 重置外观和常规设置 | `~/.zeta/config/appearance.json`、`general.json` |
| 清掉日志 | `~/.zeta/logs/` 下的文件 |
| **完全恢复出厂** | 整个 `~/.zeta/` 目录 |

删除后重启 Zeta，缺失的文件会以默认值重建。**这些操作不会影响你的代码，也不会影响 Agent CLI 自己的配置和会话历史。**

## 还是没解决

开 Issue 时请带上：

- 操作系统与版本；
- Zeta 版本（关于页面或安装包文件名）；
- Agent CLI 与版本（`codex --version` / `grok --version`）；
- 复现步骤；
- 脱敏后的相关日志。

安全漏洞请不要开公开 Issue，改用 GitHub 的私密上报（Security → Report a vulnerability）。
