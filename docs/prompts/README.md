# 提示词库

给 Zeta 日常开发用的 AI 提示词模板。目标是**少打字、不漏门禁、产出可预期**。

这些模板都假设 AI 已经读过 [`AGENTS.md`](../../AGENTS.md)，所以只用门禁编号（G1–G9）和文档章节名引用约束，不重复正文。如果 AI 明显没读，在提示词最前面加一句「先读 AGENTS.md」。

## 三档复杂度

**先判档，再选模板。** 判据是「改动触及什么」，不是「你觉得要写多少行」。

| 档 | 判据（满足全部） | 动手方式 |
|---|---|---|
| **S** 小改 | 单层内改动 · 不改任何 domain 契约 · 不命中 G1–G5 / G7 / G8 | 直接做 |
| **M** 中改 | 跨 2–3 层 · 新增或修改 domain 字段/方法 · 不动共享层、Provider 端口、持久化格式 | 先列改动清单，确认后做 |
| **L** 大改 | 命中下面**任意一条** | 必须先出方案，禁止直接写代码 |

**L 档触发条件**（任一即是 L）：

- 新增或修改 `AgentEvent`（→ 必答 [开发者文档 §7](../guides/developer_guide.md) 的 16 问）
- 新增 Provider，或新增 / 修改 `AgentProviderBundle` 端口
- 改动共享适配层（G1 列出的那批文件）
- 改持久化格式、字段语义或迁移逻辑
- 改权限 / 提问 / Plan 审批 / Plan 执行交接的语义（G5）
- 跨 feature 的结构调整，或新建 feature

拿不准就当 L 处理。方案阶段成本很低，返工成本很高。

## 文档清单

| 文档 | 用途 |
|---|---|
| [`daily.md`](daily.md) | **日常任务模板**：新增功能 / 需求变更 / Bug 修复 / 重构，各 3 档 |
| [`workflow.md`](workflow.md) | **功能开发流程**：需求分析 → 方案设计 → 任务拆解 → 实现 → 验收，含 Provider 接入和 AgentEvent 接入两个专项流程 |
| [`refactoring.md`](refactoring.md) | **重构开发流程**：动机 → 测绘 → 安全网 → 目标态 → 执行 → 等价性验收，含重构分型与陷阱表 |
| [`snippets.md`](snippets.md) | **可拼接片段**：约束尾缀、定位尾缀、测试尾缀、输出格式约定。用来给基础模板补上下文 |

**两套流程不通用。** 功能开发证明「新行为出现了」，重构证明「行为一点没变」——验收方式相反，阶段顺序也不同（重构的安全网必须前置）。分不清手上这件事属于哪种时，看一个判据：**做完之后，现有测试的断言需不需要改？** 需要改就是功能开发，不需要就是重构。

## 使用约定

- `<尖括号>` 是占位符，替换后删掉尖括号。
- 模板可以叠加 [`snippets.md`](snippets.md) 的片段。基础模板管「做什么」，片段管「注意什么」。
- 模板是起点不是枷锁。任务不符合任何一档时，直接说清楚上下文和验收标准，比硬套模板有效。
- **不要在提示词里粘贴未脱敏的日志。** `~/.zeta/logs/` 可能含项目路径和文件名。
