# 连接 AI 助手

Zeta 说的「Agent」，指你电脑上装的命令行 AI 编码助手。Zeta 不含模型，它做的是把这些助手接进图形界面，并把它们的行为摊开给你看。

## 当前支持三个

| 助手 | 出品方 | 命令 | 配置文件 |
| --- | --- | --- | --- |
| Codex | OpenAI | `codex` | `~/.codex/config.toml` |
| Grok | xAI | `grok` | `~/.grok/config.toml` |
| Claude Code | Anthropic | `claude` | `~/.claude/settings.json` |

Zeta 不会修改这些文件，除非你在 Zeta 的配置编辑器里主动保存。

> Cursor 曾经在支持列表里，现已退役。Zeta 不会启动 Cursor，也不读写 `~/.cursor` 下的任何内容。

## 各自支持到什么程度

不同助手能做的事不一样。Zeta 的做法是：**助手做不到的功能，界面上直接不出现**，而不是给你一个点了报错的按钮。所以你在某个助手下看不到某个按钮，通常不是 bug。

| 你能做的事 | Codex | Grok | Claude Code |
| --- | :---: | :---: | :---: |
| 新建会话 | ✓ | ✓ | ✓ |
| 继续历史会话 | ✓ | ✓ | ✓ |
| 浏览历史会话列表 | ✓ | ✓ | ✓ |
| 取消正在跑的回合 | ✓ | ✓ | ✓ |
| 回合执行中继续补话 | ✓ | — | — |
| 重命名会话 | ✓ | ✓ | — |
| 归档 / 取消归档会话 | ✓ | — | — |
| 分叉会话 | ✓ | — | — |
| 删除会话 | ✓ | ✓ | — |
| 从 Zeta 列表移除会话 | — | — | ✓ |
| 压缩上下文（`/compact`） | ✓ | — | ✓ |
| 用 `@` 引用文件 | ✓ | ✓ | — |
| 用 `$` 插入 Skill | ✓ | ✓ | — |
| 附加图片 | ✓ | — | — |
| 权限审批 | ✓ | ✓ | ✓ |
| AI 提问 | ✓ | ✓ | ✓ |
| 计划模式（只读规划，不改文件） | ✓ | ✓ | ✓ |
| 用 `/` 菜单进入计划模式 | ✓ | ✓ | —&nbsp;¹ |
| 「接受计划」审批卡片 | —&nbsp;² | ✓ | ✓ |
| 选择模型 | ✓ | ✓ | ✓ |
| 调节思考程度 | ✓ | ✓ | ✓ |
| Fast 档位 | ✓ | — | — |
| 用量与额度统计 | ✓ | ✓ | ✓ |

¹ Claude Code 改在权限模式里选 Plan，效果一样。

上表是保守下限。连上之后 Zeta 还会根据助手实际报告的版本和能力做调整——比如「在指定历史回合处分叉」需要 Codex 0.144.5 或更高，达不到就不会出现这个入口；对话模式列表也是连上之后才由助手报告的。

## Agent 管理页

「设置 → Agent 管理」是所有助手相关问题的排查入口。

左边是助手列表，可以在「已安装」和「全部支持」之间切换，也可以按名称或厂商搜索。点「自动检测 Agent」重新扫描一遍本机环境。

列表里每一行显示这个助手的账号状态、版本和运行状态，右侧是启用开关。禁用一个助手会停掉它当前的任务，已有会话变成只读——Zeta 会先提示你再执行。

点进某个助手，详情页分三个标签页。

### 基础信息

- **基本属性**：名称、厂商、通信方式。
- **版本**：当前装的版本，以及能查到的最新版本。
- **路径与命令**：Zeta 实际用来启动它的可执行文件路径和完整命令行。可以复制命令，也可以直接打开所在目录。
- **诊断**：最近一次检测的结果，逐项列出可执行文件是否存在、认证证据、连接是否正常、握手结果、协商到的能力、兼容性判断。出问题时这里会写明是哪一步失败的，以及建议怎么办。

页面顶部有三个按钮：**测试连接**、**查看运行日志**、**禁用 Agent**。

### 模型

列出这个助手当前可用的模型，标明数据来源和更新时间。加载失败时会提示原因——最常见的是没登录。

### 配置

直接在 Zeta 里编辑助手的配置文件。

- 默认以只读方式显示，敏感值（密钥、token 一类）会被遮挡。点「显示敏感值」才能编辑完整内容。
- 保存前会校验格式；格式不对不会写出去。
- 保存时会先备份原文件。
- 如果文件在你编辑期间被外部程序改过，Zeta 会拦下来问你要不要覆盖，而不是默默盖掉。
- 出于安全考虑，Zeta 拒绝写入符号链接指向的配置文件。

Codex 的配置保存后需要重启 Codex 才会生效，界面上会提示。

## 检测流程

自动检测会依次走这几步，任何一步失败都会明确告诉你卡在哪：

1. **文件检测**——在系统 PATH 里找可执行文件
2. **进程启动**——尝试启动它
3. **版本检测**——读出当前版本号
4. **账号认证**——检查登录状态
5. **协议握手**——和它对上话，确认双方能互相理解
6. **配置读取**——读配置文件状态

最常见的失败是第一步。Zeta 是图形应用，它看到的 PATH 可能和你终端里的不一样——如果你的助手装在 `~/.local/bin`，或者通过 nvm、asdf 这类版本管理器安装，图形应用往往找不到。

## 测试连接

详情页的「测试连接」做一次完整的往返：启动进程、握手、读回身份和能力，然后立刻断开。

**它不会发送任何提示词，不调用模型，因此不产生费用。** 测试完成后会显示耗时和协商结果。

对 Claude Code 来说，这个测试发送的是一个不带提示词的初始化请求。需要说明的是：Claude 命令行工具自己可能借此机会访问网络或更新它自己的缓存和认证状态，这部分不在 Zeta 的控制范围内。

## 运行日志

「查看运行日志」打开助手自己的运行日志，可以按级别筛选、按关键词搜索。「复制日志」复制出来的内容已经**打过码**——认证头、token、密钥这类值会被替换成圆点。

即便如此，日志里仍可能包含项目路径和文件名。往公开 Issue 里贴之前，请自己再扫一眼。

## Claude Code 的额度详情开关

Claude Code 详情页上有一个「额度详情增强」开关，默认开启，可手动关闭。

打开它，Zeta 会使用有效的 Claude Code 登录凭据调用用量查询接口，显示五小时窗口、周窗口和补充额度这些细项。

关闭它不影响基本使用：模型列表和套餐名称始终来自 Claude 命令行工具本身，和这个开关无关。

无论开关状态如何，获取 Claude Provider 和发起新请求前都会校验凭据，并在到期前 5 分钟内按需刷新。刷新只更新原有 Claude 凭据存储，不在 Zeta 配置、缓存或日志中保存副本。刷新失败时本次操作会停止；需要时请重新运行 `claude auth login`。

## 版本要求

| 助手 | 要求 | 说明 |
| --- | --- | --- |
| Codex | 0.142.5 或更高 | 低于此版本会标注「版本过旧」并停止发送消息 |
| Grok | 0.2.119 或更高 | 更早版本无法隔离多个并发会话 |
| Claude Code | 建议 2.1.22x 或更高 | 当前验证过的版本区间 |

版本比 Zeta 验证过的更新时，界面会标注「版本较新，尚未完整验证」——功能通常可用，只是没有经过完整验证。

## 常见问题

**终端里能用，Zeta 说没装。** 见上面「检测流程」里关于 PATH 的说明，以及[故障排查](troubleshooting.md#agent-连不上)。

**终端里能聊天，Zeta 说未登录。** 有些助手的「命令行可用」和「账号已登录」不是同一件事——用 API key、第三方接口或不同的配置目录都可能造成差异。这种情况下点「测试连接」，如果通过，说明 Zeta 当前使用的这条路径是可用的。

**看不到某个按钮。** 先查上面的能力对照表。这通常是该助手不支持，不是故障。
