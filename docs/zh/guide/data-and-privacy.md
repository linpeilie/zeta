# 数据与隐私

一句话：**Zeta 不上传你的代码，没有账号系统，也不做遥测。** 这篇文档把细节说清楚——它在你电脑上写了哪些文件、读了哪些别人的文件、以及怎么全部清掉。

## 你的代码不出本机

Zeta 是一个本地应用，不带服务端。它做的事是启动你电脑上已经装好的 AI 命令行工具，把消息传过去，把结果显示出来。

- Zeta 交给 AI 助手的是**项目目录路径**和**你在文件树里选中的文件路径**，不是文件内容。
- 要不要读文件、读哪些，由 AI 助手自己通过工具调用决定——它读了什么你在时间线上看得到。
- 消息本身当然会发给 AI 助手，再由它发给对应的模型服务。这条链路是助手自己的，和你在终端里直接用它时完全一样。
- Zeta 自己不发送任何统计、崩溃报告或使用数据。

## Zeta 在你电脑上写的文件

全部集中在**系统「文档」目录下的 `.zeta` 文件夹**里：

| 系统 | 路径 |
| --- | --- |
| macOS | `~/Documents/.zeta/` |
| Windows | `%USERPROFILE%\Documents\.zeta\` |
| Linux | `~/Documents/.zeta/`（若设置了 `XDG_DOCUMENTS_DIR` 则以它为准） |

里面都是明文 JSON 和纯文本，随时可以打开看或者删掉：

```
.zeta/
├── config/
│   ├── providers.json              每个助手的启用状态、程序路径、选中的模型与权限模式
│   ├── appearance.json             主题、字体、字号
│   └── general.json                发送快捷键、通知开关、界面语言
├── state/
│   ├── ide_session.json            打开过的项目、当前项目、文件树展开状态、选中文件、会话列表缓存
│   ├── usage_statistics_index.json 使用统计的汇总索引，可重建
│   └── session/<助手>/             每次发起对话时记录的设置（用了哪个模型、什么思考程度、什么时间）
├── logs/
│   └── zeta-YYYY-MM-DD.log         按天分文件的应用日志
└── cache/
    └── agent_models_v1.json        模型列表缓存，可随时删除
```

如果这个目录因为权限问题创建不了，Zeta 不会崩，而是退回到只在内存里保存状态——这次运行的设置和会话记录不会写进磁盘，关掉就没了。

## Zeta 会读哪些别人的文件

为了完成它的工作，Zeta 需要读取 AI 助手自己的目录（比如 `~/.codex`、`~/.grok`、`~/.claude`），用途是：

- **连接和恢复会话**——读取助手的配置和会话历史
- **诊断**——读取助手的运行日志，显示在「查看运行日志」里
- **使用统计**——扫描助手的历史记录，汇总成统计页上的数字
- **账号状态**——判断你有没有登录

关于写入，规则很明确：**Zeta 只在你主动使用配置编辑器并点击保存时，才会写入助手的配置文件**，而且写之前先备份原文件。除此之外不迁移、不改写、不删除助手的任何数据。

## 统计索引里有什么

`usage_statistics_index.json` 只保存一份固定的字段清单：

| 存了 | 没存 |
| --- | --- |
| 会话 ID、回合 ID | 你的提示词 |
| 开始时间、耗时 | AI 的回复正文 |
| 项目路径、模型名 | 工具调用的输出 |
| 状态、Token 数 | 原始错误文本 |
| 错误分类 | 助手的会话文件路径、环境变量、任何凭据 |

这个文件是可以重建的。删掉它只会让下次打开统计页慢一点，不会丢失任何真实数据——真实数据在助手自己的历史文件里。

## 日志里有什么

日志按天写成单独文件，记录应用级别的诊断信息（哪个操作失败了、进程什么时候退出了）。

写入前会自动打码这些内容：

- `Authorization` / `Proxy-Authorization` 头的值
- `Bearer` 开头的 token
- `sk-` 开头的密钥
- 键名是 `api_key`、`token`、`secret`、`password`、`private_key` 的值
- 你的用户主目录路径，会被替换成 `~`

**但日志里仍然可能包含项目路径和文件名。** 往公开 Issue 里贴日志之前，请自己再扫一眼。

日志目前不会自动清理，需要你手动删除旧文件。

## 凭据

Zeta 不把登录凭据保存到自己的配置、缓存或日志中。

使用 Claude Code 时，Zeta 会在获取实例和发起新请求前检查凭据，到期前 5 分钟内按需刷新。刷新只更新原有 Claude 存储：macOS 的 Keychain 条目，或 Windows/Linux 的凭据文件（macOS 原先使用文件时仍更新该文件），不迁移来源或另建备份。刷新或写回失败会阻止本次操作；取消和审批回写仍可继续。

「额度详情增强」开关单独控制用量查询，关闭它不会关闭上述认证检查与刷新。详见[连接 AI 助手](agents.md#claude-code-的额度详情开关)。

## 通知里有什么

系统通知会进入操作系统的通知中心，所以内容刻意做得很简略：标题只有类别（「任务已完成」「需要确认权限」），正文只有项目目录名。不会出现提示词、回复、命令或错误详情。

## 清理与重置

按影响范围从小到大：

| 想做什么 | 删除 |
| --- | --- |
| 清掉模型列表缓存 | `cache/` |
| 清掉历史统计 | `state/usage_statistics_index.json` |
| 清掉 Zeta 记录的对话设置 | `state/session/` |
| 忘掉打开过的项目和会话缓存 | `state/ide_session.json` |
| 重置外观和常规设置 | `config/appearance.json`、`config/general.json` |
| 重置助手配置（启用状态、模型选择） | `config/providers.json` |
| 清掉日志 | `logs/` 里的文件 |
| 完全恢复出厂 | 整个 `.zeta/` 目录 |

删完重启 Zeta，缺失的文件会以默认值重建。

**这些操作不会影响你的代码，也不会影响 AI 助手自己的配置和会话历史。** 想清理后者，去它们各自的目录里操作。

## 报告安全问题

发现安全漏洞请不要开公开 Issue。用 GitHub 的私密上报通道（仓库页面 → Security → Report a vulnerability），详见[安全策略](../../../SECURITY.md)。
