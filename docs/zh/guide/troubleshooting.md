# 故障排查

按遇到的现象检查。仍不能解决时，按文末说明报告问题。

## 安装与启动

**系统阻止首次打开。** 当前安装包没有开发者签名。确认下载来源后，按系统给出的打开选项处理。无法验证开发者、文件已损坏和安全软件报警是不同情况；后两者请重新下载并核对校验文件，保留提示内容用于报告。

**Linux 安装后找不到应用。** 刷新应用菜单，或运行解压目录中的 `zeta`。

**窗口空白或立即退出。** 记录系统版本、Zeta 版本和发生步骤。若已生成日志，查看[数据目录](data-and-privacy.md#zeta-自己保存什么)中 `logs` 下当天的文件。

**设置重启后丢失。** 检查文档目录是否可写、磁盘是否有剩余空间，以及清理工具是否删除了 `.zeta`。不要在 Zeta 运行时移动或删除该目录。

## 助手连接

**显示未检测到。** 先确认助手已安装并能独立运行。安装后完全退出 Zeta 再打开，随后执行「设置 → Agent 管理 → 自动检测 Agent」。仍找不到时，核对检测页显示的程序位置；多版本安装也可能造成差异。

需要确认安装版本时，可在终端运行对应命令：

```sh
codex --version
grok --version
claude --version
```

只需运行你使用的助手那一行。

**显示未登录或连接失败。** 在助手自身完成登录，再测试连接。若终端能用、Zeta 不能用，核对两者是否使用同一程序、账号和设置。按检测页提示检查[版本要求](agents.md#版本要求)。

**模型列表为空。** 检查登录和连接后刷新。保留的旧列表不代表已成功连接，界面会标明读取状态。

**Claude Code 提示登录续期失败。** 在 Claude Code 中重新登录，再重试。关闭「额度详情增强」不能解决登录失效。

## 对话与文件

**输入框不可用。** 检查该会话使用的助手是否已禁用，或当前是否正在执行不允许发送消息的操作。

**任务没有继续。** 先看输入框上方是否有权限或提问卡片。若没有，查看最近的错误或等待提示。

**确认计划后没有开始。** 查看是否还需要确认执行权限，或计划仍在修改中。参见[审批与计划](approvals.md)。

**取消后文件仍有改动。** 取消只停止后续工作，不撤销已经完成的修改。创建对话分支也不会恢复文件。请从备份或版本管理工具恢复需要的内容。

**选中文件后助手没读内容。** 选中只提供文件位置。请在消息中明确要求助手查看文件，并检查它报告的操作。

**记录滚动卡顿。** 报告大致对话长度、是否包含大图片或长代码块，以及调整窗口大小时是否更明显。

## 项目与历史

**文件列表少了一些目录。** `.git`、`.dart_tool`、`.idea`、`.vscode`、`build` 和 `node_modules` 不显示，当前不能自定义这份列表。

**项目从列表消失。** 检查文件夹是否被移动、删除，外接磁盘是否已连接，以及 Zeta 是否有读取权限。可以重新打开项目。

**历史会话打不开。** 确认使用的是原来的助手和账号，以及助手自己的历史文件是否仍存在。Zeta 的列表缓存不能恢复已经删除的完整历史。

## 通知

检查「设置 → 常规 → 通知」、系统对 Zeta 的通知权限和勿扰模式。正在查看对应会话时不会重复提醒。

点击通知无法打开时，尝试重新打开项目。会话已经删除的通知不能恢复该会话。

## 使用统计

**数字对不上。** 检查时间、助手、模型和项目筛选。统计可能包含从终端发起的任务；取消的任务计入已结束总数，但不计为成功。

**提示部分数据不可用。** 当前只展示能读取的历史，结果可能不完整。缺失的响应时间不参与平均值，缺失的额度不能当作零。

**没有使用记录。** 放宽时间范围，选择全部助手后刷新。若历史已被助手清理，Zeta 无法重建这些记录。

## 报告问题

通过 [Issues](https://github.com/linpeilie/zeta/issues/new/choose) 提供系统和版本、Zeta 版本、助手名称和版本、重现步骤及看到的结果。

只附相关日志片段，先遮挡账号、私人路径、密钥和对话内容。安全漏洞请使用[安全策略](../../../SECURITY.md)所述的私密方式。
