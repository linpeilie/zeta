## 安装与首次启动

### macOS 提示「无法打开，因为无法验证开发者」

安装包没有做代码签名，这是预期提示。两种打开方式：

- 在访达里**右键点击** Zeta，选「打开」，在弹窗里再点一次「打开」；
- 或到「系统设置 → 隐私与安全性」，找到被拦截的提示，点「仍要打开」。

只需要做一次。

### Windows 弹出 SmartScreen 蓝色提示

同样是未签名导致。点「更多信息」，再点「仍要运行」。

### Linux 上装完 deb 找不到应用

刷新一下桌面环境的应用菜单，或者直接在终端执行 `zeta`。用 tar.gz 免安装版的话，解压后运行目录里的 `zeta` 可执行文件。

### 启动后窗口空白，或者立刻退出

看一眼日志目录里当天的文件（路径见[数据与隐私](data-and-privacy.md#zeta-在你电脑上写的文件)）。Zeta 的设计要求启动失败也不崩溃，如果真的崩了，这是缺陷，请带上日志开 Issue。

### 设置改了但没保存下来

如果 Zeta 无法创建自己的数据目录（权限不足、磁盘满、文档目录被重定向到不可写的位置），它会退回到只在内存里保存状态。表现就是每次重启都回到默认值。检查文档目录是否可写。

## Agent 连不上

这是最常见的一类问题。Zeta 本身不含模型，它驱动的是你本机装好的 AI 命令行工具，**所以第一步永远是确认那个工具自己能跑**。

### 界面显示未检测到

先在终端里验证：

```sh
codex --version     # Codex
grok --version      # Grok
claude --version    # Claude Code
```

- **命令不存在**：没装，或者不在系统 PATH 里。
- **命令能跑，Zeta 还是找不到**：这是最典型的情况。Zeta 是图形应用，它读到的 PATH 和你终端里的往往不一样——如果工具装在 `~/.local/bin`，或者通过 nvm、asdf、volta 这类版本管理器安装，图形应用通常看不到。

  一个可行的办法是把工具所在目录加进系统级的 PATH（而不是只加在 shell 的启动脚本里），然后完全退出 Zeta 再重开。

打开「设置 → Agent 管理」，详情页的「诊断」会显示 Zeta 走到哪一步失败了，比自己猜要快。

### 连接测试失败

连接测试只做三件事：查版本、查登录状态、建立一次连接。**它不发送提示词，不调用模型，不产生费用。**

失败时对照提示看是哪一环：

| 现象 | 通常原因 |
| --- | --- |
| 找不到可执行文件 | PATH 问题，见上一条 |
| 版本检测失败 | 版本过旧，或者它的输出格式变了 |
| 账号未登录 | 先在终端里完成登录 |
| 协议握手失败（双方对不上话） | 版本和 Zeta 支持的范围不兼容，见[版本要求](agents.md#版本要求) |

### 终端里能聊天，Zeta 却说未登录

「命令行能用」和「账号已登录」不总是同一件事。用 API key、第三方接口，或者指定了不同的配置目录，都可能造成差异。

以 Claude Code 为例，可以在和 Zeta 尽量相同的环境下执行 `claude auth status --json` 看看它自己怎么说。如果它报告未登录但你确实能用，直接点 Zeta 的「测试连接」——测试通过就说明 Zeta 当前走的这条路径是可用的。

macOS 上图形应用的环境变量和钥匙串访问上下文与终端不同，Windows 上也可能因为安装方式不同而有差异。先核对管理页显示的程序路径对不对。

### 模型列表是空的

模型列表来自 AI 助手自己报告的内容。列表为空通常意味着没登录，或者连接没建立起来。先在详情页做一次连接测试。

刷新失败时 Zeta 会保留之前缓存的列表（最多 7 天），并在界面上说明这是缓存。

### Grok 同时开几个会话时状态串了

升级 Grok 到 **0.2.119 或更高**。更早的版本不支持多会话，同时打开或执行多个 Grok 会话时，状态无法正确隔离。

### 输入框不见了，只能看不能发

这条会话是只读的，因为它所属的 AI 助手在设置里被禁用了。到「设置 → Agent 管理」重新启用即可，历史消息一直都在。

## 对话与时间线

### 权限卡片没看到就消失了

审批卡片固定在输入框上方，不会被新消息挤走。它消失通常意味着：

- 你已经做出了决定；
- 请求超时了；
- 你在别处（比如助手自己的命令行界面）回应了同一个请求；
- 助手进程退出了。

响应过的请求不会重复出现，这是有意设计。

### AI 说要执行命令，但一直没动静

看看是不是在等你审批。Zeta 默认不会自动授权任何命令、文件写入或网络访问。如果 Zeta 窗口在后台，检查一下系统通知。

### 接受了计划，但它没有直接开始干

这是正常的。接受计划之后还有一步执行确认，问你用什么权限执行。确认之后 Zeta 会**新开一个回合**来执行——所以执行过程中该问的权限还是会一条条问。详见[审批、提问与计划](approvals.md#执行确认)。

### 分叉之后文件没有回到之前的样子

分叉只影响对话记录，不碰你的文件。AI 之前写进磁盘的改动仍然在那儿。要撤销文件改动，用你自己的版本控制工具。

### 时间线很长时滚动卡顿

对话再长也不该卡。如果确实卡了，请带上大致的回合数量开 Issue。

## 项目与文件树

### 文件树里少了某些目录

以下目录被有意跳过，避免打开大仓库时刷屏。这个列表目前是固定的，暂不支持自定义：

```
.dart_tool   .git   .idea   .vscode   build   node_modules
```

### 打开大仓库很慢

文件树是按需加载的——只在你展开目录时才读那一层，不会一次性递归扫描。如果连打开顶层都很慢，通常是仓库根目录本身条目极多，或者目录在网络盘、同步盘上。

### 选中文件后，AI 好像没看到内容

这是设计边界。Zeta 只把**项目路径和选中的文件路径**交给 AI，不会自动读取文件内容。要不要读、读多少由 AI 自己决定——这样你能在时间线上看到它到底读了什么。

## 会话恢复

### 重启后项目从列表里消失了

恢复时会过滤掉已经不存在的目录。请确认：

- 项目路径还在，没被移动或删除；
- 应用有权限读取该目录（macOS 上外置磁盘、网络盘或受保护目录可能需要额外授权）。

### 重启后回到了首页，之前的会话还在吗

在。展开对应项目就能看到历史会话，点进去继续。如果某条会话点开是空的，可能是 AI 助手那边的会话已经不可恢复了。

## 桌面通知

### 任务跑完了但没收到通知

通知只在你**没有正在看那个会话**时才发。以下三个条件同时成立时，Zeta 认为你就在盯着它，于是不打扰：

1. Zeta 窗口处于焦点状态；
2. 当前是对话工作台（不是设置页或统计页）；
3. 当前打开的正是产生事件的那个会话。

只要有一条不满足就会发通知。另外检查「设置 → 常规 → 通知」里的三个开关。

### 系统层面收不到通知

到操作系统的通知设置里确认 Zeta 有权限：

- **macOS**：系统设置 → 通知 → Zeta
- **Windows**：设置 → 系统 → 通知
- **Linux**：取决于桌面环境的通知服务

### 点通知打不开会话

如果那条会话已经被删除，或者不在当前的项目列表里，Zeta 会明确提示打不开。重新打开对应的项目通常就能找回来。

### 通知内容为什么这么简略

有意为之。系统通知会进入操作系统的通知中心，Zeta 不往那里放你的提示词、AI 回复、命令或错误详情。见[数据与隐私](data-and-privacy.md#通知里有什么)。

## 使用统计

### 数字和我在别处看到的对不上

统计口径是明确的，可能和你的预期不同：

- 一个**回合**算一次调用；
- 成功率的分母只包含已经结束的调用（完成 / 失败 / 已取消），**正在运行和状态未知的不计入**；
- 只有「完成」算成功；
- 统计读的是 AI 助手自己的本地历史，所以**包含你在终端里直接使用它们产生的调用**，不只是在 Zeta 里发起的。

### 平均响应时间的样本数很少

只有助手明确报告了首字响应时间的调用才会被计入，缺失的样本不做估算。页面上会标明有效样本数。

### 套餐额度显示不全

Zeta 只展示助手实际返回的字段，不推算它没提供的信息。读不出来时会保留能读到的部分（比如套餐名称），其余显示「暂时无法读取」，而不是显示成 0。

Claude Code 的五小时窗口、周窗口和补充额度需要打开「额度详情增强」开关才会读取。关掉这个开关不影响套餐名称的显示。

### 提示「部分数据不可用」

统计依赖扫描本地历史文件，偶尔会遇到读不动的文件或损坏的行。Zeta 会跳过这些，展示其余数据，并在页面上说明缺了什么。这不影响其他数字的正确性。

### 显示「暂无使用记录」

如果你确实用过，检查两件事：时间范围筛选是不是选窄了，以及 Agent 筛选是不是选了一个你没用过的助手。

## 还是没解决

开 Issue 时请带上：

- 操作系统和版本
- Zeta 版本（安装包文件名里有）
- AI 助手的名称和版本
- 复现步骤
- 相关日志（贴之前先扫一眼里面有没有你不想公开的路径）

安全漏洞请不要开公开 Issue，改用 GitHub 的私密上报（仓库页面 → Security → Report a vulnerability）。
