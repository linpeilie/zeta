# Zeta 窗口横向缩放性能优化改造方案

> 版本：v1.0  
> 日期：2026-07-24  
> 状态：可执行方案，待实施  
> 适用基线：`flutter` 分支，提交 `ed32ca14`  
> 目标平台：Windows 为首要验收平台，macOS / Linux 保持行为一致  
> 核心原则：只布局当前可见内容，只在数据变化时计算数据，只在布局语义变化时重建 UI

## 1. 文档定位

本文用于解决 Zeta 桌面窗口横向缩放时的持续掉帧问题，重点覆盖以下内容：

1. 当前问题的现象和触发条件。
2. 从 Windows `WM_SIZE` 到 Agent 时间线布局的完整调用链。
3. 造成卡顿的直接原因和放大因素。
4. 可独立提交、可测试、可回滚的分阶段解决方案。
5. 每个阶段的代码落点、状态保留策略、测试方案和性能验收标准。

本文不直接修改业务协议、Provider、会话历史格式或持久化结构。所有优化都应保持
现有消息顺序、Markdown 表现、diff 内容、Composer 草稿、滚动位置和页面切换行为。

## 2. 执行摘要

### 2.1 核心结论

窗口最右侧外边框本身不是性能瓶颈。Windows Runner 只是在每次 `WM_SIZE` 时调整
Flutter 子窗口尺寸；真正的瓶颈发生在 Flutter 收到新约束之后：

```text
Windows 连续发送 WM_SIZE
    ↓
Flutter View 宽度每次变化 1px
    ↓
IdeWorkbenchScaffold / AgentPane 的 LayoutBuilder 收到新约束
    ↓
所有保留在 IndexedStack 中的页面和 AgentPane 参与布局
    ↓
SingleChildScrollView + Column 布局全部已加载 turn
    ↓
Markdown、代码块、diff、SelectableText 重新按宽度排版
    ↓
turn grouping、unified diff 解析和 Footer 测量进一步放大耗时
    ↓
UI 线程超过单帧预算，窗口拖动出现明显卡顿
```

### 2.2 根因优先级

| 优先级 | 问题 | 性能影响 | 主要特征 |
|---|---|---:|---|
| P0 | Agent 时间线没有虚拟化 | 极高 | 历史越长越卡 |
| P0 | 多层 `IndexedStack` 让隐藏会话继续布局 | 极高 | 打开的会话越多越卡 |
| P0 | `AgentPane.LayoutBuilder` 在每个像素变化时重建对话子树 | 极高 | 横向拖动持续触发 |
| P1 | turn grouping、diff 解析在 build 阶段重复执行 | 高 | 编辑、工具调用较多时加重 |
| P1 | Footer 使用 post-frame 测量和 `setState` 反馈 | 中高 | Composer 换行或宽度变化时加重 |
| P1 | Workbench 跨断点更换 Row key | 中高 | 约 1180px 附近出现一次明显停顿 |
| P2 | 代码高亮在 Widget build 中重新解析 | 中 | 展开 diff / 代码块较多时加重 |
| 非根因 | 原生窗口边框、磁盘 I/O、窗口 resize 监听 | 低 | 当前不存在额外 resize 持久化 |

### 2.3 目标改造路径

```text
第一阶段：阻断无意义重建
    ├── Workbench 基础 Row 使用稳定 key
    └── AgentPane 只在布局档位变化时重建结构

第二阶段：隐藏页面退出布局
    ├── 用惰性 PageView 替换会话级 IndexedStack
    └── 用相同机制替换页面级 IndexedStack

第三阶段：时间线虚拟化
    ├── SingleChildScrollView + Column → CustomScrollView + SliverList
    ├── 按稳定 id 扁平化 timeline item
    └── 只构建视口及少量缓存区内的内容

第四阶段：缓存派生计算
    ├── turn revision + render projection cache
    ├── unified diff 解析缓存
    └── HighlightView 结果缓存

第五阶段：删除布局反馈环
    └── 单次布局内计算 Footer、Timeline 和浮动计划面板的位置
```

## 3. 问题描述与复现条件

### 3.1 用户可见现象

典型现象包括：

- 拖动窗口最右侧外边框改变宽度时，边框明显跟不上鼠标。
- 横向缩放比纵向缩放更卡。
- 会话内容越多、打开的 Agent 会话越多，卡顿越严重。
- 打开右侧 Files / Tools Inspector 后，卡顿进一步加重。
- 在工作台由 Wide 切换到 Medium 的宽度附近，会出现一次更明显的停顿。
- Debug 模式下更容易复现，但 Profile / Release 模式仍存在结构性开销。

### 3.2 推荐复现步骤

性能基线统一使用以下场景：

1. Windows x64，系统缩放分别验证 100% 和 150%。
2. 使用 Profile 模式启动：

   ```sh
   flutter run -d windows --profile
   ```

3. 打开一个项目，并保留至少 6 个 Agent 会话。
4. 每个会话至少包含：
   - 3 个已加载历史 turn；
   - 多段普通 Markdown；
   - 至少 1 个代码块；
   - 至少 1 组文件编辑或 unified diff。
5. 在以下状态分别横向拖动窗口：
   - 只打开左侧 Projects Pane；
   - 同时打开左侧 Pane 和右侧 Inspector；
   - 当前会话位于时间线顶部、中部和底部；
   - Composer 有草稿和无草稿。
6. 在 1280px、约 1180px 和 1000px 附近来回拖动。

### 3.3 为什么默认窗口也容易触发

默认窗口宽度为 1280px。只打开默认左侧 Pane 时，中央 Canvas 约为：

```text
1280
- WindowFrame 内容边距 16
- 左右 Activity Rail 与间距 88
- 左侧 Pane 与分隔条 288
= 888px
```

Agent 正文最大宽度为 920px，因此默认 Canvas 仍小于正文最大宽度。窗口每变化 1px，
正文宽度也会变化 1px，所有可参与布局的文本都可能重新换行。

打开右侧 Inspector 后：

```text
888 - 右侧 Pane 与分隔条 288 = 600px
```

此时中央内容还会接近或跨越 640px 的 Agent 紧凑布局断点，布局变化更频繁。

## 4. 当前实现链路

### 4.1 原生窗口层

相关文件：

- `windows/runner/win32_window.cpp`
- `windows/runner/flutter_window.cpp`
- `lib/src/app/window_bootstrap.dart`

Windows Runner 在收到 `WM_SIZE` 后调用 `MoveWindow` 调整 Flutter 子窗口。项目没有：

- `didChangeMetrics` 中的同步 I/O；
- `onWindowResize` / `onWindowResized` 监听；
- resize 期间的配置保存；
- resize 期间的 Provider 或历史数据读取；
- 自定义毛玻璃、透明窗口或持续截图。

因此不应通过节流 `WM_SIZE`、延迟 `MoveWindow` 或修改平台 Runner 来掩盖问题。
这样会造成内容与窗口边框不同步，且无法解决 Flutter 内部布局开销。

### 4.2 Workbench 层

相关文件：

- `lib/src/ui/core/workbench/ide_workbench_scaffold.dart`
- `lib/src/ui/features/ide/views/ide_home.dart`

`IdeWorkbenchScaffold` 使用 `LayoutBuilder` 解析 Wide / Medium / Compact 模式。每次
窗口宽度变化都会重新计算：

- 左右 Pane 是否内联；
- Canvas 剩余宽度；
- 左右 Activity Rail；
- Overlay 宽度和位置。

基础 Row 当前使用：

```dart
ValueKey('workbench-base-${mode.name}')
```

模式变化会替换整棵 Row Element，导致 Canvas 子树被卸载并重新挂载。

### 4.3 页面与会话保留层

`IdeHome` 当前存在两层 `IndexedStack`：

1. 页面级：Agent、Settings、Usage Statistics。
2. 会话级：Project Home 和所有 `AgentPane`。

`IndexedStack` 能保留 State，但会布局全部 child。`TickerMode` 只暂停动画 ticker，
不会阻止 build、layout 或文本排版。

因此“保留草稿、滚动位置和面板状态”的实现方式，同时让所有隐藏会话承担 resize
成本。

### 4.4 AgentPane 响应式层

`AgentPane` 内部的 `LayoutBuilder` 主要使用宽度判断：

- `< 640px` 使用紧凑页面 padding；
- `>= 640px` 使用普通页面 padding。

但当前 builder 在约束每变化 1px 时都会返回一棵新的 `Column`、Timeline、Footer
和 Composer Widget 树。即使布局档位没有变化，所有 StatelessWidget 和
ListenableBuilder 仍会因父级更新而重新 build。

### 4.5 时间线层

当前时间线是：

```dart
SingleChildScrollView(
  child: Column(
    children: [
      historyTurns,
      liveTurn,
    ],
  ),
)
```

该结构没有视口虚拟化。所有已加载历史 turn、当前 live turn、Markdown 文档、
命令卡和文件编辑卡都会参与布局。

普通 Markdown 又配置了：

```dart
MarkdownWidget(
  useColumn: true,
  selectable: true,
)
```

当前锁定的 `mixin_markdown_widget 0.3.1` 会在 `useColumn: true` 时为文档全部 block
创建 Widget。外层时间线和内层 Markdown 都是完整 Column，形成双重非惰性结构。

### 4.6 build 阶段派生计算

`_AgentTurnSection.build` 每次都会调用 `buildAgentTimelineRenderBlocks`。该函数会：

- 遍历 turn 的全部 entry；
- 对命令和文件编辑重新分组；
- 创建新的不可修改列表和 render block；
- 解析回合级 unified diff；
- 重新统计增删行；
- 为文件路径创建新的展示对象。

这些结果只依赖 turn 数据，不依赖窗口宽度，不应在 resize build 中重复计算。

### 4.7 Footer 测量反馈

`_AgentConversationLayout` 当前在 build 时安排 post-frame callback，通过
`GlobalKey` 查找 Footer 的 `RenderBox`，读取高度后再 `setState`。

同时 `SizeChangedLayoutNotifier` 会在 Footer 尺寸变化时继续安排测量。横向 resize
必然改变 Footer 宽度；当 Composer、提示或选择器发生换行时，高度也会改变，形成：

```text
layout → post-frame measure → setState → next layout
```

这不是第一主因，但会增加每帧调度和 Element 查找成本。

## 5. 改造目标与非目标

### 5.1 功能目标

- 横向缩放期间只布局当前活动页面和当前活动 Agent 会话。
- 时间线只构建视口和有限 cache extent 内的项目。
- resize 不再触发 turn grouping、diff 解析和代码高亮解析。
- 跨响应式断点时保持 AgentPane State、草稿和滚动位置。
- Footer 高度在同一次 layout 中解决，不产生 post-frame `setState`。
- 保持现有 UI、Markdown、diff、选择复制和流式更新行为。

### 5.2 性能目标

在第 3.2 节固定场景下，以同一机器、同一 Profile 构建比较：

| 指标 | 完成标准 |
|---|---|
| 隐藏 AgentPane resize build/layout 次数 | 0 |
| 时间线已构建 item 数 | 与视口相关，不随全部历史长度线性增长 |
| resize 期间 turn projection 次数 | 数据不变时为 0 |
| resize 期间 unified diff 解析次数 | 数据不变时为 0 |
| UI 线程 p95 frame time | 小于 16.7ms，或至少比基线下降 60% |
| Raster 线程 p95 frame time | 小于 16.7ms |
| 连续 10 秒 resize 丢帧率 | 小于 5% |
| 1180px 附近模式切换 | 不卸载当前 AgentPane，不丢失状态 |

绝对帧预算受测试机器影响。若绝对值无法稳定达到，应同时满足“相同场景相对基线
下降至少 60%”和结构性计数目标。

### 5.3 非目标

- 不修改 Codex app-server、ACP、JSONL 或 Provider 协议。
- 不修改 `AgentConversationTimelineStore` 的事件 identity 和 merge 规则。
- 不把 Provider 原始 payload 暴露给 UI。
- 不改变历史分页每页 3 个 turn 的业务规则。
- 不通过降低窗口刷新率、冻结画面或 resize 结束后才重绘来规避问题。
- 不引入新的状态管理框架。
- 主路径优先使用 Flutter 内建组件，不新增运行时依赖。

## 6. 目标架构

```text
IdeHome
├── Stable IdeWorkbenchScaffold
│   ├── Navigation / Inspector / Rail
│   └── RetainedPageViewport（只布局活动页面）
│       └── AgentWorkspaceViewport（只布局活动会话）
│           └── AgentPane
│               ├── Breakpoint-aware layout shell
│               ├── AgentTimelineProjectionController
│               │   ├── turn revision cache
│               │   └── stable viewport items
│               ├── CustomScrollView
│               │   └── SliverList.builder
│               ├── Active plan overlay
│               └── Composer / pending interaction footer
```

依赖方向保持为：

```text
presentation viewport / projection
    ↓ 消费
application view model / neutral timeline state
    ↓ 消费
domain model
```

Timeline Store 继续只负责规范化状态和事件合并；虚拟化、展开态、可视项目和高亮缓存
留在 presentation 层。

### 7.2 阶段 1：保持 Workbench Canvas 稳定

### 问题

基础 Row 的 key 包含 `mode.name`。Wide / Medium / Compact 切换时，Flutter 会替换
整个 Row Element，Canvas 下的 AgentPane 也随之被卸载。

### 修改文件

- `lib/src/ui/core/workbench/ide_workbench_scaffold.dart`
- `test/src/ui/core/ide_workbench_scaffold_test.dart`
- `test/src/app/ide_shell_widget_test.dart`

### 实现方案

1. 将基础 Row key 改为稳定 key：

   ```dart
   const ValueKey('workbench-base')
   ```

2. 为所有直接 slot 增加稳定 key，避免条件 child 插入或删除时发生位置误匹配：

   - leading rail slot；
   - navigation slot；
   - navigation separator；
   - canvas slot；
   - inspector separator；
   - inspector slot；
   - trailing rail slot。

3. Canvas 的 KeyedSubtree 必须始终处于同一基础 Row 中，不因 Inspector 转为 Overlay
   而改变父级。
4. 不在 mode 切换时创建新的 Canvas GlobalKey。
5. Navigation / Inspector 从 inline 转为 overlay 时，优先保留其 controller 状态；
   不要求在不同父级间强行复用 RenderObject。

### 验证

新增断点切换测试：

1. 在 Agent Composer 输入草稿。
2. 设置时间线滚动位置。
3. 将测试窗口从 Wide 调整为 Medium，再恢复 Wide。
4. 验证：
   - `AgentPaneState` identity 不变；
   - 草稿不变；
   - ScrollController offset 不变；
   - Inspector 可见性规则不变；
   - 不出现 Duplicate GlobalKey。

### 风险

MultiChildRenderObjectElement 对混合 keyed / unkeyed child 的匹配容易产生误移动，因此
必须给所有 Workbench 直接 slot 加 key，不能只修改 Row 自身。

### 7.3 阶段 2：只在布局档位变化时重建 AgentPane

### 问题

`AgentPane.LayoutBuilder` 的业务决策只有 Compact / Regular 两种，但 builder 会在
宽度每变化 1px 时重建完整对话子树。

### 修改文件

建议新增：

- `lib/src/ui/core/layout/ide_constraint_bucket_builder.dart`
- `test/src/ui/core/ide_constraint_bucket_builder_test.dart`

修改：

- `lib/src/features/agent/presentation/agent_pane.dart`
- `lib/src/features/agent/presentation/widgets/agent_pane_sections.dart`
- `test/src/features/agent/presentation/agent_pane_pr3_test.dart`

### 目标组件

新增一个按约束派生离散 key 的布局组件：

```dart
class IdeConstraintBucketBuilder<T> extends StatefulWidget {
  const IdeConstraintBucketBuilder({
    required this.selectBucket,
    required this.builder,
    super.key,
  });

  final T Function(BoxConstraints constraints) selectBucket;
  final Widget Function(BuildContext context, T bucket) builder;
}
```

内部仍使用 `LayoutBuilder`，但保存上次的 bucket 和 child：

```dart
builder: (context, constraints) {
  final nextBucket = widget.selectBucket(constraints);
  if (nextBucket == _bucket && _child != null) {
    return _child!;
  }
  _bucket = nextBucket;
  return _child = widget.builder(context, nextBucket);
}
```

要求：

- 父 Widget 配置变化时在 `didUpdateWidget` 中失效缓存。
- 主题、文字缩放等 InheritedWidget 变化仍能使 child 正常重建。
- 纯约束变化且 bucket 不变时返回同一个 Widget identity。
- 不在 layout builder 中调用 `setState`。

### AgentPane bucket

```dart
enum _AgentPaneWidthClass { compact, regular }
```

宽度判断继续使用 `IdeMetrics.stackedRowBreakpoint`。`panelHeight` 不放进顶层 bucket，
否则纵向尺寸的小变化会使整棵对话树失去缓存。

`_AgentPendingInteractionSection` 所需的 `panelHeight` 下沉到它自己的局部
`LayoutBuilder`，只重建 pending dock，而不是整个 Timeline 和 Composer。

### 预期效果

- 1280 → 1000 的连续拖动中，只要 Agent Canvas 没跨过 640px，AgentPane 结构 build
  次数应为 0。
- Text RenderObject 仍需响应真实宽度布局，但不再重复：
  - 创建全部 Widget；
  - timeline grouping；
  - MarkdownDocumentView block build；
  - HighlightView 语法解析。

### 测试

1. 连续 pump 100 个不同宽度，但不跨 breakpoint：
   - bucket builder 调用 1 次；
   - child State identity 不变。
2. 跨 breakpoint：
   - builder 仅增加 1 次；
   - Composer controller 和 ScrollController 不丢失。
3. 修改主题或文字缩放：
   - child 能正确更新，不能被约束缓存阻断。

### 7.4 阶段 3：让非活动页面退出布局

### 问题

两层 `IndexedStack` 会布局全部保留页面。简单替换成条件 child 会丢失：

- Composer 草稿；
- 附件和 mention 草稿；
- 时间线滚动位置；
- 输入焦点；
- 展开 / 折叠状态；
- Settings 和 Usage 页面局部状态。

`Offstage` 和 `Visibility(maintainState: true)` 仍会布局 child，不满足目标。

### 修改文件

建议先在 `ide_home.dart` 局部实现，验证稳定后再决定是否提升到 `ui/core`：

- `lib/src/ui/features/ide/views/ide_home.dart`
- `test/src/app/ide_shell_widget_test.dart`
- `test/src/app/ide_settings_widget_test.dart`

如提升为共享组件：

- `lib/src/ui/core/workbench/ide_retained_page_view.dart`
- `test/src/ui/core/ide_retained_page_view_test.dart`

### 推荐实现：惰性 PageView + KeepAlive

使用不可手势滚动的 `PageView.builder`：

```dart
PageView.builder(
  controller: controller,
  physics: const NeverScrollableScrollPhysics(),
  allowImplicitScrolling: false,
  itemCount: entries.length,
  itemBuilder: (context, index) {
    return _KeepAlivePage(
      key: ValueKey(entries[index].entryId),
      child: buildPage(entries[index]),
    );
  },
)
```

`_KeepAlivePageState` 使用 `AutomaticKeepAliveClientMixin`：

```dart
@override
bool get wantKeepAlive => true;
```

PageView 的 viewport 只布局活动页；离屏 keep-alive child 保存在 Sliver keep-alive
bucket 中，不继续参与每次父约束布局。

### 索引同步

1. 当前选中 entry id 仍以 `AgentWorkspaceController.selectedEntryId` 为真源。
2. `IdeHome` 根据稳定 id 计算目标 index。
3. selection 变化后使用 `jumpToPage`，不播放横向页面切换动画。
4. PageController 尚未 attach 时，在首帧后同步。
5. entries 增删或排序时使用稳定 `ValueKey(entryId)`。
6. 如当前 Flutter 版本的 `PageView.builder` 支持 `findChildIndexCallback`，必须提供
   id → index 映射，避免列表变化后 State 绑定到错误会话。
7. Project Home 使用独立稳定 id，不复用 Agent entry id。

### 两层迁移顺序

1. 先替换会话级 `IndexedStack`，这是性能收益最大的部分。
2. 验证后再替换 Agent / Settings / Usage 页面级 `IndexedStack`。
3. 保留现有 `_settingsPageMounted` 和 `_usageStatisticsPageMounted` 的按需初始化语义。
4. TickerMode 继续保留，作为活动页面动画开关。

### 状态保留验收

必须覆盖：

- 在 A 会话输入草稿，切换 B 后再回到 A，草稿不变。
- A 会话滚动到中部，切换后 offset 不变。
- A 会话存在附件和 mention 草稿，切换后不变。
- 多次新增、关闭、切换会话后 State 不串位。
- 从 Agent 切换到 Settings / Usage 再返回，Agent 状态不变。
- resize 时非活动 AgentPane 的诊断 build/layout 计数为 0。

### 备选方案

若 PageView keep-alive 在目标 Flutter 版本上不能稳定处理动态 entries，可改为：

- 仅挂载活动 AgentPane；
- 新增 presentation 层 `AgentPaneSessionState`，按 entry id 保存草稿、附件、
  mention、滚动 offset 和展开态；
- AgentPane mount 时恢复，unmount 时写回内存状态。

该方案架构更彻底，但改动和回归风险更高，只作为第二选择。

### 7.5 阶段 4：时间线 Sliver 虚拟化

### 问题

即使只布局当前会话，`SingleChildScrollView + Column` 仍会布局该会话的全部历史内容。

### 修改文件

建议新增：

- `lib/src/features/agent/presentation/agent_timeline_projection.dart`
- `test/src/features/agent/presentation/agent_timeline_projection_test.dart`
- `test/src/features/agent/presentation/agent_timeline_virtualization_test.dart`

修改：

- `lib/src/features/agent/presentation/agent_pane.dart`
- `lib/src/features/agent/presentation/widgets/agent_pane_sections.dart`
- `lib/src/features/agent/presentation/agent_timeline_grouping.dart`
- `test/src/features/agent/presentation/agent_conversation_widget_test.dart`
- `test/src/features/agent/presentation/agent_pane_pr3_test.dart`

### 第一步：按 turn 惰性构建

先将时间线改为：

```dart
CustomScrollView(
  controller: scrollController,
  slivers: [
    SliverPadding(
      padding: resolvedPadding,
      sliver: SliverList.builder(
        itemCount: turns.length,
        itemBuilder: buildTurn,
      ),
    ),
  ],
)
```

该阶段已经能避免布局视口外的完整 turn，风险较低。

### 第二步：扁平化到 render block

单个 turn 可能包含很长的消息和工具序列，因此最终目标是把时间线投影为稳定 item：

```dart
sealed class AgentTimelineViewportItem {
  const AgentTimelineViewportItem({required this.id});
  final String id;
}

final class AgentLoadOlderViewportItem extends AgentTimelineViewportItem {}
final class AgentBlockViewportItem extends AgentTimelineViewportItem {}
final class AgentLiveActivityViewportItem extends AgentTimelineViewportItem {}
final class AgentTurnFooterViewportItem extends AgentTimelineViewportItem {}
```

投影顺序：

```text
Load older（如果存在）
→ standby blocks
→ visible history turn blocks
→ 每个 turn footer
→ live turn blocks
→ live activity
→ live turn footer
```

每个 item 使用稳定 key：

```dart
ValueKey<String>('timeline-viewport-${item.id}')
```

`SliverChildBuilderDelegate` 提供 `findChildIndexCallback`，确保加载更早历史后，已有
item 的 StatefulWidget、MarkdownController 和展开状态不会错位。

### 内容宽度

不能在 CustomScrollView 外继续套完整内容 Column。建议用 `SliverLayoutBuilder`
计算居中 padding：

```text
sidePadding =
    max(pagePadding.horizontalSide,
        (viewportWidth - IdeMetrics.contentMaxWidth) / 2)
```

然后对 SliverList 使用 `SliverPadding`。这样继续保持 920px 内容轴，又不破坏
Sliver 虚拟化。

### RepaintBoundary

保留或依赖 `SliverChildBuilderDelegate(addRepaintBoundaries: true)`，边界粒度为单个
viewport item。不要给整个时间线增加一个大 RepaintBoundary。

### 加载更早历史

现有 `_loadOlderTurns` 会记录旧 `pixels` 和 `maxScrollExtent`，在插入历史后按 extent
差值恢复视口。迁移后先保留该算法，并添加动态高度测试。

若 Sliver 的估算 extent 导致位置漂移，升级为锚点算法：

1. 加载前记录第一个可见稳定 item id。
2. 记录该 item 相对 viewport 顶部的 dy。
3. 插入更早 items。
4. 下一帧查找同一 item，计算 dy 差。
5. 对 ScrollController 执行一次 `jumpTo` 修正。

不能只按新增 item 数量乘以估算高度，因为 Markdown 和 diff 高度不固定。

### 自动滚动

以下行为必须保持：

- 用户停留在底部时，流式消息继续自动跟随。
- 用户向上浏览时，流式更新不抢夺滚动位置。
- 新 turn 开始和结束时遵循现有 `autoScrollTick`。
- Composer 高度变化后底部消息不被遮挡。

### 虚拟化测试

构造 100 个 viewport item、固定 600px 高度：

- 首帧 build 数量必须远小于 100。
- 滚动到末尾后，首屏 item 可以被回收。
- item key 和 Stateful 展开态不串位。
- 调整父宽度时，只允许当前 cache extent 内 item 重新 layout。
- 加载更早 turn 后，原锚点屏幕位置误差不超过 1px。

### 7.6 阶段 5：缓存 timeline projection 和 diff 解析

### 问题

`buildAgentTimelineRenderBlocks` 的结果只依赖 turn 内容，却在 Widget build 中重复产生。

### 设计原则

- 缓存位于 presentation 层。
- Store 仍然是 provider-neutral 的 dumb merge。
- 缓存 key 不使用 Provider sourceId 或 raw payload。
- 每个 turn 独立失效，不能因 live turn 更新而重算所有历史 turn。
- 关闭会话或移除 turn 时清理缓存。

### Turn revision

为 `AgentConversationTurnState` 增加单调递增的 render revision：

```dart
int _renderRevision = 0;
int get renderRevision => _renderRevision;
```

所有会改变可见 turn 的路径统一增加 revision，包括：

- entry 新增、替换或删除；
- message 文本、状态或 phase 变化；
- tool call 状态或输出变化；
- diff 更新；
- turn status、duration、token usage、model config 变化。

`AgentConversationTurnGroup.snapshot()` 将 revision 带入不可变快照：

```dart
final int renderRevision;
```

构造函数可先提供默认值 `0`，降低现有测试迁移成本；生产 snapshot 必须传真实值。

### Projection cache

```dart
class AgentTimelineProjectionCache {
  final Map<String, _CachedTurnProjection> _turns;

  List<AgentTimelineRenderBlock> resolve(
    AgentConversationTurnGroup turn,
  );

  void retainOnly(Set<String> visibleTurnIds);
  void clear();
}
```

缓存命中条件：

```text
turn.id 相同
且 turn.renderRevision 相同
```

缓存内容：

- `AgentTimelineRenderBlock` 列表；
- 已解析的 `AgentTimelineFileEditItem`；
- unified diff line stats；
- 稳定 viewport item id。

缓存不保存：

- BuildContext；
- Widget / Element / RenderObject；
- Provider raw payload 的新副本；
- 用户选择状态和滚动状态。

### Projection controller

建议由 `AgentPane` 持有 presentation 层 controller：

```dart
class AgentTimelineProjectionController extends ChangeNotifier {
  AgentTimelineProjectionController({
    required AgentConversationViewModel viewModel,
  });

  List<AgentTimelineViewportItem> get items;
}
```

它只监听：

- `historyVersionListenable`；
- `liveTurnListenable`；
- 当前 live turn 自身的 ChangeNotifier。

窗口 constraints 变化不应触发 controller。

### 测试

- 同一 revision 连续 resolve 100 次，只计算 1 次。
- 只更新 live turn，不重算历史 turn。
- 更新一个历史 turn，只失效该 turn。
- 关闭会话后 cache 清空。
- 相同 id 但 revision 增加时不能返回旧 diff。
- live / history / replay 继续使用隔离状态，不共享 reducer。

### 7.7 阶段 6：缓存代码高亮解析

### 问题

当前 `flutter_highlight 0.7.0` 的 `HighlightView.build` 内部会执行：

```dart
highlight.parse(source, language: language)
```

父级重建时，即使代码没有变化，也会重复解析。

### 修改文件

- `lib/src/features/agent/presentation/widgets/agent_pane_cards.dart`
- `test/src/features/agent/presentation/agent_pane_pr3_test.dart`

### 实现方案

将 `_AgentHighlightedCodeBlock` 改为 StatefulWidget，缓存同一个 `HighlightView`
Widget identity：

```dart
class _AgentHighlightedCodeBlockState
    extends State<_AgentHighlightedCodeBlock> {
  Widget? _cachedHighlight;
  String? _cachedCode;
  String? _cachedLanguage;
  Object? _cachedThemeSignature;
}
```

只在以下情况重建 HighlightView：

- code 变化；
- language 变化；
- brightness / Graphite 代码主题变化；
-文字缩放或代码 TextStyle 变化。

纯父级 resize build 返回同一个 HighlightView child，使 Flutter 跳过其 Stateless
build，避免重复 `highlight.parse`。RenderParagraph 仍可根据真实宽度重新 layout。

### 依赖策略

主方案继续使用现有 `flutter_highlight`，不直接导入其传递依赖 `highlight`，因此不新增
运行时依赖。

若后续需要跨 Widget 共享 parsed nodes，再评估将 `highlight` 声明为直接依赖，并通过
`flutter pub add highlight` 添加；该变化应独立提交并说明用途。

### 7.8 阶段 7：移除 Footer post-frame 测量反馈

### 问题

当前 Footer 高度通过 `GlobalKey + addPostFrameCallback + setState` 获得，导致布局结果
在下一帧反向修改布局。

### 修改文件

- `lib/src/features/agent/presentation/widgets/agent_pane_sections.dart`
- `test/src/features/agent/presentation/agent_pane_pr3_test.dart`

### 推荐实现：CustomMultiChildLayout

新增 `_AgentConversationLayoutDelegate`，在同一次 `performLayout` 中：

1. 先 layout Footer，获得真实高度。
2. 有会话时：
   - Footer 放在底部；
   - Timeline 获得 `height - footerHeight`；
   - Floating plan 放在 Footer 上方。
3. 无会话时：
   - Footer 按 `Alignment(0, -0.12)` 放置；
   - Timeline 继续忽略交互并保持不可见。
4. 所有高度使用本次 layout 的真实 child size，不保存到 State。

布局 id：

```dart
enum _AgentConversationSlot {
  timeline,
  floatingPanel,
  footer,
}
```

删除：

- `_footerMeasureKey`；
- `_footerHeight`；
- `_measurementScheduled`；
- `_scheduleFooterMeasurement`；
- `SizeChangedLayoutNotifier`；
- Footer 高度变化触发的 `setState`。

### 动画

Footer 从新会话中心位置移动到底部只发生在首个 turn 出现时，可以保留动画，但动画
驱动必须是显式 progress，而不是尺寸测量反馈：

- `TweenAnimationBuilder<double>` 或 AnimationController；
- delegate 通过 `relayout` 读取 progress；
- `reduceMotion` 时直接使用最终值；
- 窗口 resize 本身不启动该动画。

### 测试

- 空会话 Footer 对齐不变。
- 首个 turn 后 Footer 落到底部。
- Composer 从 3 行增长到 10 行时，Timeline 不被遮挡。
- Pending interaction 出现和消失时位置正确。
- Active plan 面板位于 Footer 上方。
- 一次 `pump` 完成稳定布局，不需要额外 post-frame `setState`。
- resize 过程中 `transientCallbackCount` 不持续增长。

## 11. 风险与回滚策略

### 11.1 PageView 动态索引风险

风险：新增或删除会话后，旧 State 绑定到错误 index。

控制：

- 所有 page 使用稳定 entry id key；
- 提供 id → index 回调；
- 测试头部插入、中部删除和当前项删除；
- selection 真源仍是 controller 的 entry id。

回滚：只回退 retained viewport 提交，恢复 IndexedStack，不影响后续 Sliver 数据模型。

### 11.2 Sliver 滚动位置风险

风险：加载更早历史后因动态高度估算产生跳动。

控制：

- 保留现有 extent delta 算法作为第一版；
- 使用固定数据做 prepend 测试；
- 必要时升级为稳定 item 锚点修正。

回滚：projection 模型可以保留，时间线临时恢复非虚拟 Column。

### 11.3 状态生命周期风险

风险：MarkdownController、ScrollController 或 FocusNode 被重复 dispose。

控制：

- controller 所有权继续归 AgentPane State；
- projection cache 不持有 Widget controller；
- KeepAlive page 只在 entry 真正关闭时 dispose；
- 增加切换和关闭会话测试。

### 11.4 Cache 失效风险

风险：revision 漏增导致 UI 显示旧 diff 或旧状态。

控制：

- 所有可见状态变更统一走一个 `_markRenderDirty`；
- revision 只单调递增；
- 每类 entry 更新都有单元测试；
- live 和 history 缓存按 turn id 隔离。

回滚：关闭 projection cache，继续调用纯 grouping 函数，不影响 Sliver 结构。

### 11.5 CustomMultiChildLayout 风险

风险：大文字、Pending Dock 或 Composer 极高时约束错误。

控制：

- 所有高度使用 `clamp(0, maxHeight)`；
- Footer 先 layout；
- Timeline 在剩余高度为 0 时仍可安全布局；
- 覆盖最小窗口和 200% 文字缩放测试。

回滚：保留 Sliver 时间线，Footer 临时恢复 Column 底部布局，不恢复 post-frame 测量。

## 12. 完成定义

只有同时满足以下条件，改造才算完成：

1. 当前活动 AgentPane 是 resize 时唯一参与 Agent 会话布局的页面。
2. 时间线 build 数量受 viewport 限制，不随全部历史 item 线性增长。
3. 约束未跨档位时，AgentPane 不因每像素宽度变化重建完整子树。
4. turn 数据未变化时，resize 不执行 grouping 和 unified diff 解析。
5. Footer 不再使用 post-frame 测量和高度 `setState`。
6. Wide / Medium / Compact 切换不卸载当前 Canvas。
7. 草稿、附件、mention、滚动位置、展开态和焦点行为通过回归测试。
8. `dart format .`、`flutter analyze` 和 `flutter test` 全部通过。
9. Windows Profile 固定场景达到第 5.2 节性能标准。
10. 相关设计和开发文档已与最终实现同步。
