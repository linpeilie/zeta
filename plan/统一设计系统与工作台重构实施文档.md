# Zeta 统一设计系统与工作台重构实施文档

> 版本：v2.0  
> 日期：2026-07-15  
> 状态：可执行方案  
> 适用基线：`shadcn_flutter: 0.0.52` + Graphite Token  
> 核心原则：统一骨架 + 表面规则 + 状态规则  

## 文档定位

本文是 `plan/ui_modernization_blueprint.md` 的后续落地规格。旧蓝图中关于
`shadcn_ui`、缺失 Token 和待抽取基础组件的描述已经部分过期：当前项目已完成
`shadcn_flutter` 切换，并已具备 `IdeThemeScope`、`IdeColors`、
`IdeTextStyles`、`IdeSpacing`、`IdeEffects`、`Pane`、`PanelCard`、
`IdeTabs`、`IdeContextMenu` 等基础设施。

本轮不再重复组件库迁移，也不推翻 Graphite，而是在现有基础上解决以下第二阶段
问题：

1. 页面切换时工作台骨架发生变化。
2. 页面虽然共用颜色，却没有共用表面、密度和状态语法。
3. 设置、Agent 管理、用量统计各自形成了局部组件体系。
4. 强调蓝同时承担品牌、选中、用户消息、图表和焦点等过多语义。
5. 缺少视觉回归测试，功能测试无法阻止视觉漂移。

本文中的代码为目标结构和关键实现模板。实际提交应按路线图分批落地，每批保持
可编译、可测试、可回滚。

## 1. 执行摘要

### 1.1 重构目标

把 Zeta 从“共享一套颜色的多个页面”升级为“共享工作台骨架、表面规则、状态
规则和密度规则的一个产品”。

目标体验接近参考截图所呈现的桌面 IDE 语言：

- 大面积连续画布，避免卡片墙。
- 框架、侧栏、编辑区、控件和浮层具有稳定的明度层级。
- 蓝色仅用于焦点、主操作、活动指示和少量关键状态。
- 普通选中态使用中性表面，不再使用高饱和蓝色整块铺底。
- 宽屏保持稳定三栏；窄屏才将侧栏切换为 Overlay。
- 新会话、活动会话、设置、Agent 管理和统计使用同一窗口与页面骨架。
- Feature 页面专注业务内容，不再自行定义页面壳、通用列表行和状态色。

### 1.2 范围

#### 本轮包含

- 扩展 Graphite 颜色、排版、间距和尺寸 Token。
- 收敛 `PaneInteractiveSurface` 的 hover / pressed / selected / focus 规则。
- 新增 `IdeWorkbenchScaffold` 和页面级共享组件。
- 迁移 Agent 主页面、设置、Agent 管理、用量统计、项目列表和文件树。
- 建立深浅主题 Golden Screenshot 基线。
- 更新 `docs/design_document.md`、`docs/developer_guide.md` 和
  `docs/engineering_standards.md`。

#### 本轮不包含

- 修改 Agent provider、App Server、ACP、JSONL 等协议逻辑。
- 更换状态管理框架。
- 引入新的 UI 组件库或 Golden 测试依赖。
- 改变会话、项目、设置和用量统计的领域模型。
- 为了视觉重构重写平台目录或原生窗口实现。

### 1.3 预期效果

| 目标 | 当前状态 | 完成标准 |
|---|---|---|
| 骨架一致 | 首页、设置、统计使用不同页面骨架 | 所有页面由同一 `IdeWorkbenchScaffold` 承载 |
| 表面一致 | `PanelCard` 在各页面被不同方式嵌套 | 仅使用 Canvas / Pane / Row / Popover 四级表面 |
| 状态一致 | 选中态大量复用 `primaryMuted` | 普通选中使用中性色，蓝色只作指示或焦点 |
| 密度一致 | 行高、标题高、侧栏宽分散在 Feature | 统一使用 `IdeMetrics` |
| 排版一致 | 页面私有组件频繁覆盖字重 | 高层语义样式覆盖主要页面文本 |
| 视觉稳定 | 只有交互 Widget 测试 | 深浅主题、宽窄窗口具备 Golden 基线 |

### 1.4 优先级评估

评分范围为 1–5。优先级综合考虑视觉影响、后续复用价值、改造难度和回归风险。

| 工作项 | 影响程度 | 实现难度 | 优先级 | 原因 |
|---|---:|---:|---|---|
| 状态与表面 Token | 5 | 2 | P0 | 所有页面共同依赖，且可增量兼容 |
| `IdeWorkbenchScaffold` | 5 | 4 | P0 | 决定产品是否像同一个应用 |
| 高层共享组件 | 5 | 3 | P0 | 阻止页面继续产生局部设计系统 |
| Agent 主页面 | 5 | 3 | P0 | 使用频率最高，最接近参考目标 |
| Golden 基线 | 5 | 3 | P0 | 没有基线就无法安全迁移 |
| 设置页面 | 4 | 2 | P1 | 范围可控，适合作为属性行样板 |
| 项目 / 文件栏 | 4 | 2 | P1 | 决定三栏 IDE 的整体密度 |
| Agent 管理 | 4 | 3 | P1 | 卡片墙明显，但业务行为复杂 |
| 用量统计 | 3 | 4 | P2 | 页面最大，需保留图表的领域差异 |

### 1.5 架构判断

现有基础 Token 不应删除。`IdeColors` 和 `IdeTextStyles` 已经是正确的运行时
真源；`buildShadcnTheme` 继续只是第三方组件的投影层。

本次新增的是缺失的两层：

```text
Feature 页面
    ↓ 只组合业务内容
页面级共享组件（Workbench / Header / Row / Section / Metric）
    ↓ 只消费语义状态
Graphite Token（Color / Type / Spacing / Metrics / Effects）
    ↓ 单向投影
shadcn_flutter / Material 最小兼容层
```

### 1.6 为什么当前不同页面差距较大

根因不是单一颜色值不一致，而是设计系统目前主要停留在“基础 Token + 低层组件”，
页面级契约尚未建立：

1. **骨架所有权分散。** `IdeHome`、设置、Agent 管理和用量统计分别拼装 Header、
   导航、Detail 和内容区，同一层级的页面因此拥有不同的边距、标题高和滚动方式。
2. **表面语义不足。** `Pane`、`PanelCard` 可以复用外观，但没有规定何时应该是
   Canvas、Pane、Row 或 Popover；Feature 很容易通过嵌套 Card 自行创造层级。
3. **状态语义复用过度。** `primaryMuted` 同时承担导航选中、用户消息、Choice Card
   和弱品牌强调，导致蓝色面积与视觉权重随页面实现方式变化。
4. **高层组件重复。** 设置、Agent 管理和用量统计存在各自的 `_PageHeader`、
   私有 Row、Summary / Metric Card；组件形态相似，但状态和密度规则不同。
5. **布局常量留在 Feature。** 侧栏宽、行高、点击区域、内容最大宽度和 Composer
   尺寸散落在页面文件中，窗口变化时无法形成统一响应式行为。
6. **测试只保护功能。** 当前 Widget 测试能发现点击和状态回归，但不能发现背景
   被覆盖、行高漂移、蓝色面积变大或页面骨架切换等视觉问题。

因此本次改造不能只“换一套颜色”。必须依次补齐语义 Token、高层共享组件和
Workbench 骨架，再通过 Golden 固化结果；三者缺少任意一层，页面都会继续漂移。

## 2. 设计 Tokens 升级方案（第一优先级）

### 2.1 Token 设计原则

1. Token 按语义命名，不按某个页面或组件命名。
2. 表面 Token 与交互状态 Token 分开。
3. 深浅主题都提供最终颜色，Feature 不再现场计算透明度。
4. `accent` 不等于 `selected`，`selected` 也不等于 `userMessage`。
5. 旧字段先保留，采用“新增语义别名 + 新增状态字段”的兼容方式迁移。
6. 所有新增值仍由 `IdeThemeScope` 提供，不从 `sf.ThemeData` 反向读取。

### 2.2 表面与状态语义

#### 表面层级

| 新 Token | 当前来源 | 深色建议 | 浅色建议 | 用途 |
|---|---|---|---|---|
| `frameSurface` | `frame` | `#0A0A0B` | `#FFFFFF` | 窗口框架、标题栏、面板间 gutter |
| `canvasSurface` | `editor` | `#141517` | `#FAFAFB` | 中央编辑器和页面主画布 |
| `paneSurface` | `surface` | `#18191B` | `#F9F9FA` | 会话栏、文件栏、设置导航 |
| `controlSurface` | `surfaceElevated` | `#212225` | `#F4F5F7` | 输入框、分段控件、紧凑选择器 |
| `popoverSurface` | `surfaceOverlay` | `#2C2D30` | `#FFFFFF` | Popover、菜单、Tooltip、Drawer |

第一阶段将前五个新名称实现为旧字段的只读语义 getter，避免一次性改动所有构造、
`copyWith` 与测试。待所有 Feature 迁移完毕，再反转关系并将旧名称标记为
`@Deprecated`。

#### 交互状态

| Token | 深色建议 | 浅色建议 | 用途 |
|---|---|---|---|
| `hoverSurface` | `#242529` | `#F0F1F3` | 未选中控件 hover |
| `pressedSurface` | `#2A2B30` | `#E8EAED` | 指针按下 |
| `selectedSurface` | `#292A2E` | `#E9EAED` | 普通导航、列表选中 |
| `selectedHoverSurface` | `#303136` | `#E2E4E8` | 已选中控件 hover |
| `userMessageSurface` | `#2B2C30` | `#ECEDEF` | 用户消息气泡 |
| `focusRing` | `#1B84FF` | `#0B76D8` | 键盘焦点与输入焦点 |

`primaryMuted` 暂时保留，用于真正的蓝色弱强调，例如可操作提示和少量活动状态；
不再用于普通导航、用户气泡和大面积卡片。

## 3. 核心共享组件 / 骨架系统（第二优先级）

### 3.1 高层组件边界

高层共享组件负责视觉和交互规则，Feature 负责文案、数据和回调。

| 层级 | 负责 | 不负责 |
|---|---|---|
| `IdeWorkbenchScaffold` | Pane 排列、宽窄模式、Overlay 位置 | 项目、会话和页面业务状态 |
| `IdePageHeader` | 标题高度、排版、动作区、分隔线 | 页面导航逻辑 |
| `IdeSurface` | Canvas / Pane / Row / Popover 装饰 | 内容布局 |
| `IdeListRow` | 行高、状态、图标、文本省略 | 数据加载和选择状态来源 |
| `IdeSettingsRow` | 属性名称、描述、控件对齐 | 保存设置 |
| `CompactMetricBar` | 指标密度和响应式换行 | 统计口径 |
| `PaneInteractiveSurface` | hover / pressed / selected / focus | 业务语义 |

Feature 页面可以直接使用 `sf.TextField`、`sf.Switch`、`sf.Select` 等必要控件，
但尺寸和装饰应由 `ui/core` 包装或 `sf.ComponentTheme` 统一投影，不允许每个页面
自行设定一套 padding、radius 和颜色。

### 3.2 表面层级规则

#### 四级表面

| 等级 | 背景 | 边框 | 圆角 | 阴影 | 示例 |
|---|---|---|---|---|---|
| Canvas | `canvasSurface` | 无 | 无 | 无 | 中央工作区、页面滚动区 |
| Pane | `paneSurface` | 外层 1px | 8px | 无 | 会话栏、文件栏、设置导航 |
| Row | 透明 / 状态表面 | 仅分隔线 | 0 或 6px | 无 | Thread、文件、设置项、表格行 |
| Popover | `popoverSurface` | 1px | 12px | Overlay Shadow | 菜单、选择器、Tooltip |

规则：

1. 同一 Pane 内的连续内容使用 Row，不再每行创建一张 Card。
2. Pane 可以嵌套 Canvas，但 Pane 不应再嵌套多个同级 Pane。
3. Popover 是唯一默认带阴影的表面。
4. 错误、警告和审批可以使用 `IdeStatusCard`，但不能把普通信息也升级为状态卡。
5. `PanelCard` 在迁移期保留；新增页面优先使用 `IdeSurface`。

### 3.3 `IdeSurface` 参考实现

新增文件：`lib/src/ui/core/surfaces/ide_surface.dart`

```dart
import 'package:flutter/material.dart';
import 'package:shadcn_flutter/shadcn_flutter.dart' as sf;

import '../ide_colors.dart';
import '../ide_effects.dart';

enum IdeSurfaceLevel { canvas, pane, row, popover }

class IdeSurface extends StatelessWidget {
  const IdeSurface({
    required this.level,
    required this.child,
    super.key,
    this.padding,
    this.borderRadius,
    this.clipBehavior = Clip.antiAlias,
  });

  const IdeSurface.canvas({
    required Widget child,
    Key? key,
    EdgeInsetsGeometry? padding,
  }) : this(
         key: key,
         level: IdeSurfaceLevel.canvas,
         padding: padding,
         child: child,
       );

  const IdeSurface.pane({
    required Widget child,
    Key? key,
    EdgeInsetsGeometry? padding,
  }) : this(
         key: key,
         level: IdeSurfaceLevel.pane,
         padding: padding,
         child: child,
       );

  const IdeSurface.row({
    required Widget child,
    Key? key,
    EdgeInsetsGeometry? padding,
  }) : this(
         key: key,
         level: IdeSurfaceLevel.row,
         padding: padding,
         child: child,
       );

  const IdeSurface.popover({
    required Widget child,
    Key? key,
    EdgeInsetsGeometry? padding,
  }) : this(
         key: key,
         level: IdeSurfaceLevel.popover,
         padding: padding,
         child: child,
       );

  final IdeSurfaceLevel level;
  final Widget child;
  final EdgeInsetsGeometry? padding;
  final BorderRadiusGeometry? borderRadius;
  final Clip clipBehavior;

  @override
  Widget build(BuildContext context) {
    final colors = IdeColors.of(context);
    final brightness = sf.Theme.of(context).brightness;
    final background = switch (level) {
      IdeSurfaceLevel.canvas => colors.canvasSurface,
      IdeSurfaceLevel.pane => colors.paneSurface,
      IdeSurfaceLevel.row => Colors.transparent,
      IdeSurfaceLevel.popover => colors.popoverSurface,
    };
    final resolvedRadius =
        borderRadius ??
        switch (level) {
          IdeSurfaceLevel.canvas || IdeSurfaceLevel.row => BorderRadius.zero,
          IdeSurfaceLevel.pane => IdeRadius.allMedium,
          IdeSurfaceLevel.popover => IdeRadius.allLarge,
        };
    final showBorder =
        level == IdeSurfaceLevel.pane ||
        level == IdeSurfaceLevel.popover;

    return Container(
      clipBehavior: clipBehavior,
      padding: padding,
      decoration: BoxDecoration(
        color: background,
        borderRadius: resolvedRadius,
        border: showBorder ? Border.all(color: colors.border) : null,
        boxShadow: level == IdeSurfaceLevel.popover
            ? IdeEffects.overlayShadow(brightness)
            : const <BoxShadow>[],
      ),
      child: child,
    );
  }
}
```

### 3.4 统一 `PaneInteractiveSurface` 状态

```dart
    widget.backgroundColor ?? Colors.transparent;

    widget.hoverBackgroundColor ?? colors.hoverSurface;

    widget.pressedBackgroundColor ?? colors.pressedSurface;

    widget.selectedBackgroundColor ?? colors.selectedSurface;

  widget.enabled,
  _pressed,
  _hovered,
  widget.selected,

  (false, _, _, _) => baseBackground,
  (true, true, _, _) => pressedBackground,
  (true, false, true, true) => selectedHoverBackground,
  (true, false, false, true) => selectedBackground,
  (true, false, true, false) => hoverBackground,
  _ => baseBackground,

    : widget.selected
```

```dart
final Color? selectedHoverBackgroundColor;
```


### 3.5 `IdeWorkbenchScaffold` 设计

新增文件：
`lib/src/ui/core/workbench/ide_workbench_scaffold.dart`

#### 职责

- 宽屏：左导航 Pane + 中央 Canvas + 右检查 Pane。
- 中屏：左 Pane 内联，右 Pane 变为 Overlay。
- 窄屏：中央 Canvas 独占，左右 Pane 都是 Overlay。
- 保留现有可拖拽宽度和 Pane 可见状态。
- Overlay 一次最多打开一侧。
- 不持有项目、Thread 或页面业务状态。
- 不直接创建 `WindowFrame`；`WindowFrame` 仍是应用最外层。

#### 布局模式

```dart
enum IdeWorkbenchLayoutMode { wide, medium, compact }

IdeWorkbenchLayoutMode resolveWorkbenchLayoutMode(double width) {
  if (width >= IdeMetrics.wideBreakpoint) {
    return IdeWorkbenchLayoutMode.wide;
  }
  if (width >= IdeMetrics.mediumBreakpoint) {
    return IdeWorkbenchLayoutMode.medium;
  }
  return IdeWorkbenchLayoutMode.compact;
}
```

#### 参考实现

```dart
import 'package:flutter/material.dart';
import 'package:shadcn_flutter/shadcn_flutter.dart' as sf;

import '../ide_colors.dart';
import '../ide_effects.dart';
import '../ide_metrics.dart';
import '../ide_spacing.dart';

class IdeWorkbenchScaffold extends StatelessWidget {
  const IdeWorkbenchScaffold({
    required this.canvas,
    super.key,
    this.leadingRail,
    this.navigationPane,
    this.inspectorPane,
    this.trailingRail,
    this.navigationVisible = true,
    this.inspectorVisible = true,
    this.navigationOverlayOpen = false,
    this.inspectorOverlayOpen = false,
    this.navigationWidth = IdeMetrics.sidePaneDefaultWidth,
    this.inspectorWidth = IdeMetrics.inspectorPaneWidth,
    this.onDismissNavigationOverlay,
    this.onDismissInspectorOverlay,
  });

  final Widget canvas;
  final Widget? leadingRail;
  final Widget? navigationPane;
  final Widget? inspectorPane;
  final Widget? trailingRail;
  final bool navigationVisible;
  final bool inspectorVisible;
  final bool navigationOverlayOpen;
  final bool inspectorOverlayOpen;
  final double navigationWidth;
  final double inspectorWidth;
  final VoidCallback? onDismissNavigationOverlay;
  final VoidCallback? onDismissInspectorOverlay;

  @override
  Widget build(BuildContext context) {
    final navigation = navigationPane;
    final inspector = inspectorPane;
    return LayoutBuilder(
      builder: (context, constraints) {
        final mode = resolveWorkbenchLayoutMode(constraints.maxWidth);
        final navigationInline =
            navigation != null &&
            navigationVisible &&
            mode != IdeWorkbenchLayoutMode.compact;
        final inspectorInline =
            inspector != null &&
            inspectorVisible &&
            mode == IdeWorkbenchLayoutMode.wide;

        final base = Row(
          crossAxisAlignment: CrossAxisAlignment.stretch,
          children: [
            if (leadingRail != null) ...[
              SizedBox(
                width: IdeMetrics.activityRailWidth,
                child: leadingRail,
              ),
              const SizedBox(width: IdeSpacing.space8),
            ],
            if (navigationInline) ...[
              SizedBox(width: navigationWidth, child: navigation),
              const SizedBox(width: IdeSpacing.space8),
            ],
            Expanded(child: canvas),
            if (inspectorInline) ...[
              const SizedBox(width: IdeSpacing.space8),
              SizedBox(width: inspectorWidth, child: inspector),
            ],
            if (trailingRail != null) ...[
              const SizedBox(width: IdeSpacing.space8),
              SizedBox(
                width: IdeMetrics.activityRailWidth,
                child: trailingRail,
              ),
            ],
          ],
        );

        final showNavigationOverlay =
            navigation != null &&
            navigationVisible &&
            !navigationInline &&
            navigationOverlayOpen;
        final showInspectorOverlay =
            inspector != null &&
            inspectorVisible &&
            !inspectorInline &&
            inspectorOverlayOpen;

        if (!showNavigationOverlay && !showInspectorOverlay) {
          return base;
        }

        final colors = IdeColors.of(context);
        final brightness = sf.Theme.of(context).brightness;
        return Stack(
          children: [
            base,
            Positioned.fill(
              child: GestureDetector(
                key: const ValueKey('workbench-overlay-scrim'),
                behavior: HitTestBehavior.opaque,
                onTap: () {
                  onDismissNavigationOverlay?.call();
                  onDismissInspectorOverlay?.call();
                },
                child: ColoredBox(color: IdeEffects.scrim(brightness)),
              ),
            ),
            if (showNavigationOverlay)
              Positioned(
                top: 0,
                bottom: 0,
                left: leadingRail == null
                    ? 0
                    : IdeMetrics.activityRailWidth + IdeSpacing.space8,
                width: navigationWidth,
                child: DecoratedBox(
                  decoration: BoxDecoration(
                    color: colors.paneSurface,
                    borderRadius: IdeRadius.allMedium,
                    boxShadow: IdeEffects.overlayShadow(brightness),
                  ),
                  child: navigation,
                ),
              ),
            if (showInspectorOverlay)
              Positioned(
                top: 0,
                bottom: 0,
                right: trailingRail == null
                    ? 0
                    : IdeMetrics.activityRailWidth + IdeSpacing.space8,
                width: inspectorWidth,
                child: DecoratedBox(
                  decoration: BoxDecoration(
                    color: colors.paneSurface,
                    borderRadius: IdeRadius.allMedium,
                    boxShadow: IdeEffects.overlayShadow(brightness),
                  ),
                  child: inspector,
                ),
              ),
          ],
        );
      },
    );
  }
}
```

```dart
                  ),

            ],
```

```dart
    required this.styles,

  final CompactMetricItem item;
  final IdeTextStyles styles;
```

### 3.10 Popover 规范

现有 `IdePopover` 和 `sf.showPopover` 继续使用，不新增 Overlay 依赖。

统一规范：

- 锚点与弹层间距：8px。
- 默认宽度：280px；长模型列表最大 360px。
- `IdeRadius.allLarge`。
- 背景 `popoverSurface`。
- 边框 `border`。
- 阴影 `IdeEffects.overlayShadow`。
- 菜单行 32px，带描述选项最小 48px。
- 选中项使用 `selectedSurface`，可选右侧 check；ActivityRail 不使用侧边指示条。
- Esc 关闭并恢复焦点。
- 列表使用 roving focus，禁用项展示原因。
- Popover 内不得使用整块 `primaryMuted` 作为默认选中底。

参考图中的权限模式选择应由 `_PermissionPolicyPopover` 迁移到统一
`IdePopover` 表面和 `IdeListRow` 语法。

### 3.11 共享组件验收

- `IdeHome` 不再自行决定 Inline / Overlay 的视觉装饰。
- 设置、Agent 管理和用量统计不再拥有私有 `_PageHeader`。
- 项目、Thread、文件、Agent 行至少共享 `IdeListRow` 的状态规则。
- 普通 Pane 无阴影；Popover 是默认唯一抬升表面。
- 所有非文本按钮有 tooltip 和 semantic label。
- 所有重复行有稳定 `ValueKey`。
- 公共组件拥有独立 Widget 测试。

2. 项目和 Thread 操作命中区域当前存在 18px 私有尺寸，过小。
3. 文件行、Thread 行和导航行没有完全共用状态表面。
4. 选中态仍可能使用 `primaryMuted`。

- 宽屏默认显示会话栏和文件栏。
- Rail 是折叠入口，不是宽屏默认的信息承载方式。
- Pane Header 38px，列表行 28–32px。
- 选中 Row / Rail 图标使用中性 `selectedSurface`；`IdeActivityRail` 不再绘制侧边
  `accent` 指示条，仅靠中性选中底与 `accentForeground` 图标色表达激活态。
- 图标 14–16px，点击区域至少 28px。
- 路径、Thread 标题和文件名始终单行省略。

#### 关键改造

1. `IdeHome` 初始化状态在宽屏默认：

```dart

bool _rightTopVisible = true;
```

窄屏首次布局时只内联中央 Canvas，不自动弹出 Overlay。
2. `FileTreePane._rowHeight` 替换为
   `IdeMetrics.compactRowHeight`。
3. 项目和 Thread 操作按钮使用
   `IdeMetrics.iconButtonHitSize`。
4. `_ThreadTile` 和文件节点的默认颜色改由
   `PaneInteractiveSurface` 状态 Token 驱动。
5. Pane Header 统一使用 `Pane` 或后续 `IdePaneHeader`，不再 Feature 私有化。
6. 上下文菜单继续使用 `IdeContextMenu`，其表面统一迁移到
   `IdeSurface.popover`。

#### 组件替换

| 当前 | 替换 |
|---|---|
| 私有文件 / Thread 状态色 | `PaneInteractiveSurface` 默认状态 |
| 18px action hit size | `IdeMetrics.iconButtonHitSize` |

- 820px 以下只显示中央 Canvas，侧栏由 Rail 打开 Overlay。
- 文件树懒加载、项目操作、Thread 菜单和焦点行为不变。

## 5. 技术实现细节

### 5.1 深色 / 浅色主题

#### 保持现有单向主题链

```text
AppearanceSettings
    ↓ ThemeMode / font family / font size
IdeThemeScope
    ↓ IdeThemeData
IdeColors + IdeTextStyles + IdeMetrics
    ↓ projection
sf.ThemeData + Material ThemeData
```

规则：

1. `IdeThemeScope` 继续是唯一运行时真源。
2. `buildShadcnTheme` 和 `buildMaterialTheme` 只能读取 `IdeThemeData`。
3. Feature 不从 `sf.Theme.of(context).colorScheme` 反向解析 Graphite 语义。
4. Brightness 通过 `IdeThemeScope.of(context).brightness` 或
   `sf.Theme.of(context).brightness` 获取。
5. 主题切换时所有新增颜色通过 `IdeColors.lerp` 平滑过渡。
6. 自定义 UI 字体和代码字体继续沿用现有设置，不引入新的字体依赖。

#### 对比度目标

- 正文与 Canvas / Pane：至少 4.5:1。
- 次级文本：普通正文场景至少 4.5:1；纯辅助元数据至少 3:1。
- 图标、焦点边界和控件边界：至少 3:1。
- Disabled 状态允许降低对比，但不得只通过颜色表达不可用原因。
- Warning / Error / Success 不应直接铺满大面积背景，优先使用小图标、文字和边线。

#### Light Theme 专项

浅色主题不能简单把深色主题反转：

- `frameSurface` 与 `canvasSurface` 保持轻微差异。
- `paneSurface` 不使用纯灰大块压暗页面。
- `selectedSurface` 使用中性灰，不使用淡蓝整块填充。
- `popoverSurface` 可以为白色，但必须依靠边框和轻阴影建立层级。
- 图表填充透明度应低于深色主题。

每次迁移页面都必须同时生成 dark / light Golden，不允许最后集中补浅色。

### 5.2 响应式策略

#### 断点

| 模式 | 宽度 | 布局 |
|---|---:|---|
| Wide | ≥ 1180px | 左 Pane + 中央 Canvas + 右 Pane |
| Medium | 820–1179px | 左 Pane + 中央 Canvas，右 Pane Overlay |
| Compact | < 820px | 中央 Canvas，左右 Pane Overlay |
| Stacked Row | < 640px 可用内容宽 | 设置行、筛选器和复杂 Row 垂直排列 |

断点应依据组件父级 `LayoutBuilder.constraints.maxWidth`，不要直接用整个屏幕
`MediaQuery` 推断。窗口标题栏、Rail 和已展开 Pane 会改变真正可用宽度。

#### Pane 宽度

- 左会话 Pane 默认 280px，可拖拽 220–400px。
- 右文件 / Context Pane 默认 300px，可拖拽 220–400px。
- 设置导航固定 240px；Compact 下改为 Overlay。
- 中央 Agent 内容最小 480px；低于此值时两侧必须转为 Overlay。
- 用户拖拽宽度继续由 `IdeHome` 保存，不因页面切换重置。

#### Overlay

- 一次最多显示一侧 Overlay。
- 打开右侧时关闭左侧，反之亦然。
- Scrim 点击、Esc 和 Rail 再次点击都可关闭。
- 关闭后焦点回到触发按钮。
- Overlay 不改变底层 Canvas 的滚动位置。
- Reduce Motion 时取消滑入动画，只保留即时显示。

#### 文本缩放

- 所有 Header 和 Row 使用 `maxLines` + `ellipsis`。
- 设置行和指标条允许在较大系统字号下增高，不把高度写死为绝对值。
- `IdeMetrics.listRowHeight` 表示最小高度，不是强制裁剪高度。
- Composer 多行输入继续根据统一字号计算行高。

### 5.3 状态管理与交互态

#### 状态归属

| 状态 | 归属 |
|---|---|
| selected / active 业务值 | Feature controller / view model |
| hover / pressed / focus | 共享交互 Widget 本地状态 |
| Pane 可见和宽度 | `IdeHome` / Shell controller |
| Overlay 打开状态 | `IdeHome`，由 Scaffold 渲染 |
| ThemeMode / 字体 | `AppearanceSettingsController` |
| Popover 选项 | 对应 Feature controller |

不要把 hover、pressed 等瞬态状态加入领域 Controller，也不要让共享组件决定 Agent
或设置的选中值。

#### 状态视觉矩阵

| 状态 | 背景 | 边框 / 指示 | 前景 |
|---|---|---|---|
| Base | 透明或 `controlSurface` | `borderSubtle` | `textSecondary` / `textPrimary` |
| Hover | `hoverSurface` | 不增强 | `textPrimary` |
| Pressed | `pressedSurface` | 不增强 | `textPrimary` |
| Selected | `selectedSurface` | 无侧边指示条（列表可选 check；Rail 仅中性底 + 前景色） | `textPrimary` / Rail 图标 `accentForeground` |
| Selected + Hover | `selectedHoverSurface` | 同上，无侧边指示条 | `textPrimary` / Rail 图标 `accentForeground` |
| Focus | 保持当前背景 | `focusRing` 或 2px ring | `textPrimary` |
| Disabled | 保持 Base | 无焦点 | `textTertiary`，opacity 0.48–0.6 |

语义色不参与普通交互态。只有业务状态本身是 error / warning / success / info 时才
使用相应颜色。

#### 键盘与无障碍

- 所有 Row 支持 Enter / Space 激活。
- 所有 IconButton 有 `IdeTooltip` 和 `Semantics.label`。
- Tabs 使用 roving focus。
- Popover 打开后焦点进入首个可用项，关闭后恢复。
- Disabled 项展示原因，不能只有灰色。
- 自定义图表提供语义摘要，不要求对每个点创建独立节点。
- 重要状态变化通过可读文本表达，不只靠红绿颜色。

### 5.4 避免未来视觉漂移

#### 组件约束

1. Feature 不新增页面级 `_PageHeader`。
2. Feature 不新增通用 `_SomethingRow`，除非内容结构确实是领域专用。
3. Feature 中的 `PanelCard` 使用必须说明其属于哪一级表面。
4. Feature 不直接使用 `primaryMuted` 作为普通选中背景。
5. Feature 不手写 Popover 阴影、圆角和边框。
6. 同类控件必须先查找 `ui/core` 是否已有实现。
7. 新增视觉语义先扩展 Token，再修改调用方。

#### 自动检查建议

新增只读检查脚本：
`tool/check_ui_style.sh`，在 CI 或提交前执行以下扫描：


- 是否重复创建了已有共享组件？

```dart
        Row(
          children: [
            Expanded(
              child: Column(
                crossAxisAlignment: CrossAxisAlignment.start,
                children: [
                  Text(title, style: styles.sectionTitle),
                  if (subtitle != null)
                    Text(subtitle!, style: styles.meta),
                ],
              ),
            ),
            if (trailing != null) trailing!,
          ],
        ),
        const SizedBox(height: IdeSpacing.space8),

    );
  }
}
```

### 7.3 `IdePageBody` 模板

```dart
import 'package:flutter/widgets.dart';

import '../ide_metrics.dart';
import '../ide_spacing.dart';

class IdePageBody extends StatelessWidget {
  const IdePageBody({
    required this.child,
    super.key,
    this.maxWidth = IdeMetrics.settingsContentMaxWidth,
  });

  final Widget child;
  final double maxWidth;

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        final compact =
            constraints.maxWidth < IdeMetrics.mediumBreakpoint;
        return Align(
          alignment: Alignment.topCenter,
          child: SingleChildScrollView(
            padding: compact
                ? IdeSpacing.pagePaddingCompact
                : IdeSpacing.pagePadding,
            child: ConstrainedBox(
              constraints: BoxConstraints(maxWidth: maxWidth),
              child: child,
            ),
          ),
        );
      },
    );
  }
}
```

### 7.7 风格检查清单

#### 骨架

- [ ] 页面是否位于统一 `IdeWorkbenchScaffold` 内？
- [ ] 页面切换是否保留 WindowFrame、Pane 状态和滚动状态？
- [ ] 宽屏是否展示稳定三栏？
- [ ] 窄屏是否只把必要 Pane 转为 Overlay？

- [ ] 能否明确指出每个区域是 Canvas、Pane、Row 还是 Popover？
- [ ] 是否存在 Pane 内嵌多个同级 Card 的卡片墙？
- [ ] 普通表面是否错误使用阴影？
- [ ] Popover 是否使用统一边框、圆角和阴影？

- [ ] 是否只通过 `IdeColors` 读取颜色？

### 7.8 完成定义

本轮重构只有同时满足以下条件才算完成：

1. 首页、设置、Agent 管理和用量统计共用稳定工作台骨架。
2. 页面不再各自维护通用 Header、普通 Row 和指标卡。
3. 普通选中、用户消息和焦点拥有独立语义 Token。
4. 中央 Agent Canvas 不再被 `frame` 覆盖。
5. 宽屏三栏、窄屏 Overlay、深浅主题全部通过 Golden。
6. Feature 中没有新增硬编码颜色、圆角和阴影。
7. 现有行为测试、静态分析和全量测试通过。
8. `docs/design_document.md`、`docs/developer_guide.md`、
   `docs/engineering_standards.md` 与实现一致。

最终视觉统一不意味着所有页面采用相同布局。Agent 仍是会话工作流，用量统计仍是
数据分析页面；统一的是它们的窗口骨架、表面层级、密度、排版和交互状态，使用户
始终明确自己仍然处于同一个 Zeta IDE 中。
