### TASK-UI-001：将 Workbench 提升为所有主要页面的常驻统一骨架（已完成，2026-07-16）

**修复前问题**

`IdeWorkbenchScaffold` 当前只在首页模式创建。切换到设置或用量统计时，`IdeHome._buildPageBody()` 会直接用新页面替换整个 Workbench，导致页面骨架变化，也会销毁 AgentPane 子树。

**涉及位置**

- `lib/src/ui/features/ide/views/ide_home.dart`
- `lib/src/ui/core/workbench/ide_workbench_scaffold.dart`
- `lib/src/features/settings/presentation/settings_page.dart`
- `lib/src/features/usage_statistics/presentation/usage_statistics_page.dart`
- `lib/src/features/agent_management/presentation/agent_management_page.dart`

**实施结果**

- `WindowFrame` 内常驻带稳定 Key 的 `IdeWorkbenchScaffold`，删除了
  `IdeHome._buildPageBody()` 的独立顶层页面切换。
- Canvas 改为延迟挂载的保活页面栈：`AgentPane` 始终挂载，设置和使用统计首次访问后
  保留，非活动页通过 `TickerMode` 暂停 ticker。
- Workbench Canvas 的 `Expanded` slot 直接使用稳定 Key，Navigation/Inspector slot
  增删和 Canvas 换位不会销毁 Agent 子树。
- 设置 Feature 拆分出 `SettingsNavigationPane` 和 `SettingsPageCanvas`；Agent 管理作为
  设置 Canvas 分区接入，未保存配置确认仍由 `SettingsPageCanvasState` 持有。
- 页面 slot 策略已经明确：Agent 首页使用 Navigation/Canvas/Inspector；设置与 Agent
  管理使用 Navigation/Canvas；使用统计只使用 Canvas。Wide/Medium 内联可用 Navigation，
  Compact Pane 走 Workbench Overlay。
- 新增真实 `IdeHome` 的 Agent → Settings → Agent、Agent → Usage → Agent 测试，验证
  `WindowFrame`、Workbench、AgentPane Element、当前 Thread、草稿、非零滚动位置、
  Pane 宽度和可见状态保持。

**实施要求**

- `WindowFrame` 内始终保留同一个 `IdeWorkbenchScaffold` 实例结构。
- 首页、设置、Agent 管理和用量统计通过 Workbench 的 Navigation、Canvas、Inspector slot 切换内容。
- 页面切换不得重新创建 Agent 会话主区域的关键 State、ScrollController 或输入状态。
- 页面业务仍由对应 Feature 持有，不把业务路由逻辑下沉到共享 Scaffold。
- 明确各页面在 Wide、Medium、Compact 下分别提供哪些 Pane。

**验收标准**

- 首页、设置、Agent 管理、用量统计均位于同一个 Workbench 下。
- 页面切换时 `WindowFrame`、Workbench Key、Pane 宽度和可见状态保持不变。
- 从 Agent 页面进入设置再返回时，对话滚动位置、草稿和当前 Thread 不丢失。
- 不再由 `IdeHome._buildPageBody()` 返回相互独立的顶层页面骨架。

**测试要求**

- 新增实际 `IdeHome` 页面切换 Widget 测试。
- 覆盖 Agent → Settings → Agent、Agent → Usage → Agent 两条路径。
- 验证滚动位置、Pane 宽度、Pane 可见状态和草稿状态保持。

**依赖**

- 无；其他响应式和 Golden 任务依赖本任务。

**验证结果**

- `dart format --output=none --set-exit-if-changed .` 通过。
- `flutter analyze` 通过，0 issues。
- `flutter test` 通过，544 项测试。

## 6. 全局完成定义

全部任务完成后，本次统一设计系统重构应同时满足：

- 所有主要页面由一个常驻 `IdeWorkbenchScaffold` 承载。
- 1280px 以上默认稳定三栏，Medium/Compact 使用统一 Overlay 规则。
- Feature 不再直接使用 `PanelCard`、旧 Token、硬编码颜色/圆角/阴影和现场状态 alpha。
- Canvas / Pane / Row / Popover 四级表面可以覆盖所有主要视觉区域。
- 设置、Agent 管理、用量统计、Project/File Pane 和 Agent 关键状态均有 Dark/Light Golden。
- format、analyze、全量测试、Golden 和 UI style 检查全部由 CI 强制执行。
- 设计文档、开发指南、工程规范、AGENTS 与实现一致。
- 旧 UI API 有明确弃用和删除周期，不能继续新增消费者。

## 7. 每个任务的统一交付要求

每个开发任务提交时必须包含：

1. 代码变更及必要的中文注释或公共 API 文档。
2. 对应 Widget/单元/Golden 测试。
3. `dart format --output=none --set-exit-if-changed .` 通过。
4. `flutter analyze` 通过。
5. `flutter test` 通过。
6. 如修改视觉，提交 Dark/Light 和 Wide/Compact 对照截图或 Golden 差异说明。
7. 如引入或删除 Token/共享组件，同步更新设计与开发文档。
