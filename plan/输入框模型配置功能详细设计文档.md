### 0.1 修订摘要

本次修订不改变模型配置的业务含义、持久化策略和生效时机，主要调整信息架构与交互表现：

1. Popover 打开后首先展示模型列表，不展示模型搜索。
2. 移除独立的“当前模型”Header，当前选择直接由模型列表项的选中状态表达。
3. 用户点击模型后，在该模型列表项下方展开内嵌配置区域；配置不会固定出现在列表底部。
4. 内嵌区域不重复展示“`<模型名> 配置`”标题，仅包含 Reasoning effort 与 Fast。
5. 模型切换时，旧配置收起、新配置在目标模型下展开，并使用统一的尺寸、位移与淡入淡出动画。
6. 优化选中项、内嵌卡片、Reasoning effort 分段控件、Fast 开关及 Flutter 组件职责。

## 1. 背景与目标

### 1.1 背景

用户需要在 Agent 输入框附近快速完成以下操作：

- 查看当前使用的模型及其有效配置；
- 切换模型；
- 调整所选模型的 Reasoning effort；
- 开启或关闭 Fast；
- 理解配置的生效时机和不可用原因。

模型是一级决策对象，Reasoning effort 和 Fast 是所选模型的二级配置。界面需要准确表达这一归属关系，避免将 Popover 设计成与输入任务割裂的独立设置页。

### 1.2 设计目标

- **模型优先**：打开 Popover 后，首要视觉对象和首个操作对象均为模型列表。
- **归属明确**：配置直接出现在所选模型下方，不要求用户在列表与底部面板之间建立关联。
- **渐进披露**：初始仅展示模型列表；用户明确选择后才展示二级配置。
- **低干扰**：不展示搜索、供应商、价格、上下文长度、能力标签和模型描述等非必要信息。
- **操作连续**：在同一 Popover 内完成模型选择和二级配置，调整后保持 Popover 打开。
- **状态稳定**：异步刷新、模型切换和内容展开不造成入口清空、列表闪烁或锚点跳动。

### 1.3 非目标

V1 不包含：

- 模型搜索、筛选、排序或分组；
- 模型详情、价格、上下文窗口、能力标签或性能比较；
- Provider 品牌或 Provider 专属视觉；
- 高级参数，如 temperature、top-p、工具权限或 reasoning budget；
- 独立模型设置页。

## 2. 核心设计原则

### 2.1 信息层级

```text
模型（一级对象）
└── Reasoning effort（二级配置）
└── Fast（二级配置）
```

模型列表项负责表达“选择了哪个模型”；列表项下的扩展区域负责表达“该模型如何运行”。二者必须在空间上相邻，在状态上由同一个 `modelId` 关联。

### 2.2 选中与展开是两个状态

界面需区分：

- `selectedModelId`：当前将用于新回合的模型；始终存在有效值。
- `expandedModelId`：当前正在查看或编辑配置的模型；Popover 初次打开时为 `null`。

因此，Popover 打开后可看到当前模型的选中样式，但不会立即展示配置。用户点击任一可用模型行后，该模型成为选中模型，同时在其行下展开配置。

该拆分保证“先展示模型列表，选择后再展示配置”的交互要求，同时不丢失当前选择状态。

### 2.3 Provider 中立

界面只使用产品统一的模型名称、状态和控件，不使用 Provider Logo、专属配色或 Provider 文案。相同能力使用相同交互规则。

### 2.4 Fast 状态语义

入口中的闪电符号仅表示 **Fast 当前已启用**，不表示该模型“支持 Fast”。支持性和可配置性由 Popover 内的 Fast 控件状态表达。

## 3. 总体信息架构

### 3.1 收起入口

```text
[ GPT-5.6-Luna · 中 ⚡  ▾ ]
```

入口展示最终有效状态：

1. 模型名称；
2. 当前 Reasoning effort；
3. Fast 已开启时显示闪电；
4. 展开方向图标。

### 3.2 Popover 初始状态

Popover 每次新打开时只展示模型列表。当前模型在列表内显示选中状态，配置区域保持收起。

```text
┌──────────────────────────────┐
│ 选择模型                     │
│                              │
│ ✓  GPT-5.6-Luna              │
│    GPT-5.5                   │
│    GPT-5.4                   │
│    GPT-Legacy            ⓘ   │
└──────────────────────────────┘
```

### 3.3 点击模型后的状态

```text
┌──────────────────────────────┐
│ 选择模型                     │
│                              │
│ ✓  GPT-5.6-Luna              │
│   ┌────────────────────────┐ │
│   │ 思考程度               │ │
│   │ [ 低 | 中 | 高 | 极高 ]│ │
│   │                        │ │
│   │ ⚡ Fast          [ ON ]│ │
│   └────────────────────────┘ │
│    GPT-5.5                   │
│    GPT-5.4                   │
└──────────────────────────────┘
```

配置区域属于 `GPT-5.6-Luna` 列表项的扩展内容，位于该模型与下一模型之间，不固定在列表底部。

## 4. 用户流程

### 4.1 切换模型并配置

```text
点击入口
  ↓
打开 Popover，仅展示模型列表
  ↓
当前模型在列表内保持选中样式，配置不展开
  ↓
点击一个可用模型
  ↓
立即更新列表选中状态
  ↓
在该模型行下展开内嵌配置
  ↓
恢复该模型上次有效的 Reasoning effort / Fast
  ↓
用户按需调整配置，立即保存
  ↓
Popover 保持打开，点击外部或按 Esc 关闭
```

### 4.2 点击当前已选模型

若用户点击当前已经选中的模型：

- 不重复触发模型切换或持久化；
- 将该列表项的配置区域展开；
- 若其配置已展开，则保持展开，不将模型行当作折叠开关；
- 关闭配置需关闭 Popover，或选择另一个模型。

此规则避免同一模型行同时承担“选择”和“手风琴开关”两种相互冲突的语义。

### 4.3 切换到其他模型

当已有配置区域展开，用户点击另一模型时：

1. 目标模型立即进入 selected 状态；
2. 旧配置区域开始收起并淡出；
3. 新配置区域随列表重排移动到目标模型下方；
4. 恢复目标模型上次有效配置；
5. 新配置区域淡入；
6. Popover 保持打开。

若配置读取需要异步请求，应先使用缓存值；没有缓存时在新卡片内展示局部加载态，不阻塞模型选中。

## 7. 模型列表

### 7.1 列表规则

- 直接展示服务端返回且按产品规则排序后的完整模型列表；
- 不提供搜索、筛选或分组；
- 列表超过 Popover 可用高度时，仅模型列表内部滚动；
- 模型名称保持单行，超出后省略并提供 Tooltip；
- 不展示模型图标、描述、能力标签、价格、Context 或 Provider；
- 同一时刻只能有一个选中模型和一个展开配置区域；两者在选择完成后指向同一模型。

### 7.2 ModelRow 尺寸

| 属性 | 规范 |
| --- | --- |
| 行高 | 40 px |
| 水平内边距 | 10 px |
| 图标与文本间距 | 8 px |
| 圆角 | 8 px |
| 模型名称 | 14 px / Medium |
| 状态图标 | 16 px |

### 7.3 列表项状态

#### Default

- 透明背景；
- 模型名使用 `text-primary`；
- 左侧预留与选中图标等宽的 16 px 空间，避免状态切换时文本横向跳动。

#### Hover

- 使用 `surface-hover`；
- 鼠标指针为 pointer；
- 不提前显示配置区域。

#### Selected

- 左侧显示 check 图标；
- 背景使用 `accent-subtle`；
- 模型名使用 `text-primary` 或 `accent-foreground`；
- 可使用 2 px 左侧强调条，但强调条和 check 不应同时过重；默认以 check + 淡背景为主。

#### Selected + Expanded

- ModelRow 保持 selected 表现；
- 行底部与内嵌配置卡片之间间距为 4 px；
- 选中行与卡片在视觉上构成同一列表项，但不使用包围两者的重边框。

#### Disabled

- 文本和图标使用 `text-disabled`；
- 不显示 check，不响应选择；
- 右侧显示 `info` 图标；
- Hover 时不使用可点击强调色；
- Tooltip 展示不可用原因，例如“当前账号没有访问权限”或“当前额度不可用”。

不可用原因不直接占用列表行空间。

#### Loading / Refreshing

- 有缓存时继续展示缓存列表和选中状态；
- 后台刷新不清空列表、不关闭展开区域；
- 可在“选择模型”标签右侧显示 12 px 进度指示；
- 刷新失败时保留旧值，并使用非阻断提示。

## 8. 选中模型内嵌配置（ModelInlineConfig）

### 8.1 定位与语义

`ModelInlineConfig` 是所选模型列表项的扩展内容，不是独立设置卡片。因此：

- 必须紧跟在对应 `ModelRow` 之后；
- 必须位于该模型与下一模型之间；
- 不展示“GPT-5.6-Luna 配置”或“当前模型配置”等重复标题；
- 只呈现与该模型直接相关的二级配置；
- 切换模型后随对应列表项一起移动。

### 8.2 外观

| 属性 | 规范 |
| --- | --- |
| 外边距 | 左右 8 px、底部 6 px、顶部 4 px |
| 内边距 | 12 px |
| 圆角 | 10 px |
| 背景 | `surface-container-high`，与 Popover 背景形成一级层差 |
| 边框 | 可选 1 px `border-subtle`；暗色模式优先使用边框，亮色模式可仅用背景层差 |
| 阴影 | 无或极弱，不使用独立浮层阴影 |
| 内容间距 | 12 px |

卡片需与模型行保持从属关系：视觉重量低于选中模型行，高于普通列表背景。

### 8.3 内容结构

```text
ModelInlineConfig
├── ReasoningField
│   ├── FieldLabel：思考程度
│   └── ReasoningSegmentControl
├── Divider（可选）
├── FastRow
│   ├── FastLabel（闪电 + Fast）
│   └── Switch
└── CompatibilityAlert（仅冲突或自动调整时显示）
```

## 9. Reasoning effort 控件

### 9.1 控件形式

Reasoning effort 使用单选 Segmented Control，不使用 ChoiceChip、下拉框或一组无关联按钮。

```text
思考程度
┌──────┬──────┬──────┬──────┐
│  低  │  中  │  高  │ 极高 │
└──────┴──────┴──────┴──────┘
```

仅展示当前模型支持的档位。若产品要求保持固定位置，可显示不支持档位为 disabled，但不得允许选择。

### 9.2 尺寸

| 属性 | 规范 |
| --- | --- |
| 字段标签 | 12 px / Medium / `text-secondary` |
| 标签与控件间距 | 8 px |
| 控件高度 | 32 px |
| 控件宽度 | 填满卡片内容区 |
| 单项最小宽度 | 48 px，剩余空间等分 |
| 外层圆角 | 8 px |
| 内边距 | 3 px |
| 选中滑块圆角 | 6 px |

### 9.3 状态

| 状态 | 表现 |
| --- | --- |
| Default | 透明或弱背景，`text-secondary` |
| Hover | 单项背景轻微提高 |
| Selected | 实色 pill / `surface-raised`，文字提高对比度 |
| Focus | 控件整体或当前单项显示焦点环 |
| Disabled | 降低对比度，无 hover |
| Saving | 保持选择结果；必要时在字段标签右侧显示微型进度，不锁死整个卡片 |

### 9.4 交互

- 点击立即更新本地状态和入口摘要；
- 立即触发持久化，不需要“确定”按钮；
- 键盘左右方向键在可用档位间移动；
- Space / Enter 选择当前聚焦档位；
- 选中 pill 在档位间平滑滑动，规范见第 11 节。

## 10. Fast 控件

### 10.1 布局

Fast 使用紧凑 Feature Row，不再嵌套第二张卡片。

```text
⚡ Fast                                  [开关]
```

| 属性 | 规范 |
| --- | --- |
| 行高 | 36 px |
| 图标 | 14 px |
| 图标与标题间距 | 6 px |
| 标题 | 13 px / Medium |
| Switch | 使用系统/设计系统紧凑尺寸，触控热区不小于 32 × 32 px |

V1 不展示“快速响应模式”等固定说明文案，以控制卡片高度。需要解释时使用 Tooltip。

### 10.2 状态与语义

- Off：入口不显示闪电；卡片内 Switch 为关闭；
- On：入口显示闪电；卡片内闪电使用强调色，Switch 为开启；
- Unsupported：整行 disabled，Tooltip 说明“该模型不支持 Fast”；
- Temporarily unavailable：整行 disabled，Tooltip 展示服务端返回的可理解原因；
- Saving：Switch 保持乐观更新后的状态，不使用整卡遮罩。

### 10.3 与 Reasoning effort 的兼容性

若 Fast 与某一 Reasoning effort 组合不兼容，不自动修改用户的另一项选择，也不只使用 Toast 提示。冲突应在当前内嵌卡片中通过 Inline Alert 解决：

- 当 Reasoning effort 为“极高”且用户尝试开启 Fast 时：Fast 保持关闭，Reasoning effort 保持“极高”；显示操作“切换到高并开启 Fast”。
- 当 Fast 已开启且用户尝试切换到“极高”时：当前有效配置保持不变；显示操作“关闭 Fast 并切换到极高”。
- 用户点击 Inline Alert 的操作后，两项配置作为一次原子更新提交；成功后同步更新入口摘要并移除 Alert。
- 用户继续选择其他兼容档位或关闭 Popover时，Alert 自动移除。

示例：

```text
⚠ Fast 与“极高”不兼容
  [切换到高并开启 Fast]
```

这种处理保证用户明确知道系统将修改哪两项配置，并避免静默自动降级。

## 11. 动画与过渡规范

### 11.1 动画原则

- 动画服务于“配置属于哪个模型”的空间理解；
- 选中反馈必须先于或同时于内容展开，不得让用户等待动画后才看到选择结果；
- Popover 顶边与入口锚点保持稳定；
- 禁止通过全列表淡出重绘来切换模型；
- 尊重系统 `reduce motion` 设置。

### 11.2 首次展开

用户点击模型后：

| 属性 | 规范 |
| --- | --- |
| 容器尺寸 | 高度从 0 过渡到内容高度 |
| 内容透明度 | 0 → 1 |
| 内容位移 | Y -4 px → 0 |
| 时长 | 180 ms |
| 曲线 | `easeOutCubic` |
| 延迟 | 透明度可延迟 30 ms，避免内容在空间尚未展开时拥挤 |

动画期间卡片内容不接受重复点击；ModelRow 与其他模型行仍可响应新的模型选择，新的选择将中断并接管当前过渡。

### 11.3 模型切换

从模型 A 切换至模型 B 时采用协调式过渡：

1. **0 ms**：B 立即显示 selected；A 取消 selected；
2. **0–80 ms**：A 的卡片内容 opacity 1 → 0；
3. **0–180 ms**：A 卡片收起，列表项通过布局动画移动；
4. **40–180 ms**：B 卡片展开，内容 opacity 0 → 1、Y -4 px → 0；
5. **180 ms**：聚焦状态进入 B 的配置区域或保留在 B 的 ModelRow，取决于输入方式。

视觉上应表现为“扩展内容从 A 迁移到 B”，而不是先完整收起、停顿、再完整展开。总时长控制在 180–220 ms 内。

### 11.4 Reasoning 选中滑块

| 属性 | 规范 |
| --- | --- |
| 位移/宽度过渡 | 150 ms |
| 曲线 | `easeOutCubic` |
| 文字颜色 | 100 ms linear |

### 11.5 Popover 打开与关闭

- 打开：opacity 0 → 1，scale 0.98 → 1，150 ms `easeOutCubic`；
- 关闭：opacity 1 → 0，scale 1 → 0.98，100 ms `easeInCubic`；
- chevron 同步旋转 180°；
- 不在打开动画中逐项延迟模型行，避免降低操作速度。

### 11.6 Reduce motion

系统启用减少动态效果时：

- 移除 scale、位移和滑块移动；
- 仅保留不超过 80 ms 的淡入淡出，或直接切换；
- 保持选中状态、焦点与内容顺序不变。

## 12. 滚动、定位与高度变化

### 12.1 内部滚动

- Popover 超过最大高度时，`ModelList` 成为唯一垂直滚动容器；
- “选择模型”标签可固定在顶部，也可随列表滚动；V1 推荐固定，便于维持上下文；
- 内嵌配置卡片属于列表流，不悬浮、不吸顶。

### 12.2 自动可见

配置展开完成后，应确保：

- 被选中的 ModelRow 完整可见；
- 配置卡片至少完整展示 Reasoning control 和 Fast row；
- 若空间不足，使用最小必要距离的平滑滚动；
- 用户使用鼠标滚轮期间，不主动抢夺滚动位置。

### 12.3 锚点稳定

Popover 默认优先显示在入口上方或下方的可用空间较大一侧；一旦打开，在本次会话中不因配置展开而切换方向。空间不足由内部滚动解决。

## 13. 系统状态与反馈

### 13.1 Agent 运行中

用户可以在 Agent 运行中修改配置，但修改仅对下一次新回合生效。

Popover 顶部显示轻量状态 Banner：

```text
配置将在下一回合生效
```

规范：

- 位于“选择模型”标签之前；
- 使用信息色，不使用警告色；
- 高度 32–36 px；
- 不阻止模型选择或配置编辑；
- Agent 空闲后自动移除。

入口 Tooltip 同步说明生效时机。

### 13.2 初始化与后台刷新

- 有缓存：立即展示缓存配置，后台刷新；
- 无缓存：入口展示安全默认值或骨架，Popover 局部加载；
- 刷新期间不清空入口、不重置选中模型、不折叠已展开配置；
- 服务端返回新列表时，尽可能按 `modelId` 保留选中和展开状态。

### 13.3 保存成功

常规成功不显示 Toast。入口与 Popover 的状态变化即为主要反馈。

### 13.4 保存失败

- 回滚到最近一次服务端确认的有效配置；
- 入口和卡片同步回滚，避免状态不一致；
- 在对应卡片内显示 Inline Error；
- 提供“重试”，但不关闭 Popover；
- 若模型切换保存失败，恢复原 selectedModelId 和其配置展开位置。

### 13.5 当前模型失效

若刷新后当前模型被移除或不可用：

1. 根据服务端规则选择默认可用模型；
2. 在列表中更新选中状态；
3. 不自动展开配置；
4. 显示一次非阻断提示说明发生了自动切换。

## 14. 配置继承与持久化

### 14.1 模型级配置

每个模型维护最近一次有效配置：

```text
ModelPreference
├── modelId
├── reasoningEffort
├── fastEnabled
├── serviceTierId
├── updatedAt
└── version
```

切换模型时，优先恢复该模型上次有效配置；若不存在历史配置，则使用服务端默认值。

### 14.2 有效性校验

恢复配置前需根据最新 capability 重新校验：

- Reasoning effort 是否仍受支持；
- Fast 是否仍可用；
- Reasoning effort 与 Fast 的组合是否合法。

无效历史值不得直接渲染为可用状态，应按服务端默认或产品兼容规则归一化后再展示。

### 14.3 更新时机

- 模型选择：点击可用 ModelRow 后立即更新本地状态并持久化；
- Reasoning effort：选择后立即更新并持久化；
- Fast：切换后立即更新并持久化；
- 不提供额外提交按钮；
- 同一模型的快速连续修改应合并或取消过期请求，最终以最后一次用户选择为准。

## 15. 键盘与无障碍

### 15.1 键盘导航

| 按键 | 行为 |
| --- | --- |
| Enter / Space（入口） | 打开 Popover |
| Esc | 关闭 Popover，焦点返回入口 |
| ↑ / ↓（模型列表） | 在可用模型行间移动焦点，可跳过 disabled 项 |
| Enter / Space（模型行） | 选中并展开该模型配置 |
| Tab | 从展开模型行进入 Reasoning control，再进入 Fast Switch |
| ← / →（Reasoning） | 切换可用档位 |
| Space（Fast） | 开关 Fast |
| Home / End | 跳到首个/最后一个可用模型 |

模型切换后，不应强制将键盘焦点跳入卡片。使用键盘选择时，焦点默认停留在目标 ModelRow，用户按 Tab 进入配置；使用鼠标选择时，不显示持续焦点环。

### 15.2 语义

- Popover 使用 `dialog` 或符合设计系统的非模态浮层语义；
- 模型列表使用单选列表语义（`listbox` + `option` 或等价 Flutter Semantics）；
- `selectedModelId` 通过 `selected` 语义暴露；
- 展开配置与模型行通过可访问名称或 `controls` 关系关联；
- Reasoning Segmented Control 暴露为 radio group；
- Fast 暴露为 switch，并包含模型上下文，例如“GPT-5.6-Luna，Fast，已开启”。

### 15.3 视觉可访问性

- 不只依赖背景色表达选中，同时使用 check 图标和语义；
- 文本与背景满足 WCAG AA 对比度；
- 焦点环与边框不得被裁切；
- Tooltip 不作为唯一的关键错误反馈，但可用于不可用原因和补充说明。

## 16. Flutter 组件结构

### 16.1 推荐组件树

```text
AgentModelConfig
├── ModelConfigTrigger
└── ModelConfigPopover
    ├── NextTurnBanner（条件渲染）
    ├── ModelListLabel
    └── ModelSelectorList
        └── ModelListItem × N
            ├── ModelRow
            └── AnimatedModelExpansion
                └── ModelInlineConfig
                    ├── ReasoningField
                    │   └── ReasoningSegmentControl
                    ├── FastRow
                    │   └── FastSwitch
                    └── CompatibilityAlert / InlineError（条件渲染）
```

### 16.2 组件职责

#### AgentModelConfig

- 协调入口与 Popover；
- 持有或订阅 `selectedModelId`、`expandedModelId` 和保存状态；
- 处理打开、关闭、外部点击与焦点恢复。

#### ModelConfigTrigger

- 展示当前有效模型、Reasoning effort 和 Fast 状态；
- 处理文本截断、Tooltip、焦点与打开状态；
- 不负责模型或配置数据请求。

#### ModelConfigPopover

- 提供浮层定位、最大高度、滚动边界和运行中 Banner；
- 每次打开时将 `expandedModelId` 初始化为 `null`；
- 不渲染搜索框或独立当前模型 Header。

#### ModelSelectorList

- 渲染模型列表和键盘 roving focus；
- 根据 `selectedModelId` 渲染选中状态；
- 根据 `expandedModelId` 将配置插入对应项内部；
- 负责展开后的自动可见与滚动位置。

#### ModelListItem

- 由 `ModelRow` 与条件渲染的扩展内容组成；
- 使用稳定 `ValueKey(model.id)`，避免切换时状态错位；
- Disabled 项仅展示不可用状态和 Tooltip。

#### ModelInlineConfig

- 不展示模型名或“配置”标题；
- 接收明确的 `modelId` 和已归一化配置；
- 组合 Reasoning、Fast、兼容性提示和局部错误；
- 不直接决定自己插入列表的位置。

### 16.3 状态模型

```dart
class AgentModelConfigUiState {
  final String? selectedModelId;
  final String? expandedModelId;
  final String? selectedReasoningEffort;
  final String? selectedServiceTierId;
  final List<AgentModelInfo> models;
  final Map<String, AgentModelPreference> preferences;
  final Set<String> savingModelIds;
  final bool isRefreshing;
  final bool appliesNextTurn;
  final AgentModelCompatibilityConflict? compatibilityConflict;
  final AgentModelSelectionSaveError? saveError;
  final String? selectionNotice;
  final String? refreshError;
}
```

约束：

```text
Popover closed:
  expandedModelId = null

Popover opened initially:
  selectedModelId = current model
  expandedModelId = null

After selecting model X:
  selectedModelId = X
  expandedModelId = X
```

### 16.4 动画实现建议

推荐组合：

- `AnimatedSize`：列表项扩展高度；
- `AnimatedSwitcher`：配置内容按 `modelId` 切换；
- `FadeTransition` + `SlideTransition`：卡片内容进入/退出；
- 自定义 `AnimatedContainer` 或设计系统 Segmented Control：Reasoning 选中滑块；
- `Scrollable.ensureVisible`：展开后保证关键控件可见。

示意代码：

```dart
class ModelListItem extends StatelessWidget {
  const ModelListItem({
    required this.model,
    required this.selected,
    required this.expanded,
    required this.onSelect,
    super.key,
  });

  final ModelOption model;
  final bool selected;
  final bool expanded;
  final VoidCallback onSelect;

  @override
  Widget build(BuildContext context) {
    return Column(
      key: ValueKey(model.id),
      mainAxisSize: MainAxisSize.min,
      children: [
        ModelRow(
          model: model,
          selected: selected,
          onPressed: model.enabled ? onSelect : null,
        ),
        AnimatedSize(
          duration: const Duration(milliseconds: 180),
          curve: Curves.easeOutCubic,
          alignment: Alignment.topCenter,
          child: expanded
              ? ModelInlineConfig(
                  key: ValueKey('config-${model.id}'),
                  modelId: model.id,
                )
              : const SizedBox.shrink(),
        ),
      ],
    );
  }
}
```

实际实现需补充淡入淡出、减少动态效果、请求竞态处理和语义，不应只依赖上述示意代码。

## 18. 验收标准

### 18.1 信息架构

- [x] Popover 中不存在模型搜索框。

- [x] 同一时刻最多存在一个内嵌配置区域。

- [x] Disabled 模型无法选择，并可通过 Tooltip 获取原因。

- [x] 保存失败时入口与卡片同步回滚并提供局部重试。

## 20. 结论

最终方案采用 **模型列表优先 + 选中项内嵌展开配置（Inline Expansion）**：模型选择是 Popover 的第一任务，Reasoning effort 与 Fast 作为所选模型的二级内容直接出现在该模型下方。该方案减少了独立 Header、搜索框和底部配置区带来的视觉重量，通过明确的空间归属和连续动画，提升选择效率、信息层级和操作可理解性，同时保留原有的 Fast 语义、模型级配置继承、缓存刷新、不可用模型与下一回合生效等业务规则。
