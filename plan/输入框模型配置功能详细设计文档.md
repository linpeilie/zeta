# Zeta 输入框模型配置功能详细设计文档

版本：V1.1  
状态：第二阶段定稿  
适用范围：Flutter Desktop Agent 输入框  
功能范围：模型、Reasoning effort、Fast  
目标读者：产品、交互设计、视觉设计、Flutter 开发、Provider/协议开发、测试

---

## 0. 决策摘要与事实边界

### 0.1 已确认决策

1. 使用 provider 中立的统一模型配置组件。
2. 模型、Reasoning effort 和 Fast 合并为一个收起入口。
3. Reasoning effort 直接展示可选档位，不展示档位说明。
4. 闪电只表达“Fast 已启用”，并同时显示在收起入口和 Popover 中。
5. Fast 必须由 provider 通过 isFastTier 显式声明，不允许客户端根据 tier ID 或名称猜测。
6. 切换模型时优先恢复该模型上次有效配置。
7. 配置修改立即生效并持久化，Popover 保持打开。
8. Agent 运行中允许修改，但界面只承诺新配置对下一次新回合生效。
9. 不规定所有 provider 通用的 steer 配置继承规则。
10. Fast 与 Reasoning effort 不兼容时提供明确反馈和兼容档位快捷操作。
11. 模型超过 8 个时显示搜索；V1 不加入最近使用、推荐或收藏。
12. 无权限、限额耗尽或暂时不可用的模型保留在列表中并禁用。
13. 不可用原因不直接占用列表空间，通过鼠标悬浮、键盘聚焦和屏幕阅读器提供。
14. 模型选择和每模型偏好按 provider 全局保存，不按项目或 thread 区分。
15. V1 不依赖模型简介、价格、上下文长度或能力标签，因为暂无稳定数据来源。
16. 所有新增文案进入 Zeta 中文本地化规划。
17. 没有任何可用模型时完全禁止发送，不允许静默回退服务端默认模型。

### 0.2 明确假设

以下内容尚未由 provider 协议事实确认，本文作为设计假设处理：

- 如果 provider 声明了 Fast tier，但没有提供 Reasoning effort 兼容矩阵，暂时假设该 Fast tier 与该模型所有可用 Reasoning effort 兼容。
- 如果不可用模型没有返回具体原因，Tooltip 使用通用文案“当前不可用”。
- V1 假设每个模型最多存在一个 isFastTier=true 的服务档位。
- 中文名称“思考强度”为推荐翻译，最终名称仍需经过本地化文案评审。
- 当前模型配置在 provider 内全局共享，因此同一 provider 的多个 thread 不保留各自独立配置。

## 1. 背景、目标与非目标

### 1.1 背景

当前 Zeta 输入框将以下能力拆成多个同级胶囊入口：

- Model；
- Reasoning effort；
- Service tier/Fast；
- 其他权限或 session 配置。

它们在视觉上互相独立，但模型、Reasoning effort 和 Fast 实际属于同一份模型选择状态。当前界面还存在以下问题：

- 用户容易误以为三者可以完全独立组合；
- Reasoning effort 可能直接展示 provider 返回的完整说明句，占用大量空间；
- 用户需要分别打开多个 Popover；
- Fast 已选中后缺少清晰的关闭入口；
- 模型切换会恢复默认值，不能记住每个模型上次的偏好；
- 模型加载失败时，模型入口可能直接消失；
- 不可用模型、无权限、限额和能力兼容关系尚无完整产品规则。

### 1.2 设计目标

- 用户无需展开 Popover，即可识别当前模型。
- 用户无需展开 Popover，即可看到当前 Reasoning effort。
- Fast 开启时，用户可从收起入口一眼识别。
- 在一个 Popover 中完成模型、Reasoning effort 和 Fast 配置。
- 清楚表达 Reasoning effort 与 Fast 均从属于当前模型。
- 切换模型时恢复该模型上次有效配置。
- 覆盖加载、错误、不可用、限额和动态能力变化。
- 在窄窗口、深色模式和大文字缩放下保持紧凑、可读、无溢出。
- 为未来扩展保留数据与组件位置，但不在 V1 提前展示无可靠来源的信息。

### 1.3 非目标

- 不重构 provider 选择入口。
- 不把审批、沙箱、权限策略或普通 session 配置合并进模型 Popover。
- 不提供模型收藏、最近使用和智能推荐。
- 不展示模型价格、上下文长度、图像、工具调用或质量标签。
- 不展示 Reasoning effort 的速度、质量和费用说明。
- 不在客户端根据模型名称猜测能力或分组。
- 不改变当前已经运行的 Agent 回合。
- 不为各个 thread 保存独立模型配置。
- 不允许在无可用模型时使用未知默认模型继续发送。

## 2. 用户场景与核心任务

### 2.1 发送前确认配置

用户准备发送任务，希望确认当前模型、当前 Reasoning effort，以及是否开启 Fast。

成功标准：无需打开 Popover 即可读取全部当前配置。

### 2.2 快速切换模型

用户根据任务类型选择另一个模型。

成功标准：

- 只需打开一个 Popover；
- 选择模型后自动恢复该模型上次有效配置；
- 不需要再次设置 Reasoning effort 和 Fast；
- Popover 不自动关闭。

### 2.3 只修改 Reasoning effort

用户保留当前模型，只调整 Reasoning effort。

成功标准：

- 直接看到所有可选档位；
- 不需要阅读说明；
- 修改后收起入口立即更新；
- Popover 保持打开。

### 2.4 开启或关闭 Fast

成功标准：

- Fast 开启时，收起入口和 Popover 都显示闪电；
- Fast 关闭时，两处都不显示闪电；
- 支持 Fast 但尚未开启时，不显示闪电；
- 用户可以明确切回 Fast Off。

### 2.5 运行中准备下一回合

Agent 正在运行，用户希望提前配置下一次新回合。

成功标准：

- 配置入口保持可用；
- Popover 明确显示“下次新回合生效”；
- 当前回合不受影响；
- steer 的实际配置语义交给 provider，不在 UI 中作统一承诺。

### 2.6 模型不可用

模型无权限、限额耗尽、暂时下线或受到工作区限制。

成功标准：

- 模型仍可被发现；
- 模型行不可选择；
- 原因不直接占用列表空间；
- 鼠标悬浮、键盘聚焦和屏幕阅读器均可获得原因。

### 2.7 没有可用模型

Provider 返回的模型全部不可用，或模型列表为空。

成功标准：

- 发送按钮完全禁用；
- 界面解释原因；
- 用户可以重试或前往 provider 设置；
- 不静默降级到未知默认模型。

## 3. 设计原则

### 3.1 以模型为配置主体

模型是一级对象，Reasoning effort 和 Fast 是所选模型的二级配置。

### 3.2 状态和能力严格区分

- 闪电表示 Fast 已启用；
- isFastTier 表示某个服务档位具备 Fast 语义；
- 支持 Fast 但未开启时不显示闪电。

### 3.3 收起状态只展示当前结果

入口只展示用户当前真正会使用的配置，不展示候选能力、价格或说明。

### 3.4 修改即时、结果可预期

- 修改立即反馈；
- Popover 不因选择而关闭；
- 自动回退或自动关闭 Fast 时必须通知用户；
- 异步旧结果不得覆盖新选择。

### 3.5 不展示不可信信息

没有稳定数据来源的模型简介、价格和能力标签不进入 V1。

### 3.6 紧凑但不依赖猜测

允许省略长文字，但不使用含义不明确的单字母或纯颜色状态。

### 3.7 延续 Zeta 设计系统

实现必须使用 Graphite 语义令牌和现有 ui/core 原语，不引入独立视觉体系。

## 4. 信息架构

    模型配置
    ├── 收起入口
    │   ├── 当前模型
    │   ├── 当前 Reasoning effort
    │   ├── Fast 已启用状态
    │   └── 展开箭头
    └── Popover
        ├── 全局状态区
        │   ├── 下次新回合生效
        │   ├── 加载/刷新状态
        │   └── 错误或自动调整提示
        ├── 模型选择区
        │   ├── 搜索（模型数量 > 8）
        │   ├── 模型名称
        │   ├── 默认标记
        │   ├── 当前选中状态
        │   └── 可用/不可用状态
        └── 当前模型配置区
            ├── Reasoning effort
            ├── Fast
            └── 兼容性反馈

### 4.1 信息层级

一级：当前模型。  
二级：当前模型的 Reasoning effort 和 Fast。  
三级：加载、不可用、兼容性和持久化反馈。

### 4.2 V1 模型列表信息

模型行只展示：

- 模型名称；
- 当前选中状态；
- 默认模型标记；
- 可用或禁用状态图标。

不展示：

- 模型简介；
- 能力标签；
- Fast 支持标签；
- 价格；
- 上下文长度；
- 图像或工具调用能力。

## 5. 收起状态布局与信息优先级

### 5.1 标准布局

    Fast 开启：
    [ GPT‑5.6‑Luna · Medium ⚡ ⌄ ]

    Fast 关闭：
    [ GPT‑5.6‑Luna · Medium ⌄ ]

中文本地化示例：

    [ GPT‑5.6‑Luna · 中 ⚡ ⌄ ]

### 5.2 排列顺序

1. 模型名称；
2. 分隔点；
3. Reasoning effort；
4. Fast 已启用闪电；
5. 展开箭头。

该顺序固定，不根据语言方向之外的条件变化。

### 5.3 信息优先级

| 优先级 | 内容 | 规则 |
|---|---|---|
| P0 | 模型名称 | 始终可见，可截断 |
| P1 | Fast 闪电 | Fast 开启时优先保留 |
| P2 | Reasoning effort | 空间不足时可隐藏 |
| P3 | 展开箭头 | 始终保留 |
| 不展示 | 通用模型图标 | 信息价值不足 |

### 5.4 尺寸与视觉

- 最小交互高度：28 logical pixels。
- 使用一个统一胶囊。
- 模型名称使用主要文字权重。
- Reasoning effort 使用次级文字色。
- 闪电使用 accent 语义色，不使用 warning。
- 展开时使用现有 IdeChip 的 selected/open 层级。
- 展开箭头可随开关状态旋转。
- 不使用原始颜色值或临时圆角。

### 5.5 响应式降级

| 入口可用宽度 | 展示内容 |
|---|---|
| ≥180px | 模型、Reasoning effort、闪电、箭头 |
| 128–179px | 截断模型、Reasoning effort、闪电、箭头 |
| 96–127px | 截断模型、闪电、箭头 |
| <96px | 保持最小 96px，并进入输入区现有横向滚动区域 |

规则：

- Fast 开启时，闪电优先于 Reasoning effort 保留。
- 不使用 M、H 等可能含义不明确的单字母缩写。
- 隐藏的信息仍需进入 Tooltip 和辅助语义。

### 5.6 Tooltip

入口统一 Tooltip：

    GPT‑5.6‑Luna
    思考强度：中
    Fast：已开启

运行中修改后增加：

    下次新回合生效

模型名称被截断时，Tooltip 必须使用完整名称。

## 6. Popover 整体结构

### 6.1 宽窗口结构

    ┌────────────────────── 模型配置 ───────────────────────┐
    │ 下次新回合生效                                         │
    │                                                       │
    │ ┌──────────── 模型 ────────────┐ ┌─ GPT‑5.6‑Luna 配置 ┐│
    │ │ [ 搜索模型… ]                │ │                    ││
    │ │                              │ │ 思考强度           ││
    │ │ ✓ GPT‑5.6‑Luna       默认    │ │ [低] [中] [高]     ││
    │ │   GPT‑5.4‑Mini               │ │ [极高]             ││
    │ │   GPT‑Legacy          ⓘ      │ │                    ││
    │ │   GPT‑Offline         ⓘ      │ │ ⚡ Fast      [开]  ││
    │ │                              │ │                    ││
    │ └──────── 可滚动 ──────────────┘ └──── 固定区域 ──────┘│
    └───────────────────────────────────────────────────────┘

状态图标仅表示存在不可用状态。原因通过悬浮、聚焦或屏幕阅读器提供，不直接显示在行内。

### 6.2 窄窗口结构

    ┌────────────── 模型配置 ──────────────┐
    │ [ 搜索模型… ]                        │
    │                                      │
    │ 模型                                 │
    │ ✓ GPT‑5.6‑Luna                默认   │
    │   GPT‑5.4‑Mini                       │
    │   GPT‑Legacy                    ⓘ    │
    │ ──────────────────────────────────── │
    │ GPT‑5.6‑Luna 配置                    │
    │                                      │
    │ 思考强度                             │
    │ [低] [中] [高] [极高]               │
    │                                      │
    │ ⚡ Fast                       [开]   │
    └──────────────────────────────────────┘

### 6.3 布局规则

- 可用宽度充足时使用左右两栏。
- 空间不足时切换为上下结构。
- 模型列表独立滚动。
- 配置区在正常缩放下保持可见。
- 文字放大导致内容无法容纳时，整个 Popover 可滚动。
- 模型超过 8 个时显示搜索。
- 模型不超过 8 个时不保留空搜索区域。

### 6.4 尺寸与定位

- 标准宽度：480px。
- 窄布局宽度：360–420px。
- 极窄窗口：viewport width - 16px。
- 最大高度：min(480px, viewport height - 24px)。
- 默认在输入框上方打开。
- 上方空间不足时允许向下翻转。
- 与入口保持约 6px 距离。
- 与窗口边缘至少保持 8–12px 间距。

### 6.5 不可用原因展示

不可用模型行：

- 使用禁用文字和状态图标；
- 不直接显示原因文字；
- 鼠标悬浮约 400–500ms 后显示 Tooltip；
- 键盘聚焦时显示同一 Tooltip；
- 语义标签直接包含原因；
- 不可用行仍可被方向键聚焦；
- Enter 或 Space 不改变模型选择。

## 7. 模型、Reasoning effort 和 Fast 完整交互规则

### 7.1 打开与关闭

| 触发条件 | 界面反馈 | 最终结果 |
|---|---|---|
| 点击入口 | 入口进入展开态，Popover 出现 | 当前模型滚动到可见区域 |
| Enter/Space | Popover 打开，焦点进入当前模型 | 可继续使用键盘配置 |
| 再次点击入口 | Popover 关闭 | 已完成修改保留 |
| 点击外部 | Popover 关闭 | 已完成修改保留 |
| 按 Esc | Popover 关闭，焦点返回入口 | 已完成修改保留 |
| 页面或 provider 被切换 | Popover 关闭 | 加载新 provider 的全局配置 |

点击外部关闭时应消费本次点击，避免误触底层按钮。

### 7.2 选择模型

| 触发条件 | 界面反馈 | 最终结果 |
|---|---|---|
| 点击可用模型 | 模型行选中，配置区立即刷新 | 恢复该模型上次有效配置 |
| 首次选择模型 | 配置区显示 provider 默认配置 | 默认配置立即持久化 |
| 点击已选模型 | 不重复写入 | 保持当前配置 |
| 点击不可用模型 | 不改变选中状态，显示不可用 Tooltip | 当前配置保持不变 |
| 保存失败 | 回滚原模型，显示统一 Toast | 失败模型不成为当前模型 |

选择模型后：

- Popover 不关闭；
- 焦点保持在该模型行；
- 收起入口立即更新；
- 当前 provider 的全局模型选择立即更新。

### 7.3 Reasoning effort

展示形式：

    思考强度

    [ 低 ] [ 中 ] [ 高 ] [ 极高 ]

规则：

- 只展示选项名称。
- 不展示档位说明。
- 不展示速度、质量和费用解释。
- 按 provider 返回顺序排列。
- provider 返回本地化显示名时优先使用。
- 标准 ID 可由本地化层映射。
- 当前项使用单选语义和选中状态。
- 选择后立即更新入口。
- 选择后 Popover 保持打开。
- 只有一个选项时显示单个只读选中项。
- 没有可配置 Reasoning effort 时不渲染该区块。

不可用 Reasoning effort：

- 选项保留并禁用；
- 行内不显示原因；
- 悬浮、聚焦和语义标签提供原因；
- 不展示能力描述。

### 7.4 Fast

支持且关闭：

    Fast                                      [关]

- 不显示闪电；
- 收起入口不显示闪电；
- 开关可操作。

支持且开启：

    ⚡ Fast                                   [开]

- Popover 显示闪电；
- 收起入口同步显示闪电；
- 辅助技术朗读“Fast，已开启”。

当前模型不支持 Fast：

    Fast                              当前模型不支持

- 不显示闪电；
- 开关禁用；
- 如果当前 provider 所有模型都不支持 Fast，整个 Fast 区块不显示；
- 不在模型列表中展示 Fast 支持标签。

只有满足以下条件时才将当前服务档位视为 Fast：

    selectedServiceTier.isFastTier == true

禁止使用以下推断方式：

- id == priority；
- 名称包含 fast；
- 固定 service tier 排序；
- 根据模型名称猜测。

如果 provider 没有返回 isFastTier，该 tier 不得以 Fast 形式展示。

### 7.5 Fast 与 Reasoning effort 不兼容

用户尝试开启 Fast：

    Fast 与“极高”不兼容。
    [切换到“高”并开启 Fast]

触发快捷操作后：

1. Reasoning effort 切换到 provider 返回的推荐兼容档位；
2. Fast 开启；
3. 两项作为一个事务保存；
4. 收起入口更新；
5. Popover 保持打开。

如果保存失败，两项同时回滚。

Fast 已开启，用户选择不兼容档位时：

1. 接受用户选择的新 Reasoning effort；
2. 自动关闭 Fast；
3. 立即移除收起入口和 Popover 中的闪电；
4. 显示 Toast：“极高”与 Fast 不兼容，Fast 已关闭。

不得静默关闭 Fast、静默改回旧 Reasoning effort，或阻止用户选择新的 Reasoning effort。

### 7.6 Agent 运行中

| 触发条件 | 界面反馈 | 最终结果 |
|---|---|---|
| 运行中打开 Popover | 顶部显示“下次新回合生效” | 允许继续配置 |
| 运行中修改模型 | 入口立即显示新模型 | 当前运行回合不改变 |
| 运行中修改 effort/Fast | 入口立即更新 | 下一次新回合使用新配置 |
| 发送 steer | 不显示统一继承承诺 | 实际行为由 provider 决定 |

“下次新回合生效”不应被解释为 steer 一定使用新配置。

### 7.7 没有可用模型

触发条件：

- 模型列表为空；或
- 所有模型均不可用；或
- 当前配置失效且找不到任何可用回退模型。

界面反馈：

    [ 没有可用模型  !  ⌄ ]

Popover：

    当前没有可用模型。
    [重试] [打开 Provider 设置]

最终结果：

- 发送按钮禁用；
- Enter 提交无效；
- 辅助技术朗读发送禁用原因；
- 不允许使用 provider 未知默认模型继续发送；
- 模型恢复可用后自动解除发送禁用。

## 8. 状态切换与配置继承规则

### 8.1 保存范围

配置按 provider 全局保存：

    Provider
    ├── currentModelId
    └── modelPreferences
        ├── modelA
        │   ├── reasoningEffort
        │   └── serviceTierId
        └── modelB
            ├── reasoningEffort
            └── serviceTierId

后果：

- 同一 provider 的不同项目共享当前选择；
- 同一 provider 的不同 thread 共享当前选择；
- 切换 thread 不恢复 thread 专属配置；
- 切换 provider 时恢复该 provider 自己的全局配置。

### 8.2 配置恢复优先级

    该模型上次保存且仍有效的配置
                    ↓
    该模型的 provider 默认配置
                    ↓
    第一个可用 Reasoning effort + 非 Fast 默认 tier
                    ↓
    没有有效配置：禁用发送

### 8.3 场景规则

| 场景 | 处理 |
|---|---|
| 切回曾使用模型 | 恢复该模型上次有效配置 |
| 首次选择模型 | 使用 provider 默认配置 |
| 上次 effort 已移除 | 回退默认 effort，并提示 |
| 上次 Fast tier 已移除 | 关闭 Fast，并提示 |
| 模型不再支持 Fast | 关闭 Fast，并提示 |
| 当前模型被移除 | 切换 provider 默认可用模型 |
| 默认模型不可用 | 选择第一个可用模型 |
| 所有模型不可用 | 禁止发送 |
| 应用重启 | 恢复最后一次成功持久化的配置 |
| provider 切换 | 恢复目标 provider 全局配置 |
| 能力刷新 | 保留有效字段，只修正失效字段 |

### 8.4 自动调整反馈

自动调整时显示一次性 Toast：

    原模型配置已不可用，已切换到默认配置。

如果仅调整单项，应具体说明：

    “极高”已不可用，已切换到“中”。

同一能力版本不得重复提示。

### 8.5 异步与并发

- 每次选择使用版本号或 token。
- 最后一次用户操作优先。
- 旧异步结果不得覆盖新状态。
- 乐观更新超过 300ms 时，在对应配置区显示紧凑进度。
- 失败时只回滚当前事务。
- 组合快捷操作必须整体成功或整体回滚。

## 9. 正常、悬停、选中、聚焦、禁用、加载、错误和空状态

| 状态 | 收起入口 | 模型列表 | 配置区 |
|---|---|---|---|
| 正常 | 中性边框和背景 | 普通文字 | 当前配置正常显示 |
| 悬停 | 背景轻微增强 | 行背景增强 | 控件 Hover |
| 展开 | accent 边框、箭头旋转 | 当前模型可见 | Popover 展开 |
| 选中 | 展示当前配置 | 选中背景＋勾选 | 当前 effort/Fast 选中 |
| 聚焦 | 明确 focus ring | 聚焦边框 | 聚焦控件有 ring |
| 按下 | 短暂按压反馈 | 行背景加深 | 开关/选项按压反馈 |
| 禁用 | tertiary 文字 | 禁用颜色＋状态图标 | 控件不可操作 |
| 加载 | 缓存值＋进度 | 保留旧列表 | 显示刷新状态 |
| 首次加载 | 正在加载模型 | 骨架或进度 | 暂不显示 |
| 错误 | 错误图标 | 保留缓存列表 | 错误横幅＋重试 |
| 空状态 | 没有可用模型 | 空状态 | 重试/设置入口 |
| 同步中 | 新值立即显示 | 新模型选中 | 对应字段显示紧凑进度 |
| 自动调整 | 显示新有效值 | 新模型选中 | Toast 说明原因 |

### 9.1 加载策略

有缓存：

- 立即展示缓存配置；
- 后台刷新；
- 不清空入口；
- 不在刷新期间禁用发送，除非缓存配置已知不可用。

无缓存：

    [ 正在加载模型… ]

- 入口暂时不可配置；
- 发送按钮禁用；
- 加载成功后恢复正常状态。

### 9.2 加载失败

有可用缓存：

- 保留缓存配置；
- Popover 顶部显示刷新失败；
- 提供重试；
- 允许继续发送。

无可用缓存：

- 入口进入错误态；
- 发送按钮禁用；
- 提供重试和 Provider 设置入口。

### 9.3 不可用状态

列表不直接显示原因文字。

视觉上使用：

- 禁用文字；
- 状态图标；
- 不可点击光标；
- 无 Hover 选择背景。

原因通过：

- Tooltip；
- 键盘焦点提示；
- 屏幕阅读器语义描述。

## 10. 边界场景

### 10.1 长模型名称

- 单行省略号；
- Reasoning effort、Fast 闪电和箭头不能被挤出；
- Tooltip 展示完整名称；
- 屏幕阅读器朗读完整名称；
- Popover 模型行不换成多行描述。

### 10.2 多模型

- ≤8：不显示搜索；
- >8：显示搜索；
- 使用 builder/虚拟列表；
- 支持分页或增量加载；
- 搜索匹配模型名称和 provider 明确提供的别名；
- 不根据模型能力搜索，因为 V1 没有可靠能力数据。

无结果：

    没有匹配的模型。
    [清除搜索]

### 10.3 小窗口

- 从左右两栏切换为上下布局；
- 模型入口保持一个整体；
- 不重新拆成三个选择器；
- Popover 不超出窗口；
- 输入工具栏继续支持现有横向滚动。

### 10.4 深色模式

- 所有颜色来自 IdeColors；
- Fast 使用 accent，不使用固定黄色；
- 禁用、选中、悬停和聚焦保持可区分；
- 不仅依靠色相表达状态；
- 不使用 feature 内自定义阴影和原始颜色值。

### 10.5 大文字和缩放

- 支持 200% 文字缩放；
- Reasoning effort 可换行；
- Popover 必要时整体滚动；
- 控件不能被裁切；
- Tooltip 文案允许换行；
- 可点击区域不因视觉压缩而小于最小尺寸。

### 10.6 单一或无 Reasoning effort

只有一个：

- 显示单个只读选中项；
- 收起入口仍展示当前值。

没有：

- 不渲染 Reasoning effort 区块；
- 收起入口只显示模型、Fast 和箭头。

### 10.7 多个服务档位

V1 只把 isFastTier=true 的档位映射为 Fast。

如果未来出现多个 Fast tier、多个互斥服务档位或非 Fast 的可配置服务档位，则升级为服务档位选择器，不增加多个 Fast 开关。

### 10.8 能力动态变化

- 刷新期间保留旧状态；
- 新能力到达后校验当前配置；
- 有效配置无提示；
- 失效配置按继承规则回退；
- 无可用模型时立即禁用发送。

### 10.9 无模型能力元数据

由于暂无稳定来源：

- V1 不展示模型能力差异说明；
- 不展示速度、质量、价格和上下文长度；
- 不根据模型名称推断能力；
- 未来数据契约稳定后，通过模型详情区扩展，不改动收起入口结构。

## 11. 键盘操作与可访问性要求

### 11.1 键盘操作

| 按键 | 行为 |
|---|---|
| Tab / Shift+Tab | 在入口和 Popover 控件间移动 |
| Enter / Space | 打开入口或激活当前控件 |
| Esc | 关闭 Popover 并返回入口 |
| ↑ / ↓ | 在模型列表中移动 |
| Home / End | 移动到首个或末个模型 |
| ← / → | 在 Reasoning effort 中移动 |
| Space | 切换 Fast |
| Cmd/Ctrl+F | 模型超过 8 个时聚焦搜索 |
| Enter on model | 选择模型，不关闭 Popover |
| Enter on disabled model | 不选择，展示不可用原因 |

### 11.2 焦点规则

- 打开后聚焦当前模型。
- 当前模型自动滚动到可见区域。
- 选择模型后焦点保持在该行。
- 配置区刷新不得抢焦点。
- 不可用模型仍可聚焦，以便获取原因。
- 关闭后焦点返回入口。
- Popover 内保持合理焦点循环。

### 11.3 语义标签

收起入口示例：

    模型配置，
    GPT‑5.6‑Luna，
    思考强度中，
    Fast 已开启，
    已收起。

不可用模型示例：

    GPT‑Legacy，
    不可用，
    原因：当前账户没有权限。

Fast：

    Fast，开关，已开启。

### 11.4 不依赖颜色或悬浮

虽然不可用原因不直接显示在列表中，但必须同时支持：

- 鼠标悬浮；
- 键盘聚焦；
- 屏幕阅读器。

移动焦点到不可用项时，Tooltip 或等价的可视提示必须出现。

### 11.5 对比度与目标尺寸

- 正文文字对比度至少 4.5:1。
- 焦点环、边框和关键控件至少 3:1。
- 交互目标最小 28×28 logical pixels。
- 选中状态同时使用背景和勾选。
- Fast 同时使用闪电和语义状态。

## 12. 文案、图标和 Tooltip 建议

### 12.1 本地化要求

所有文案必须通过 Zeta 本地化资源提供，不在组件中硬编码。

以下翻译为推荐方案，尚待本地化文案评审：

| Key | English | 简体中文 |
|---|---|---|
| modelConfig.title | Model configuration | 模型配置 |
| modelConfig.models | Models | 模型 |
| modelConfig.reasoningEffort | Reasoning effort | 思考强度 |
| modelConfig.fast | Fast | Fast |
| modelConfig.appliesNextTurn | Applies to next turn | 下次新回合生效 |
| modelConfig.loading | Loading models… | 正在加载模型… |
| modelConfig.unavailable | Currently unavailable | 当前不可用 |
| modelConfig.noModels | No models available | 没有可用模型 |
| modelConfig.retry | Retry | 重试 |
| modelConfig.openProviderSettings | Open provider settings | 打开 Provider 设置 |
| modelConfig.defaultModel | Default | 默认 |
| modelConfig.fastDisabled | Fast was turned off | Fast 已关闭 |

标准 effort 推荐映射：

| ID | English | 简体中文 |
|---|---|---|
| low | Low | 低 |
| medium | Medium | 中 |
| high | High | 高 |
| xhigh | XHigh | 极高 |

Provider 自定义 effort 应返回展示名称或本地化 key；否则显示原始 ID。

### 12.2 图标规则

- 模型配置入口：不显示通用模型图标。
- 当前模型：列表中使用勾选。
- 默认模型：使用文字标记。
- Fast 已开启：使用闪电。
- Fast 支持但未开启：不显示闪电。
- 不可用：使用中性状态图标。
- 错误：使用警告图标和文字。
- 加载：使用统一紧凑进度指示器。
- 不引入模型品牌图标。

### 12.3 Tooltip 规则

应该使用：

- 完整当前配置；
- 被截断的模型名称；
- 不可用原因；
- 禁用 Reasoning effort 原因；
- 错误和状态图标含义。

不应该使用：

- Low、Medium、High、XHigh 的能力解释；
- 模型价格或质量描述；
- 已经直接显示的普通标签；
- 必须立即看到的兼容性错误。

Fast 不兼容属于当前配置错误，应直接显示在配置区，不应只放在 Tooltip。

## 14. 埋点与效果衡量指标

### 14.1 推荐事件

| 事件 | 属性 |
|---|---|
| model_config_opened | provider、current_model、model_count、layout、turn_running |
| model_config_closed | close_reason、duration、change_count |

| model_list_loaded | duration、status、model_count |
| model_config_retry | previous_error、result |

### 14.2 隐私规则

不得记录：

- 搜索原文；
- 用户 Prompt；
- provider 原始错误载荷；
- 账号、权限令牌或密钥；
- 不必要的用户目录和项目路径。

### 14.3 核心指标

- 完成模型＋Reasoning effort＋Fast 配置的中位操作次数。
- 从打开 Popover 到首次有效修改的时间。
- Popover 无操作关闭率。
- Fast 开关后短时间反向切换率。
- 自动配置回退率。
- 无效配置导致发送失败的比例。
- 模型加载失败率。
- 重试成功率。
- 搜索无结果率。
- 无可用模型导致的发送阻断次数。
- 键盘用户配置完成率。
- 窄窗口布局溢出率。

### 14.4 建议效果目标

- 用户可在一次 Popover 打开中完成全部模型配置。
- 完整配置最多需要：打开、选择模型、选择 effort、切换 Fast。
- 用户能够准确区分“支持 Fast”和“Fast 已开启”。
- 无可用模型时不得产生未知模型发送请求。
- 可用缓存状态下，打开 Popover 不产生可感知等待。

## 15. 验收标准

### 15.1 收起入口

- [ ] 模型、Reasoning effort 和 Fast 合并为一个入口。
- [ ] 模型名称始终处于第一信息位。
- [ ] Reasoning effort 使用短选项名称，不显示描述。
- [ ] 只有当前选中 tier 的 isFastTier=true 时显示闪电。
- [ ] Fast 关闭或仅支持时不显示闪电。
- [ ] 不通过 tier ID、名称或模型名推断 Fast。
- [ ] 不显示通用模型图标。
- [ ] 长模型名正确截断。
- [ ] 窄状态下完整配置仍可被 Tooltip 和辅助技术读取。

### 15.2 Popover

- [ ] 模型列表和当前模型配置区层级明确。
- [ ] 宽窗口使用左右布局，窄窗口使用上下布局。
- [ ] 模型列表滚动时配置区保持可见。
- [ ] 模型超过 8 个时才显示搜索。
- [ ] 选择模型、effort 或 Fast 后 Popover 不关闭。
- [ ] 外部点击、Esc 和再次点击入口可以关闭。
- [ ] Popover 不超出窗口边界。

### 15.3 模型列表

- [ ] V1 不展示模型简介、价格或能力标签。
- [ ] 可用模型可以选择。
- [ ] 不可用模型可见但不可选择。
- [ ] 不可用原因不直接显示在列表中。
- [ ] 鼠标悬浮可查看不可用原因。
- [ ] 键盘聚焦可查看不可用原因。
- [ ] 屏幕阅读器可朗读不可用原因。
- [ ] 隐藏和废弃模型不展示。

### 15.4 Reasoning effort

- [ ] 直接展示 provider 返回的可选项。
- [ ] 不展示档位描述。
- [ ] 切换后入口立即更新。
- [ ] 不可用选项保留禁用状态。
- [ ] 不可用原因可通过悬浮、聚焦和语义获得。
- [ ] 无可选 effort 时不显示空区块。

### 15.5 Fast

- [ ] Fast On 时入口和 Popover 均显示闪电。
- [ ] Fast Off 时两处均不显示闪电。
- [ ] isFastTier 缺失时不展示为 Fast。
- [ ] Fast 可以明确切换回 Off。
- [ ] 不兼容时显示原因和兼容档位快捷操作。
- [ ] 选择不兼容 effort 后，Fast 自动关闭并提示。
- [ ] 组合快捷操作成功或整体回滚。

### 15.6 配置继承

- [ ] 切回模型时恢复该模型上次有效配置。
- [ ] 首次使用模型时使用 provider 默认配置。
- [ ] 偏好按 provider 全局保存。
- [ ] 不按项目或 thread 分别保存。
- [ ] 能力失效时按照回退顺序调整。
- [ ] 自动调整必须提示。
- [ ] 快速连续更新采用最后一次操作结果。

### 15.7 运行与发送

- [ ] Agent 运行中入口保持可用。
- [ ] Popover 显示“下次新回合生效”。
- [ ] 当前运行回合不改变。

- [ ] 没有可用模型时发送按钮完全禁用。

- [ ] 不允许回退到未知服务端默认模型。

### 15.8 状态与可访问性

- [ ] 覆盖正常、悬停、选中、聚焦、禁用、加载、错误和空状态。

## 16. 仍待确认的问题

当前没有阻塞设计定稿的产品问题，但仍有以下技术与文案问题需要在开发前确认：

1. Provider 的模型不可用状态和 unavailableReason 使用什么统一协议结构。
2. Provider 是否能为不可用 Reasoning effort 返回结构化原因。
3. Fast 与 Reasoning effort 兼容矩阵的协议字段和默认语义。
4. 如果出现多个 isFastTier=true 的 tier，客户端应如何选择或展示。
5. 大模型列表的搜索由客户端本地完成，还是需要 provider 支持服务端搜索。
6. 模型分页的缓存、搜索和当前选中模型定位规则。
7. “Reasoning effort”的最终中文名称是否采用“思考强度”。
8. Provider 自定义 effort 的本地化显示名由 provider 返回文本还是本地化 key。
9. 不同 provider 的 steer 配置语义需要分别记录，但不进入统一 UI 承诺。
10. 未来获得可靠模型能力元数据后，是否增加独立的模型详情区。

这些问题不应被实现阶段静默假设。开发方案应明确记录采用的临时规则，并为 provider 差异保留可扩展字段。
